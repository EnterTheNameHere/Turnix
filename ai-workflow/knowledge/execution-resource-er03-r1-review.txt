R2: host resource finalization crosses an outstanding abort cleanup callback
---------------------------------------------------------------------------
executionSessions.hostClosePreflight(stop) reserves shutdown admission for each
runtime, then closes broker/resource admission. For pending initializations it
permits an attempt in phase 'cleanup' to proceed to executionResources.finishClose
before testing hasLifecycleWork. That ER-01 service finalizer can invoke the
provider's release callback and stop its process even while the failed attempt's
broker-owned lease finalizer is still executing under finalizationScope.

The later pending/lifecycle-work check does return typed incomplete cleanup, but
only after the resource effect has occurred. Callback-free admission closure is
valid; destroying a callback-owned resource before its owner unwinds is not.
Runtime roots/cleanup tickets must cover effects, not just legacy teardown.

2. Wrap the real published binding's leaseCloser with an Event pause before its
   original close. Failed initialization reaches abort/cleanup after loading A.
   Confirm attempt.phase == 'cleanup', _cleanupAdmissions is nonempty and the

3. While that lease callback is still outstanding, call host.stop. It reports
   LlmExecutionCleanupError but nevertheless terminates the process before the
   callback is released. Assertion: 'Host finalized process across live abort
   cleanup callback'. The initializer preserves its original hook ValueError.

No timing/sleep inference, real inference, production-source edits or forged
ownership were used. The Event controls a callback already owned by the broker;

This is a residual path beyond the original preflight-versus-composer races, not
a claim that the original three cases still fail on R1.
