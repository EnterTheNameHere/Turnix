Binding / ownership / admission
--------------------------------
Host-trusted LlmExecutionBindings.bind accepts an exact published Registration,
an ER-01 domain, a copied selector -> immutable issued ProfileReference map, issued owners'
LlmOwnerGrants, full adapter contract and an owned leaseCloser. The full shape and
support flags are checked before publication. A Pack's registerProvider call never
grants binding/profile/transition/evidence authority. Binding/registration tombstones
remain rooted in the host service. Re-registering a controlled name requires a new
explicit trusted binding; no revoked/failed controlled path becomes legacy fallback.
Lazy profile issuance checks exact runtime owner and its own selector grants before
provider IO. No raw argv/slot/cache controls enter the neutral core.

ApplicationRuntime creates a distinct owner object for each registered CodeEntry.
Only normal invokeCapability creates controlled LlmInvocationAccess, carrying a
separate validity token and the actual Job CancellationSignal. Creation/registration/
unload contexts cannot bootstrap controlled execution. Public facade methods require
current invocation validity. Handles retain owner/binding/core protection, never a
CodeEntryContext, bound validity callback, transaction, memory or IO view. Closing
access revokes use and queues stop for any outstanding copied call; cleanup remains
authorized after revocation. No new admission authority is inferred from identity
strings, provider options, physical ports or an existing lease.

Controlled calls obtain one ER-01 claim before openExecution/getExecutionProfile.
That claim protects profile resolution, helpers/query preparation, token estimation,
context preparation, streaming and cleanup. All phases share exact Registration,
frozen options, authorized profile and ResidencyToken. Initial load/idle replacement
remains an explicit transitionProfile request under the actual ER-01 host grant.
reserveConversation wraps the exact exclusive reservation across sequential fresh
invocations. Calls inherit its profile when model is omitted and reject mismatches.
Foreign/closed/non-reentrant calls reject immediately; unrelated domains are not
globally serialized. Ordinary compatible claims still follow ER-01 rules.

Controlled profile/result/preview snapshots contain no live token estimator.
LlmExecutionEvidence records immutable residency/context/cleanup facts; snapshot()
contains only serializable safe identities/generations/effects, never handles or
opaque payloads. ProcessingRun/completion payloads receive that snapshot only.
prepareProcessing/estimateInputTokens create profile-only sessions, do not allocate
or reset inference contexts and release their operation. runPreview reacquires and
validates exact issued preview/owner/registration/options/profile/generation before
provider IO, with explicit StalePreview failure. Ordinary run(query) makes no hidden
preview-provenance guarantee. runProcessing rebuilds inside its own admission scope.

Context / effects / transaction rules
--------------------------------------
FreshContext(retain=False, required=False) is the controlled default: best-effort
owned logical freshness, separate from weights, capacity, hidden caches or GPU reset.
Required freshness names only that narrow adapter contract; lack of support rejects.
Retention requests also reject unsupported support before IO. ReuseContext requires
an exact issued retained handle, owner/registration/profile and its ER-01 pin/context
generation. Loss/eviction/incompatibility/invalidation cannot silently rebuild.
Retained state pins residency between calls. Closing a conversation revokes/disposes
its retained children; closing handles accepts no provider evidence. Successful
disposal drops private payload references. Actual provider realization is ER-03.

Every attempted open has exactly one closeExecution owner, even partial open. Local
iterator close, adapter finalization and core claim.finish are separate; iterator
failure cannot skip finalization. Quiescence is trusted adapter evidence, not EOF,
transport close or Job-terminal status. Primary exception/cancellation classification
survives; llmCleanup attaches safe immutable cleanup disposition, including local
iterator-close failure. Otherwise-successful calls with failed/unknown cleanup
raise explicit cleanup error; required retained loss is explicit and cannot return
a valid handle. Partial context transfers remain disposed or owned by their exact
call/pin ticket; uncertain disposition keeps ER-01 protection, without recovery.

Context mutations have exact revision receipts and provisional-root guards. Guard
validation occurs again after core acquisition to close the preflight/admission race.
Only admitted operations whose provider hook can run touch the receipt. Foreign,
busy or stale rejection does not destroy another valid handle. Other scopes cannot
consume provisional state; sequential authorized calls in one Job can. Scope reset
and live nonce checks invalidate copied scopes/estimators. Old abort receipts cannot
erase a later admitted mutation. Completion/commit/outer Job abort invalidates the
appropriate derived state; already accepted authoritative Value state survives late
IO/Job failure. No context/transaction object is retained to implement the guard.
Helper estimation requires its own grants plus live borrow nonce, exact actual
runtime issuer/registration/profile/options and current invocation validity. It
delegates no transition/reservation/payload/cleanup authority. The actual runtime
capability bridge forwards the parent signal. Inference never borrows that claim.

Lifecycle and pending-close semantics
--------------------------------------
New owner/registration revocation is callback-free under existing lanes. Adapter
lease, call, retained-pin and conversation cleanup queues are rooted in the host
service, not only in a runtime that can be removed. Post-lock lifetime boundaries
cover direct close, application close, host stop and failed create/load/activation.
Legacy Pack teardown and invokeCapability/runJob retain their serialization lanes;
normal provider execution still runs within that existing runtime serialization.

For controlled active calls, close first revokes authority and dispatches cooperative
stop outside host/runtime lanes before trying legacy teardown. Still-active/unknown
work returns typed LlmExecutionCleanupError without waiting across the mutation lane;
the runtime stays owned for explicit retry. A pending host stop blocks new host
admission through its stopping gate, and may remain unfinished until explicit retry.
This is not automatic recovery/preemption, nor a new guarantee about legacy unbound
provider shutdown. Existing ER-01 host tests remain unchanged and passing.
Known-finished runtime removal with uncertain context/lease cleanup retains the
host-rooted tombstone/queue. Repeated closed/stopped paths still drain/report it.
Late completion inside legacy teardown queues adapter finalization until outside
the enclosing locks. Second-thread probes establish actual lock boundaries.
Direct Pack unload revokes current incarnations but permits ordinary reactivation;
runtime/host shutdown closes future owner/binding admission permanently.
