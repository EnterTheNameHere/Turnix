ACCEPTED REQUIREMENTS
---------------------
Reuse existing hardware telemetry; avoid duplicate collectors.
Monitor ordinary inference and variability, not only optimizer experiments.
Measure whole-system CPU, RAM, GPU and VRAM under normal competing workloads.
Keep engine-specific instrumentation with the engine integration, not generic
backend. Unused engines must not load their monitoring.
Future hardware providers may include AMD/Radeon and Intel; initial NVIDIA
support must not become a universal dependency.
When unused, optional monitoring must not keep polling or retaining histories.
Shared collection must honor active consumers independently.
Monitoring never authorizes server restarts or optimizer experiments.
Backend versus Pack placement remains open to actual implementation pressure.
Optimization should consider speed, latency, memory headroom and variability.

STREAMED-TEXT MEASUREMENT (ACCEPTED)
------------------------------------
Normal inference monitoring must remain useful without engine-native token
counters. Timestamp delivered text using a monotonic clock; expose observed
characters/second and optionally words/second, plus first-text latency and
delivery variation. Stream chunks are not necessarily model tokens; network
or buffering effects may cause bursts. Use time windows for meaningful plots.
Do not present words/second or characters/second as actual tokens/second or
convert them with an arbitrary universal ratio. When reliable engine token
measurements exist, preserve them separately. Generic stream observation can
work across providers; engine-specific metrics remain optional.
Do not retain generated content solely to calculate rates, and avoid additional
work when no consumer has enabled monitoring.
