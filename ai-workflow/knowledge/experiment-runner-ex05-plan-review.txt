Binding implementation clarifications
---------------------------------------
1. TTL / attachment / call-final retention (mandatory correction): separate viewer
   publication expiry from capture/source lifetime. Acquire an App-owned in-flight
   lifetime guard before exposing a session to expiry; it covers setup/attachment,
   the actual single synchronous call and copying immutable call-final evidence.
   No timer/ordinary handoff/viewer failure may release that source or capture grant
   during this guarded period. Do not hold a controller lock across ctx.llm.run,
   a sink, serialization, backend release or network IO; timers mark expiry pending
   and perform safe viewer-parent revocation separately outside locks.
2. Define maxLifetimeSeconds explicitly as viewer/publication expiry and bounded
   post-call tail policy, or rename it before shipping host4. It is NOT an absolute
   forced source-disposal deadline during in-flight work. Timer expiry may revoke
   only the viewer parent then; capture remains independent until its final snapshot
   is copied (or explicitly unavailable). After guard exit, release source immediately
   if expiry/teardown was requested, otherwise only for the remaining bounded tail.
   No unbounded tail extension after a long call; deadline origin must be explicit.
   Existing provider/Job and hardware-lock limits still apply. Unknown/pending release
   stays explicit; no native/thread force-stop or hard wall-clock guarantee.
3. If monitoring is unavailable before calling LLM, select unobserved execution once
   and record unavailable before starting it. Never catch a generic LLM RuntimeError
   and retry without observation: the first call may already have sent. A failing
   optional facility cannot create a second request, reset history or replace primary
   inference/cancellation/UNKNOWN/cleanup. Required archive failures remain fatal.
4. Test expiry precisely during setup-before-attachment, active stream, call-final
   snapshot/ACK and post-call tail, including concurrent revoke/teardown. Assert
   one actual inference, no observation-induced Failed Job, no lost immutable snapshot
   relabeled available, separate capture/viewer grants, correct pending ownership and
   no next call authorized by a publication. Test a stuck handoff and ordinary/first
   non-Exception errors with independent cleanup, without retaining Context.
5. RUN snapshots/grants must be copied before invocation invalidation; APPLICATION
   snapshots before release. PM call-final metrics use only that actual call/session/
   epoch and stream measurement definition. No post-call hardware tail counted as
   call cost, no inference token count from characters and no silence-as-zero-rate
   or absent reasoning-as-empty. Application duration excludes its later completed-
   turn archive ACK; document exact interval, not pure engine latency.
6. Pin report source boundary to the EXACT unfiltered reader-validated manifest/
   DATA/COMMIT version/sequence/digest. Derive commit hash only using that version's
   verified fields, never weaker log parsing or a later selected record. Unsupported
   version/oversize/unavailable scope stays explicit. Invalid source identities may
   be unavailable; never invent binding or equate missing with matching data.
7. Validate complete typed report/archive2 observation shapes and strict policy enums,
   ranges, decimal units/epochs, selections, observationId/attempt/provider-call links
   BEFORE accepting/projecting them. Closed top-level keys alone are insufficient.
   Include rehashed missing/contradictory correlation/version cases and source-prefix
   state preservation. A live-schema codec placeholder is not a publication/grant.
8. All inherited EX-04/R1 validation remains effective for archive1 AND archive2,
   including required exact body history and inconsistent final send/response facts.
   Test original raw archive1 reproducer unchanged and equivalent archive2 faults.
   Observation additions/cleanup must not permit sealing incomplete original Job/
   suite evidence as success or relaxing native cleanup. Host3 behavior stays accepted.
9. Enforce declared actual/cumulative read, retention, private-workspace, output,
   base64 and CSV expansion caps before allocation/publication; report invalid/prefix
   export separately from completed bytes. A complete export marker is not a caller
   ACK-return/source-success/durability receipt. Default output excludes private text,
   paths and descriptors. Explicit content cannot include live credentials/authority.
10. Handoff notices/callback ordinary errors must not leak via repr/trace/Job/error
    cause/context or export. No callback under runtime/authority/queue locks; do not
    wait for reader readiness. A stalled worker remains pending/owned with bounded
    retained notice, not falsely stopped. Endpoint/source teardown makes stale notice
    unusable; arbitrary trusted callback code is not a privacy sandbox.
