EX-03-R1 [P2]: SIGINT can deadlock the suite controller at Job handoff
---------------------------------------------------------------------
first-party/applications/experimentRunner/launcher.py:127-148, especially 129/136.
SuiteControl uses threading.Lock. execute installs a Python SIGINT handler which
synchronously calls control.cancel(). If the first SIGINT arrives on the main
thread while begin/end/cancel already owns _lane, that handler tries to acquire
the SAME non-reentrant lock. The main thread cannot release it until the handler
returns; the handler cannot return until it acquires it. No further Job boundary
or host finally is reached. At a later unit handoff an owned model may still be
resident, so the standard terminal cancellation path can hang without cleanup.
This is a single ordinary SIGINT, not the documented limitation of repeated
interruptions inside provider shutdown or forced process termination.

Independent model-free reproduction: dispatch actual Python SIGINT from the
cancellation-flag check performed INSIDE begin's lock. Child prints that it is
dispatching, then fails to return within four seconds. Bounded parent subprocess
times out, kills and reaps only that exact MODEL-FREE diagnostic Python child.
No actual model abort/kill, domain repair or emergency provider disposal involved.
This confirms deterministic same-thread lock reentry on unchanged delivered source.

Required correction: ensure SIGINT handling can request suite cancellation without
blocking on a lock held by the interrupted thread. Preserve correct active-Job
selection and first-cancellation behavior, including the interval between testing
the cancellation flag and publishing the new Job. A naive reentrant-lock change
must not lose cancellation there or admit later work after a gap cancellation.
Do not relabel completed Jobs, replace cancellation with success, add retries,
weaken resource cleanup or modify shared backend/provider APIs.
Add deadline-bounded model-free actual SIGINT regressions at begin and end handoffs,
plus exact active-Job cancellation and no subsequent transition/Job admission.
Existing cross-thread cancellation, R1 aggregate interrupt and UNKNOWN tests remain.
