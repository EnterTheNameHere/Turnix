02. REQUIRED SHARED CORRECTIONS: ACK OWNERSHIP AND CLEANUP
---------------------------------------------------------
Proposal03 roots a beforeLaunch callback on the supervisor; proposal04 later says
the pending record contains no Application callback and releases the pin after
spawn/child/readers/pipes resolve, omitting ACK resolution. These cannot all hold
when beforeLaunch is still blocked. A running callback necessarily retains its
call frame/closure, potentially including the archive port, until it returns.

Binding resolution:
- ackResolved is a required cleanup obligation, including after expiry/cancellation.
  Pending ownership MUST root the exact still-running ACK worker/callback state
  and request; never report all workers joined, remove its root, release workspace
  pin or claim confirmed cleanup while it runs. Scope text must include ACK/spawn/
  supervisor workers as well as child/capture readers. Complete cleanup includes
  supervisor termination/settled ownership handoff, not merely two reader joins.
- No live Context/Job captured by platform workers; App callback cannot use or
  reenter runtime. Document unavoidable bounded callback-closure retention instead
  of claiming it is absent. Clear that callback/port reference after resolution.
  Late archive ACK may be visible but never triggers launch after ticket expiry,
  stop, invalidation, caller abandonment or unknown result publication.
- The pending owner may attempt cleanup after callback/spawn resolves; a blocked
  callback cannot simultaneously run the supervisor's cleanup loop. Do not imply
  it does. Caller can return immutable unknown after its bounded wait, with exact
  roots/pin and quarantine retained. No thread termination or fabricated finite
  callback completion. Late cleanup never rewrites the original returned evidence.
- confirmed is true only after all five stated obligations plus any actual owned
  worker obligation resolve. childReaped=true on not-attempted is an explicit
  vacuous obligation, not a child-exit observation; exitCode remains null.
- Provide and test one status/phase/launchState/stopReason/failureCategory/cleanup
  consistency table. Distinguish pre-prepare evidence=None/category from full
  outcomes, normal nonzero completion, interrupted same-object primaries and
  cleanup unknown with a known exit. No successful outcome with incomplete streams.

04. APPLICATION CORRECTION: STABLE INPUT COMPARISON IDENTITY
-----------------------------------------------------------
P2 contract finding: addendum03 inputs-index entries include observedTimeNs,
device/inode/mtime/ctime and sourceRelativePath. Addendum07 uses inputsIndexSha256
as the comparison input identity. Identical raw content in two legitimate runs
therefore differs when only observation time/file identity changes. Requiring
allowInputDifferences for that case would misclassify equal frozen inputs.

Binding replacement for new report@2/comparison@2 fields:
Keep the complete inputs-index artifact hash as private evidence/source binding.
Add a distinct semantic frozen-input hash over sorted entries of EXACT
 {inputId,bytes,sha256}
using original rawRef byte count/digest. Hash the canonical array, including []
for no inputs. Exclude observation metadata and physical/source location from
THIS content hash. Procedure references already bind logical input IDs. Original
relative source relationships remain in provenance and disclosed if relevant.
Use inputsSha256 in procedureIdentity {procedureSha256,inputsSha256}; leftInputsSha256/
rightInputsSha256 in procedureQualification refer to this same semantic hash,
not inputs-index artifact digest. Different IDs/content differ; missing validated
evidence is unavailable, never the hash of an invented empty array.
Do not silently change old comparison@1 modes/qualifications.

Independent deterministic Python3.15 check of this proposed index shape: two
indexes with identical rawRef/inputId but changed observedTimeNs/inode produce
different full-index SHA256 and equal canonical semantic-input SHA256. This is
a contract counterexample, not an executed App comparison regression.
Required App tests: same input bytes/new source inode/time => equal semantic
identity; changed bytes/ID => different; absent/corrupt => unavailable; default
comparison qualifications and explicit difference opt-in disclose actual changes.
