-----------------------------------------

stable adapter object, registered domain and immutable profile-reference catalog.
The host selects that object; Pack config/model titles/ports cannot create new
authority or evade a conflicting domain. Domains do not imply separate hardware.

Split the existing PreparedConfiguration identity deliberately:

  endpoint/transport/security policy and host-selected domain ID. Changing it
  cannot replace a live adapter; fail explicit domain compatibility instead.
- Residency: resolved selected LlamaCppModel and complete ordered launch argv,
  captured cwd, frozen relevant environment including absence, automatic-config
  observations, startup timeout/check policy, target/mmproj/template/auxiliary
  identities and LC configuration fingerprint. Include executable observation
  available when catalog is frozen, but never claim loaded-byte attestation.

startup settings, even those not promoted to first-class fields. No semantic
normalization of unknown extraArgs. Aliases may conservatively differ. Request
sampling/template controls stay frozen per call and do not change residency.

Reuse LC parsing, inheritance, validation, environment and argv construction.
Do not use profileId alone as an actual residency generation. Cache one exact
ResidencyDescriptor/ProfileReference per fingerprint within the trusted catalog,
because ER-01 rejects a second descriptor object for an existing identity.
Selectors None and configured names map to issued references; titles are labels.
Draft/speculative weights are part of the selected residency, never separately
loaded, owned or scheduled. New trusted catalogs may add immutable profiles to
the same stable domain, without mutating old descriptors or grants.

The host composition object owns stable adapter lifetime through host shutdown.
Per-registration binding tickets own application participation/lifetime only.

4. Complete provider path coverage
-----------------------------------
materialize receives the immutable descriptor and exact token. It constructs one
per-residency driver from the frozen profile, starts only that target, checks LC
capability policy/readiness and returns Materialization plus the owned driver
ticket. Driver shell state is not the adapter/domain identity. Failed startup
returns confirmed-empty only after proving no child exists or confirmed reap;
otherwise retain the exact process ticket with unknown effect. No old-profile
restore, implicit restart or fallback. Auxiliary startup failure is the same
whole-residency failure, not a partially accepted target.

openExecution validates the issued admission token against the adapter's resident
ticket without selecting a model or starting/restarting anything. It installs
partial-open cleanup ownership before IO and a cooperative stop callback. Return
a generation-bound session using that exact driver, model and frozen options.
getExecutionProfile is read-only on this resident. Its estimator uses identical
LC-02 messages/template controls for /apply-template and /tokenize, with session
validity before and after both endpoints; no saved mutable-driver estimator.
ER-02 scopes query construction/helpers and validates previews unchanged.
prepareProcessing/estimateInputTokens do not allocate/erase inference slots.

Inference uses only the admitted session. Allocate an available concrete slot
from this residency's configured range, excluding retained/active slots if a
reviewed retention mechanism is later supplied. This is bounded provider capacity
bookkeeping; no queue/retry/fairness policy. Lack of capacity fails immediately.
Validate slot IDs locally; never allow modulo aliasing or arbitrary caller IDs.
Preserve the existing payload builder, SSE parser, reasoning/usage evidence and
request semantics. Internal slot/cache fields are adapter-owned and rejected as
caller providerOptions. No HTTP transport entry without a live session ticket.

Make managed driver start/ensureModel/_startModel/postJson/stop reachable only
through trusted adapter tickets. Public managed calls without that authority
reject, including the substrate provider, saved estimator and direct onLoad path.
Do not solve a failed check by invoking the old implementation. Configuration
evidence/summary are immutable inspection; explicit help/version probes remain
bounded, model-free LC operations and never authorize inference or transitions.

release stops only the exact owned process object for the token. Fix stop's
current detach-before-wait behavior: retain process ownership until poll/wait
confirms exit, including terminate->timeout->kill->wait failure. Report unknown
if reap is unconfirmed. Final binding release and host close call this same
domain release path, never a second raw stop. Repeated cleanup does not repeat
unsafe callbacks or clear peer/stale generations. No process lookup by PID/port.

5. Fresh, retained and unsupported guarantees
---------------------------------------------
Default supportsFresh=True means best-effort owned logical inference freshness.
For each fresh inference send an adapter-owned id_slot and cache_prompt=false.
Record attempted freshness, not a claim that an accepted request reset everything.
Weights and capacity are unchanged; no context resize or MoE/GPU cold reset.
Where the trusted profile explicitly enables slot actions, erase only the owned
idle slot and validate the returned slot ID/count. Report acknowledged erase scope
separately from unverified effective binary behavior. Do not silently inject a
filesystem save path or expose save/restore/snapshots to Packs. Missing/disabled
erase support is explicit best-effort uncertainty, not a success assertion.
supportsRequiredFresh=False initially: stronger required reset rejects before IO.
An erase acknowledgement alone does not certify broader hidden-state freshness.

Proposed stock adapter supportsRetention=False. FreshContext(retain=True) and
ReuseContext reject through accepted ER-02 before provider mutation. Do not issue
a fake retained handle backed only by id_slot, a token count or client transcript.
No cache_prompt=true fallback advertised as required reuse. This is a concrete
provider limitation requiring Integration disposition, not an accepted reduction
of ER-03's retained-state objective. Full required reuse cannot be declared done.

If Integration supplies an adequate provider mechanism, map each retained payload
to exact process/residency/context generation, owned slot, compatible rendered
prefix/token identity and immutable template/settings identity. LlmProviderContext
transfers its disposer to ER-02/ER-01; existing pins block transitions between
calls. Reuse preflight must prove state present before a request capable of
rebuild; missing/stale/evicted/incompatible/foreign/busy state fails without replay.
Cancellation, process loss, provider mutation and cleanup uncertainty invalidate
the exact handle; no silent new handle. Disposal erases only the owned idle state,
with unknown evidence retaining the blocker. These are acceptance criteria, not
a mechanism claimed implemented by stock HTTP.

Packs retain authoritative history, supply complete appropriate messages, and
choose overflow policy. Do not truncate/rewrite history, shrink capacity, change
sampling, or infer append-only server conversation from a slot. Explicit fixed
experiments reject unsupported overflow/reset guarantees. No bitwise determinism,
all-cache isolation or universal contract/attestation machinery.

6. Quiescence, cancellation and cleanup evidence
------------------------------------------------
Track request-not-sent, request-may-have-reached-provider, observed terminal stream,
transport closed and provider completion separately. bindStop requests local close;
it never supplies confirmed quiescence. Cancelled/error/early-closed generation
requests with ambiguous server disposition return unknown and quarantine through
ER-01, preserving the primary Job classification and ER-02 cleanup attachment.
No timer, Job terminal state, EOF or HTTP closure frees that blocker.

For normal completion, require the valid terminal protocol plus a post-terminal
validated slot observation showing the same owned process remains live and that
operation's slot is idle. An uncorrelated idle observation after cancellation may
precede a queued task and is NOT sufficient. Missing/malformed/disabled slots,
busy state, process replacement and ambiguous observations yield unknown. Do not
poll indefinitely or restart. Read-only template/tokenizer operations can confirm
their own completion after fully validated synchronous responses; ambiguous HTTP
failure remains unknown. An open failing before any IO is confirmed no-work.

Trusted unload can confirm owned-process exit only when ER-01 permits release;
never forcibly replace busy/unknown resources as recovery. Unknown operation
tombstones remain unavailable even if a human later kills a server. No recovery
API is invented here. Host/service lifetime retains exact cleanup ownership and
reports pending state on repeated shutdown. Stop/wait, session finalization and
lease disposal must run outside host/runtime/registry/broker/domain locks; use
second-thread probes to test this, including failed activation and late completion.
