Combined-checkout dependency interpretation (revised)
------------------------------------------------------
The launcher derives the reusable provider under the checkout root. This is
consistent with the intended current Application workflow, where backend and
first-party/llmDrivers/llamaCpp are imported into the same branch as the AppPackage.
A deliberately App-only exported snapshot fails because it OMITTED the platform.
That was a valid observation for a future separate-root packaging scenario, but
NOT a defect requiring correction under today's full-platform-import procedure.
No launcher.py, run.py, README or Application test rewrite is required solely
to accommodate independent platform roots.

Do not extend an experiment definition with provider paths or grants. Preserve
the existing trusted catalog/composition, EntrySelector and explicit transition
rules and the accepted EX-01/02/R1 implementation. Future independent repository
packaging remains possible, but is a separate design and task, not a precondition
for restoring the source boundary now.
