Concrete separation problem / smallest Application correction
---------------------------------------------------------------
launcher.py currently derives ROOT from APP.parents[2] and DRIVER from
ROOT/first-party/llmDrivers/llamaCpp. An Application-only external snapshot lacks
that sibling provider: loadAdapter() reproducibly raises FileNotFoundError.
run.py inserts its Application checkout root into sys.path; this does not install
an external backend. Embedded Python _pth also ignores ordinary PYTHONPATH and
pins its parent checkout, so test origin assertions are necessary.

Propose an APPLICATION-OWNED follow-on boundary correction, not EX-03:
- launcher resolves the reusable provider root from the actually loaded backend
  package's platform root, rather than its Application directory. Use explicitly
  composed trusted platform installation/root; do not accept this path from an
  experiment definition or expand provider/grant authority.
- README documents separate Application and platform roots, interpreter/dependency
  bootstrap and CLI validate/run/inspect commands. For the current embedded runtime,
  a trusted bootstrap sets explicit Python import paths before importing/runpy;
  do not rewrite another checkout's _pth or silently fall back to historical copies.
- tests assert Application module origins come from the Application checkout,
  backend and provider origins from the selected platform tree, and no provider
  copy is necessary in the Application-only artifact. Add actual CLI bootstrap
  coverage, preserve all 72 existing tests including R1, and bump changed Python
  source versions. Expected owned edits: launcher.py, README.md and test module;
  adjust run.py only if actual bootstrap verification demonstrates a need.
- Manifest packId applications.experimentRunner, version 0.1.0, kind appPack and
  CodeEntry source stay unchanged. PackResolver already accepts separate roots;
  activate explicit reusable provider then AppPack, preserve exact source-selected
  grants, trusted catalog and transition. No backend/PackManager/package solver work.

Keep existing relative Application paths on ITS branch for this bounded correction:
current import namespace, CLI commands and source-selected entry shape rely on
them. This preserves working interfaces, not platform classification or historical
cherry-pick precedent. They must be excluded from platform source/distribution.
A top-level AppPackage directory/namespace rename can be reviewed separately if
desired; it is unnecessary to enforce the source boundary and is not proposed as
an automatic repository migration. The external Application artifact contains only
the eight Application files plus its own tests; it never vendors backend/provider.
