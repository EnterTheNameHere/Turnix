BOUNDED FIX / PROTECTED INVARIANTS
---------------------------------
Production change only: backend/telemetry/service.py, version 6 -> 7.

subscribe() now treats publication, initial collection/reused delivery and worker
setup as one acquisition under the existing lifecycle lock. Any escaping
BaseException revokes the new subscription using the existing release path, clearing
its current/history and removing its cadence/collection claim. Remaining consumers
retain their claims, histories, providers and legitimately collected evidence.
Service-owned providers close only when no remaining claim needs them; borrowed
providers retain their existing cleanup contract. Original failure is re-raised.
If rollback itself raises, an exception note records the cleanup exception type;
the cleanup error does not replace the original. No generated content is captured.

_ensureWorker() clears only the just-published worker when Thread.start raises.
Construction failure publishes nothing. If the OS thread actually started before
start raised, its identity has been revoked; when it enters the loop it cannot
collect or clear a replacement worker. Worker startup and publication remain under
the existing condition lock, with one shared collector.

_samplingLoop() has an identity-checked loop and finally under the lifecycle lock.
Normal exit, unexpected exceptions and control-flow exceptions relinquish only that
worker's identity and notify waiters. An old thread cannot clear a newer identity.
Unexpected exceptions continue to threading.excepthook unchanged; there is no
automatic retry/restart loop and no new retained exception/traceback history.

EXPLICIT RECOVERY / EVIDENCE
----------------------------
Public signatures/types are unchanged. subscribe() requests one polling worker
when needed, including after unexpected worker exit. Successful explicit sample()
now also invokes the same worker-ensure path after collecting once; it restarts
polling only when active claims require it. A valid legacy start() still uses that
same worker-ensure seam; repeated start remains rejected as before. Passive current/
history reads, release and owner teardown do not autonomously restart collection.

If manual collection fails, it raises normally and does not request worker startup.
If collection succeeds but worker startup fails, the startup error propagates while
the legitimately collected snapshot remains retained. Recovery is caller-initiated,
with no backoff manager, retry queue or scheduling-policy change.

Samples retain actual original monotonic/wall timestamps throughout interruption.
A joining recovery request may reuse old evidence; it is never restamped as fresh.
Once collection resumes, the actualIntervalSeconds and start/end timestamps expose
the full elapsed gap. Tests verify a deterministic 5000-second recovery gap,
unchanged pre-fault history, bounded two-sample retention and exactly one replacement.
