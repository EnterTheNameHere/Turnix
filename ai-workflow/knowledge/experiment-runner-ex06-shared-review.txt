P2 / R1 - LATER CALLER INTERRUPTION REPLACES EARLIER WORKER PRIMARY
-----------------------------------------------------------------
Path: backend/process/capture.py at4430418, particularly lines309/318/379,
519/538/552/560/570. Caller and worker keep separate primary variables.
Line560 selects caller-local primary before the already recorded operation.primary.
Therefore observation order across threads is lost.

Independent deterministic sequence:
1. Actual supervisor's beforeLaunch raises exact KeyboardInterrupt A, before spawn.
2. Supervisor stores operation.primary is A and signals its real done Event.
3. Instrumented caller wait observes BOTH done and operation.primary is A, THEN
   raises exact SystemExit B. The ordering is explicit, not a scheduling guess.
4. execute catches B into caller-local primary, then line560 chooses B over A.
5. API raises B with confirmed cleanup. Expected: same original A remains primary.

This violates the binding same-object/first-BaseException contract. It can change
outer signal/exit semantics even though owned resources have settled. The ordinary
single-critical-error tests do not cover two ordered errors across owner threads.
No native child, model or configured executable was launched by this regression.
Workspace removed and runner active root released; this is an exception-precedence
defect, not a claim of child leakage or failed cleanup.
