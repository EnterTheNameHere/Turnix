Proposed configuration contract
-------------------------------
Add these fields to llamaCpp defaults and models[name], following existing
per-field inheritance. A model's explicit null suppresses its inherited field.
Absent/null optional fields emit no new flag and mean upstream/environment/
template default is unknown, not false. No new thinking flag is emitted for old
minimal configs. Fields below are server startup configuration, never per-call.

Field                       Type/range                 argv
moeCacheMiB                 exact int 0..2147483647    --moe-cache-mib N
cpuMoe                      exact bool                --cpu-moe when true
serverReasoning             on|off|auto string         --reasoning VALUE
serverReasoningEffort       nonblank exact str         --reasoning-effort VALUE
serverReasoningBudget       exact int -1..2147483647   --reasoning-budget N
serverReasoningBudgetMessage exact str, empty allowed --reasoning-budget-message VALUE
serverReasoningFormat       none|auto|deepseek|        --reasoning-format VALUE
                            deepseek-legacy
serverReasoningPreserve     exact bool                --reasoning-preserve or
                                                      --no-reasoning-preserve
chatTemplateKwargs          JSON object                --chat-template-kwargs JSON

Retain cpuMoeLayers and existing GPU/KV/offload/load/parallel settings. Bound
cpuMoeLayers to pinned C++ int range as well. bool is never an integer. Reject
NaN/infinity, arbitrary Python objects, non-string JSON keys, cycles and wrong
exact scalar types recursively. Freeze caller-owned nested values at parsing,
before lease identity or later argv creation. Serialize JSON deterministically,
preserving values and rejecting non-finite values, with no shell interpolation.
Unknown template keys are permitted and have unverified template semantics.

moeCacheMiB=0 explicitly disables the expert cache; it is distinct from KV cache.
cpuMoe=false emits no switch because upstream has no negative cpu-moe switch.
It means this provider adds no all-expert override, not verified GPU placement.
Reject cpuMoe=true together with any non-null cpuMoeLayers, including zero,
rather than depending on the order of tensor overrides. cpuMoe=false can coexist
with cpuMoeLayers (partial CPU placement is a separate setting).
Budget -1 requests unrestricted, 0 requests immediate thinking termination;
neither proves template/backend honor. Empty budget message explicitly clears it.
Effort 'default' removes the template effort key upstream; other nonblank strings
are template-defined, not an invented exhaustive low/medium/high enum. Server
effort 'none' is a template string, unlike request reasoningEffort='none'.
Format controls extraction/representation; it does not suppress generation.
Preservation is template-dependent. Explicit auto/default differ from omission
in requested evidence and compatibility identity, even if behavior coincides.

Server template precedence and contradictions
--------------------------------------------
1. Resolve model overrides over driver defaults, independently for each field.
   chatTemplateKwargs is whole-object replacement, not recursive merge.
2. Validate known template keys: enable_thinking and preserve_reasoning must be
   exact booleans, reasoning_effort a nonblank exact string.
3. Reject any dual authority between serverReasoning and enable_thinking,
   serverReasoningEffort and reasoning_effort, or serverReasoningPreserve and
   preserve_reasoning, even if equal or serverReasoning='auto'/effort='default'.
   This removes argv-order-dependent assignments. Permit the deprecated kwargs
   forms alone for compatibility; document preferred dedicated fields.
4. Reject an explicit thinking-off setting plus an explicit non-default effort,
   positive budget or budget message. Off plus 0/-1 is permitted and preserved.
   A zero budget is not treated as equivalent to thinking-off. Format and
   preservation remain independent controls, not inferred enablement.
5. Reject --no-jinja when template/reasoning controls requiring template handling
   are configured; never silently enable Jinja or claim template capabilities.

Existing request reasoningEffort remains unchanged. Pinned server request parsing
