caller first on return, and used exception truthiness in several selection sites.

before completion signal. Always preferring worker would fail reverse ordering.

under the operation's existing short RLock, iff primary is None. Every reader read/
close, supervisor, caller start/wait/unregister, retained-owner scheduling and
release failure uses that same arbitration. Record is the first action of handled
critical paths, not deferred until other bookkeeping. No exception truthiness,
no caller-local competing primary, no thread-priority rule, no lock over IO/client
callbacks. Final selection reads the one latch and re-raises the identical object.
Opaque immutable evidence/trace semantics unchanged; ordinary cleanup failures do
not replace the first critical object.

Retained cleanup now catches/records critical exits without discarding exact roots.
If final release fails, preserve the first critical object and report immutable
UNKNOWN with sticky quarantine/exact retained ownership, rather than prematurely
claiming confirmed release or leaking an unowned handle. No speculative retry of
partially completed release, no force-clear or new recovery API. Normal confirmed
release remains unchanged. Background completion never rewrites returned UNKNOWN.
This correction does not add process/workspace/provider APIs or change App scope.
