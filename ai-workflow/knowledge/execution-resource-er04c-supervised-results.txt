How supervision / cleanup worked
--------------------------------
abortProbe is a separate interactive tool; ordinary ER-04 run.py remains
unchanged. The Integration operator inspected status and issued a token-bound
run command for EACH case. A controlled first-event boundary captures active
state and performs only that selected abort. The command reader and read-only
monitor remain independent of inference/cancel workers. No unattended batch,
automatic kill or automatic escalation exists in this tool.

Job cancellation uses the actual Job signal on a separate control thread.
Disconnect closes the retained actual response. Early-close closes the admitted
provider iterator on its owning reader thread at a yield boundary; the harness
does not fake a completed event. Timeout adjusts only the exact response socket
at that boundary. Stream-delete adds a fresh private X-Conversation-Id only in
the test-only transport wrapper; exact lookup precedes DELETE. The trusted
composer, owner grants, admission, profile and pipeline remain in use throughout.
The test-only _Session.stream wrapper is restored at case exit, not a source
change to ER-03. No ordinary application gets a raw driver/process capability.

After observing exact native stop AND the original unknown claim, the operator
explicitly issued terminate with the case's token. OwnedChild validates original
Popen object, PID AND retained Windows kernel handle, with exactly one recorded
child. No process is reopened by name/PID or discovered at a port. Each explicit
terminate was followed by wait/reap, actual exit code 1. No wait timed out, so no
kill command was issued. All case workers ended and command sessions exited 0.
The tool refuses finish while a live unknown child or worker remains. It never
calls host.stop to evade a tombstone; the original unknown state was still
recorded after process exit. All six retained children are confirmed reaped;
no probe operator session, inference/cancel/monitor worker remains active.

Provider-specific correction proposal (PENDING REVIEW, not implemented)
----------------------------------------------------------------------
Prefer the existing header-free path initially; this evidence does not require
opting every request into resumable semantics. A minimal correction would:
- Own an explicit per-operation transport/socket with a supported interrupt
  mechanism. The stop callback marks cancellation and interrupts only that
  transport; the reader owns final close. Do not block signal delivery on HTTP
  polling or rely on BufferedReader.close acquiring an in-progress read lock.
  The test-only private response.fp.raw._sock access is not a production API.
- Bind the native task while the exact admitted slot is demonstrably active,
  keeping the stable SSE identity separate. Establish the no-other-task/queued-
  request invariant under trusted managed ownership; otherwise remain unknown.
- Before closeExecution finalizes, await bounded same-task idle/release evidence
  on the same retained live process/generation. Missing correlation, changed
  owner/task/generation, deadline or failed IO remains UNKNOWN. Do not query
  later to repair a finalized ER-01 tombstone. Production evidence cannot rely
  solely on debug logs; the exact task-binding/slot acknowledgement rule needs
  explicit review. An attempt, DELETE status or arbitrary idle never suffices.
- Preserve Cancelled/Failed Job and rollback independently of confirmed cleanup;
  a native completion racing cancel may be safe to dispose without making the
  cancelled workflow successful. Retention/freshness promises remain unchanged.

Regression gates: blocked read and pre-header stop; absent/wrong/stale task ID;
natural completion/cancel race; changed process/generation; multiple owned slots;
owner/host revocation while drain is pending; repeated stop; no double finalizer;
unknown disposal remains quarantined. Re-run actual bounded cases on any proposed
correction and review ER-01/02/R1/R2 structural compatibility before acceptance.
An opt-in DELETE variant is an alternative if independently interruptible
transport is insufficient, with per-operation private keys and the SAME native
evidence requirements. No generic recovery, scheduling or architecture expansion.
