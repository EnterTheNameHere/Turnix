07. NAMING DECISIONS - APPROVED 2026-11-14
-----------------------------------------
07.01. ActantError is renamed PlatformError. It is the common base for
exceptions defined by platform contracts, not necessarily a report of
an internal platform malfunction. CoreError and CoreInvariantError
retain their current direct inheritance relationships; only the old
base name changes. No ActantError compatibility alias is introduced.

07.02. Use Tertalis for product identity, branding, and uniquely owned
namespaces (for example, tertalis.save-bundle@1). Otherwise prefer
semantic names reflecting responsibilities and concepts, such as
PlatformError, ApplicationRuntime, and MemoryValueSystem. Do not
mechanically prepend Tertalis to classes or rename meaningful concepts.

07.03. Agreed vocabulary:
  - Platform: overarching system and its provided facilities,
    responsibilities and contracts.
  - Framework: creator-facing programming model and contracts; a
    perspective of the platform, not necessarily a separate subsystem.
  - Runtime: an execution mechanism/environment qualified by scope;
    not an unqualified synonym for the whole platform. Python adapter
    execution and application execution may be distinct scopes.
  - Infrastructure: mechanisms supporting platform facilities.
No requirement to create classes or architecture subsystems merely to
match these terms.

07.04. Ambiguous existing identifiers, especially actantRunId, require
semantic review before replacement. RuntimeHost and ApplicationRuntime
are not automatically renamed. The rule is approved, not an exhaustive
identifier-by-identifier rename map.

07.05. NEXT APPROVED PLANNING STEP: prepare a read-only source identifier
rename map from a fresh actant-integration ref, separating straightforward
replacements from semantic questions; review the map before any rename
branch creation or source edit. Branch creation/source writes still need
