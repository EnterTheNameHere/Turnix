Selected narrow shared shape (names proposed for review)
----------------------------------------------------------
1. Provider-owned PrivateRequestEvidence broker, optional trusted constructor
   parameter on LlamaCppComposition, default None/off. Instance-local operation
   scopes, NOT module-global transport interception or generic event collection.
   Host policy lists exact initially composed caller EntrySelectors and required/
   disabled capture plus bounded maxBodyBytes. Existing selector/transition grants
   remain the sole execution authority. Definitions/providerOptions cannot mint
   capture rights, choose destinations or broaden policies.
2. Host archive port opens broker.scope(expected actual ApplicationRun/CodeEntry
   instance, immutable suite/unit/turn correlation, sink, required=True) around one
   ctx.llm.run. Scope has a non-serializable one-use nonce and is invalidated in
   finally; no global lookup by caller-supplied string grants. ContextVar belongs
   to that broker instance; no cross-thread/process/global capture subscription.
   Closed/copied/reused/nested/foreign scopes reject as appropriate, never leak.
3. compose already sees snapshot.owners actual identities AND runtime-issued owner
   objects; bind policy there, not from application names. Current
   LlmAdapterAdmission exposes residency/context/stop, NOT actual caller identity.
   Small candidate backend addition: trusted read-only owner reference supplied by
   LlmCallSession from access.owner when constructing LlmAdapterAdmission. Only
   provider validates identity against compose-time policy; never expose/store the
   live owner in App evidence. No new grant, Context or transaction. Integration
   may choose an equivalent narrower owner binding, but identity must be actual,
   not inferred from resource profile/filename/correlation/target label.
4. _Session.stream claims that one scope for its exact admitted ticket/owner after
   request options are validated, before stream IO. Estimator/template/slot traffic
   does not consume the inference scope. Keep admission, cleanup ownership and
   revocation checks unchanged. New execution after revocation denied; exact old
   ticket may still emit final diagnostic disposition through its already bound
   sink, without authorizing any new provider operation.
5. Immediately after constructing http.Request, capture EXACT immutable
   transport.data bytes, content type application/json, encoding utf-8, length,
   SHA-256 and opaque evidence-call ID plus safe owner/residency correlation.
   No reserialization, header/URL/cookie/Authorization capture or live handles.
   Raw user/model-facing body is explicitly private intentional content. Store
   original bytes as artifact; parsed view optional/non-authoritative. Provider
   wraps ordinary sink errors in fixed private failure categories, no raw paths
   through traces/observerErrors. Non-Exception exits keep first-exit semantics.
6. REQUIRED serialized/body artifact + record must ACK BEFORE OwnedHttpTransport.open
   can send. Absent/broken/wrong-owner/oversized/failing required capture rejects
   before inference send; no best-effort fallback. Default off does not allocate
   buffers or add bodies/paths to generic metadata/events/PM/G/traces. Explicit
   disabled policy is recorded unavailable/disabled by App, not full provenance.

Private phase facts (proposed actant.llamaCpp.requestEvidence@1)
-----------------------------------------------------------------
Provider uses the same sink for its exact admitted request, no global events:
 - serialized: exact Request.data length/hash/body reference, ACK required;
 - transport-attempt: durable intention BEFORE open; does NOT claim bytes sent;
 - response-headers-observed: only after exact open returns successful response;
 - final transport facts: actual mayHaveSent, response/body-observation availability,
   reason and stage when known, with serverConsumption ALWAYS unknown.
Capture booleans are observed facts, not a universal delivery enum or server ACK.
Initial App turn-attempt with no later provider evidence => capture/send unavailable,
not invented bytes. Serialized ACK only => prepared-for-transmission; if process
dies before final facts, delivery UNKNOWN (even if it died just before open).
Explicit final mayHaveSent=false after known pre-send failure => not-sent according
to this owned transport; true => may-have-sent, never consumed/delivered guarantee.
Header/SSE observation is only response evidence. Cancellation/pre-header/partial
send/final-sink failure preserves ambiguity and original Job/cleanup disposition.

Before-send sink failure is fatal and stops before open; existing finalizer handles
the actual unsent/uncertain provider state, not an archive-invented cleanup receipt.
After-send sink failure cannot unsend: poison archive, latch separate capture/write
failure and cooperatively cancel that exact Job as necessary; preserve primary
provider error/cancellation/UNKNOWN, no replay or claims repair. Final callback/
archive-close failure may be unpersistable; caller diagnostics and recovered prefix
must label missing observations unavailable. No generic best-effort observer change.
