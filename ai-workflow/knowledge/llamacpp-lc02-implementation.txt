Request precedence and exactness boundary
-----------------------------------------
providerOptions.chatTemplateKwargs maps to chat_template_kwargs, reasoningFormat
to reasoning_format; omission/null leaves out a field, explicit {} sends {}.
Known kwargs enable_thinking/preserve_reasoning require exact booleans and
reasoning_effort nonblank text. Request kwargs override matching server defaults
upstream. Request reasoningEffort overrides startup effort; within one request,
reasoningEffort plus template reasoning_effort fails even if equal. Effort 'none'
disables thinking/clears template effort and conflicts with enable_thinking=true;
none+false is allowed. Other efforts+false remain independently valid/dormant.
Template effort 'none' is only a template string. Request effort 'default' passes
through (unlike server effort default's special removal). Format does not control
generation. No per-request control mutates startup config, argv, profile identity
or managed sharing policy.

/apply-template and inference receive identical messages and reasoning/template
controls. Explicit external model reaches /apply-template and /tokenize; managed
model routing stays resident. Count is for the server-returned rendered prompt,
with no fallback when an endpoint/setting/protocol is unavailable. Safe profile
tokenEstimation records matched-request forwarding, pinned source and
effectiveHonor=unverified-binary-and-template, failurePolicy=raise-without-fallback-count.
Actual deployed template/endpoint honor remains a prerequisite, not an HTTP-success
attestation. Unknown kwargs are template-defined and not universally certified.
