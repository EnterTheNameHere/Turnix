Reproduced defects and corrected protocol
------------------------------------------
Own Python 3.15.0b4 reproduced all three Integration Event-controlled failures on
the synchronized original source before edits: capability entered composing;
runtime close and stop finalized a provider during an outstanding composer.
The original source's readiness/no-pending checks were detached from actual use.
Passing submitted tests did not establish those admission guarantees.

One callback-free runtime admission lane now serializes actual activation,
invocation and shutdown decisions. It is a lifecycle gate, not an ER-01 claim
manager or provider scheduling authority. Activation publishes its exact attempt
under this lane and rejects immediately if an invocation/finalizer already owns
admission, or shutdown/unload has closed it. It does not wait for a handler's
runtime execution lane. No gate/lane is held across composer callbacks.

Invocation reserves an issued ticket after readiness diagnostics and before
waiting for its existing execution lane. Actual invokeCapability/runJob entry
rechecks live ticket membership, issuing thread, phase and shutdown admission
while already in that execution lane. Tickets persist through outside-lane
lifetime cleanup; copied/expired scopes cannot authorize the actual entry.
Nested normal capabilities and existing Job/transaction serialization remain.
Lifecycle continuation records the exact attempt and issuing thread; onLoad/
lifecycle Contexts gain no direct LLM execution grant.

Shutdown's no-pending operation now closes actual admission BEFORE any provider
finalizer, not merely checking a snapshot. Permanent runtime/host closure cannot
reopen. A winning activation is revoked but retains objects until its composer
unwinds; shutdown returns typed pending. A winning shutdown prevents a later
attempt from starting. Active/queued invocation ownership blocks legacy teardown;
already-queued calls revalidate closed admission before arbitrary handler code.
Cooperative controlled stop still runs outside lanes with Job outcome preserved.

Host stop reserves every live/pending runtime's admission, including later batches
in active runtimes, before any resource finalizer. Application close does the
same for its exact runtime. Direct PackLoader unload keeps a reversible gate
through the entire outside-lane cleanup boundary; a successful unload can later
reactivate through fresh trusted composition. No old grant/Registration is revived.

Outside-lane lifetime and failed-attempt cleanup reserve actual finalizer tickets
against new activation. Runtime roots survive host removal until this finishes.
A composing registry's effects are deferred; unrelated registries still drain/
report failure rather than a global skip silently hiding their cleanup errors.
Pending cleanup keeps ownership and reports uncertainty; no polling/recovery or
callbacks under host/runtime/admission/registry/broker/domain lanes were added.

Equivalent-path audit also reproduced two adjacent lifecycle failures before
their narrow fixes: full Pack reload could not perform the new trusted binding
required by the old controlled-name tombstone; and a revoked non-null binding
could incorrectly satisfy the composition barrier. New replacement registration
now goes through explicit accepted bind/R1 validation (never legacy fallback),
and composer/barrier require the exact existing binding to be live. No grant
extension, broker internals mutation or new binding/admission API is introduced.
