01. Scope and exact evidence modes
-----------------------------------
Use DA-26 sections04/06's explicit three-way/missing-material discipline, without
claiming Window/StateEquality/DA-26 ComparisonResult or replay implementation.
New closed App enum EvidenceComparison: Equal, NotEqual, NotComparable. No boolean
equality facade. Fixed versioned modes, no automatic fallback or normalization:
 actant.experiment.answer-text@1: exact committed succeeded-turn answer string;
 actant.experiment.reasoning-text@1: exact separately exposed committed reasoning;
 actant.experiment.request-body@1: exact validated serialized BODY artifact bytes.
Empty exposed text is available, distinct from null/unavailable. Failed/partial
answer text never substitutes for completed answer. A failed call's valid serialized
body can compare; prepared bytes do not prove send or consumption. Missing final
suite record does not destroy a narrowly available field in a valid prefix.
Corrupt input always NotComparable, even if a selected prefix contains matching data.

One explicitly selected pair per compare command. No automatic row joining:
 compare --left DIR --left-unit ID --left-turn ID --right DIR --right-unit ID
         --right-turn ID --mode MODE [--allow-input-differences] [--format table|json]
Unit IDs select exact configuration AND repetition; turn IDs select exact records.
Labels/UUID equality alone never establishes equivalent inputs. Alignment signature
hashes immutable ordered USER role/content prefix through selected turn, turn ordinal,
historyPolicy and contextPolicy; conversation/name/turn labels are not identity.
Default requires equal signature; explicit allow-input-differences permits descriptive
cross-input comparison with differences disclosed. Explicit unit pair is the config
mapping; configuration/default/override/profile/source/asset differences are shown,
not silently required equal. Actual query-history digest and requested-options digest
are separate: equal user prefix can still have differing earlier generated answers.
No hidden zip by index, fuzzy alignment, automatic repetition pairing or weaker mode.
Absent/ambiguous selection yields NotComparable; same archive/observation copies are
labelled, never counted as an independent repetition or statistical independence.

Closed comparison reasons: source-invalid, source-unavailable, unsupported-version,
input-limit, selection-missing, selection-ambiguous, input-signature-mismatch,
turn-not-completed, answer-unavailable, reasoning-unavailable, body-unavailable,
field-available. Reasons can be a bounded list; no raw exceptions/paths. Equal and
NotEqual require field-available; a missing field never equals empty/zero/another
missing field. Equality claims only this selected mode, not suite success, cleanup
safety, model effectiveness, determinism, consumption, quality or replayability.
Difference summary is lengths/hashes plus first differing code-point offset for text
or byte offset for body. Linear bounded scan, no quadratic diff or default snippets.
