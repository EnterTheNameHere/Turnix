PUBLIC GRANT CONTRACT / BACKEND BOUNDARY
---------------------------------------
Only backend production change: backend/observation.py version 1 -> 2. Collectors,
stream measurement/execution, contexts, runtime/host and PackLoader are unchanged.
New types: ObservationReadGrant, frozen ObservationPublicationSnapshot and
ObservationGrantRevoked. The existing context already supplies ObservationFacade;
no separate context/module change was necessary.

- ctx.observations.export(session): requires a valid invocation and the actual
  selected same-ApplicationRun session owner. Rejects expired/foreign/released
  authority; no caller-supplied application identity is trusted.
- grant.snapshot(): selected immutable session/clock identity, source request and
  lifetime plus the existing ObservationSnapshot. This reads no new hardware and
  retains no invocation context/validation callback. It may advance existing PM-02
  live window summaries according to the accepted snapshot contract.
- grant.revoke()/grant.revoked: revoke/check only this read scope. There is no source
  release, inference execution, subscription creation or session-discovery API.
- ctx.observations.bindReadGrant(grant): validates same-app invocation authority and
  acquires a separately revocable derived publication reader. Revoking its parent
  ends derived reading; revoking the derived reader leaves its parent/peers intact.

Grants acquire NO collection or source-lifetime claim. RUN sessions still release
on source invocation invalidation. Explicit APPLICATION ownership is required for
source lifetime beyond the invocation. Session release revokes its weakly registered
readers; ApplicationRun/host teardown revokes source ownership as before. No expired
context is retained. Already copied immutable evidence remains caller-owned.
Grant construction/binding/reading/revocation is serialized under the source service
lock. Cross-service/foreign binding cannot substitute an ID for owner identity.
These are mediated public API guarantees for trusted in-process Python Pack code,
not a Python introspection sandbox. No object internals cross the JSON boundary.

PACK / APPLICATION PUBLICATION
------------------------------
Pack ID: observation.bridge, modPack version 0.1.0.
Source bundle: first-party/observationBridge/{manifest.json,codeEntry.py,bridge.py,
schema.py,__init__.py,README.md}. Helpers load relative to the resolved Pack root,
including when copied outside first-party; the process cache holds code only.
ManualActivationPlan must explicitly select it in the publishing application.
Activation creates one endpoint and zero observation sessions, collectors or
automatic inference attachments. Each activated instance owns its endpoint/state.

Capabilities (all same-ApplicationRun through existing capability mediation):
- observation.bridge.publish@1, exactly {grant}: the fresh bridge invocation binds
  its own reader through the facade, then returns publicationId/snapshotUrl/schemaId/
  sessionId/clockEpochId. Raw sessions, fabricated payload shapes and foreign grants
  are rejected. Multiple publications can derive independently from one parent.
- observation.bridge.withdraw@1, exactly {publicationId}: idempotent publication
  withdrawal; clears its cache and derived reader, leaving source/parent/other
  publications/readers/consumers unchanged.
- observation.bridge.connection@1, no payload: private descriptor containing
  endpoint, readCredential, authorization=Bearer, schemaId and allowedOrigins.

At most 8 publication entries, each retaining only its latest bounded response and
fixed fingerprint/revision; no accumulating or persistent history. Source retention
must be <=512 hardware samples and <=512 stream windows. Larger configured sources
are rejected, not silently clipped. Per-core CPU output caps at 256 and reports exact
droppedCoreCount. Encoded responses cap at 2 MiB. A source/parent-revoked publication
returns 410 and clears cached bytes; its bounded entry remains until withdrawn.

AUTHORIZATION / ENDPOINT / LATER VIEWER HANDOFF
----------------------------------------------
Initial adapter: replaceable standard-library read-only loopback HTTP polling.
Bind is always literal IPv4 127.0.0.1; default port 0 is collision-safe ephemeral.
No external bind, host-wide session registry/discovery or cross-app aggregation.
One request worker, backlog 8, finite socket I/O timeout, one response per connection;
shutdown actively interrupts accepted sockets, including partial HTTP headers.
No reader thread fanout or new collector. The adapter never invokes runtime
capabilities from HTTP threads and never captures onLoad/cleanup contexts.

GET /publications/<opaque-128-bit-id> requires Authorization: Bearer <credential>.
Credential is random 256-bit per activated instance, not a query parameter/cookie.
Host must equal 127.0.0.1:<actual-port> exactly. Present Origin must match an explicit
configured local HTTP-origin allowlist (including port); default list is empty.
Origin-free authenticated nonbrowser tools work. Wildcards, null/file origins,
external origins, paths and credential-bearing origins are rejected.
Browser OPTIONS preflight checks Host, allowlisted Origin, GET and requested
Authorization header; it returns no observations and needs no read credential.
No credentialed wildcard CORS, logs, HTTP credential/discovery route or mutation API.
Responses, including parser/unsupported-method errors, use fixed non-reflective
JSON and no-store headers; request/error handling never emits credentials or raw source
diagnostics. Browser credentials are not inferred from loopback proximity.

The intended later G-02 viewer obtains the connection descriptor and selected
publication URL explicitly from the application/user out of band (for example,
copy/paste into its future connection form), keeps credentials in memory, and sends
the Authorization header. No token in URLs/share links/logs or default persistence.
The application's observationBridge.allowedOrigins names that viewer's local HTTP
origin before activation. G-01 serves no HTML/browser viewer and installs no discovery
or general hosting infrastructure. Concrete G-02 UI/browser smoke test remains later.

REVOCATION / SHUTDOWN ORDERING
------------------------------
The publication lock covers validation, serialization/cache and response sending.
Withdrawal waits preceding sends, removes cached evidence and revokes only its
derived reader before returning. Source grant reads linearize under the observation
service lock; source/parent revocation stops later reads. An already copied in-flight
response may finish after source revocation as caller-owned evidence. No source-lock
callback enters the bridge, avoiding reverse lock ordering. Every read revalidates
before using cache; 410/503 never serve cached fallback. Bounded bytes may remain
until next validation/withdrawal/unload but cannot bypass the validation check.

Unload first rejects new work and interrupts accepted clients, then withdraws
readers/caches, stops/closes/joins the endpoint and erases its credential. Teardown
uses no invocation observation authority. onLoad failure self-cleans even if
PackLoader subsequently calls onUnload with None. Failure after onLoad returned
state uses ordinary PackLoader cleanup. Cleanup errors remain reported; resource
revocation happens before a final socket-close error can escape. Source observation
sessions and independent grants/consumers survive bridge-only unload.

VERSIONED SCHEMA / G-02 CONSUMER CONTRACT
----------------------------------------
Schema ID: actant.observation-publication@1. Transport-independent serializer:
first-party/observationBridge/schema.py:serialize(). Exact field/unit/HTTP contracts
and application examples are documented in the Pack README at the implementation ref.

- Opaque publication/session identities and evidence-change revision.
- clock.kind=host-process-monotonic, random ObservationService composition epochId;
  all its application owners share it. Reconstructed/injected services get new
  epochs. A later viewer must reject unsupported schema and reset association on
  epoch change; bridge restart also creates new publication IDs/credentials.
- All exact integer evidence uses decimal JSON STRINGS: nanosecond timestamps/gaps,
  counts, bytes, revision and retention limits. Null means unknown; bounded
  hardwareIndices are ordinary array indices. A later JS viewer should parse Ns as
  BigInt, subtract a common origin, then convert relative deltas for plotting.
- Explicit units/encodings, whole-host hardware scope, source lifetime and needs.
- Original sequential collection start/end, separate display Unix wall Ns,
  target/actual cadence, RAM/swap/CPU/GPU/VRAM and optional numerical sensor evidence.
  Tagged scalar availability/unit/value distinguish missing values from real zeros.
- PM-02 origin/observed-through/end/first/last text, first-text latency, silence,
  Unicode character/delivery counts, state/outcome, bounded half-open windows,
  gap count/sum/min/max, partial flags and character delivery rates. No token inference.
- Exact stream droppedWindowCount, source retention bounds, conservative hardware
  truncation and hardwareDroppedCount=null (PM-01 has no exact eviction counter).
- Correlation references overlapping hardware intervals and uncovered Ns spans,
  never simultaneous-read claims, interpolation or assumed missing poll counts.
- Fixed availability markers replace raw reasons. No prompts, responses, generated
  text, native-token metadata, arbitrary provider metadata, Python internals,
  exceptions/tracebacks, GPU names/performance-state strings or unrelated app data.
