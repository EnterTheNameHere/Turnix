--------------------

RuntimeHost.executionResources is an ExecutionResourceService. Trusted composition
registers stable domain ID, immutable envelope key and exact adapter. Only identical
adapter/key registration reuses a domain; failed/unknown tombstones persist after
the final participant closes. No replacement can bypass outstanding cleanup.
ResidencyDescriptor is frozen. Complete immutable identity bytes must be safe
opaque fingerprints; the adapter owns completeness/payload immutability. Core
never compares/hashes/renders payloads. Repeated profile registration requires the
same issued descriptor, without certifying equivalence of opaque provider objects.
Generation increases on every materialization attempt, including failed attempts.

domain.openParticipant(allowedProfiles=..., allowIdleTransition=...) is a trusted
host grant API, not a public Pack assertion. Exact issued participant identity is
authority; future ER-02 derives it from actual runtime/invocation ownership. There
is no hostile-Python sandbox. participant.acquire(profile, reservation=...,
retained=..., cancellation=...) admits ready compatible work only; no implicit load.
Explicit transitionIdle/unloadIdle requires the host grant, approved profile and
no operations/reservations/pins. Ordinary compatible claims can coexist; capacity
scheduling is not provided. reserveExclusive pins a generation, denies unrelated
compatible calls and requires the exact reservation for its own operations.
Overlapping/reentrant reservation calls fail Busy. Own idle pins may stay;
foreign pins block exclusive acquisition. Participant lifetime alone is not a pin.

OperationClaim.finish/retain/bindStop and pin.invalidate are trusted adapter hooks.
Future Pack facades must never let an owner assert provider quiescence. Revoked
objects retain exact cleanup authority; duplicate equal finish is idempotent,
foreign/conflicting finish cannot alter state. Stop binding is once-only;
unregister withdraws without allowing replacement. Pending stop survives late
binding. Running stop callbacks keep claims installed even after confirmed finish.
claim.retain(payload, disposer) transfers ownership only when a pin is returned;
otherwise the adapter remains responsible. Pin context generation is distinct
from residency generation and survives between calls. Reuse checks owner, issued
identity, generation, loss, revocation and concurrent use. Loss is ContextLost,
never implicit rebuild. Closing a used pin defers its registered disposer until
confirmed operation drain. Disposer runs once outside locks; exceptions/unknown
effects retain its exact blocker. Closing reservations cannot release exclusion
while child operations/pins remain. No provider slot/cache/reset mechanism exists.

ProviderEffect has attempted/acknowledged/failed/unknown plus independent confirmed/
unknown quiescence. Local close, cancellation and Job terminal state do not prove
quiescence. Callback exceptions/malformed results fail closed without private text.
Unknown state blocks new admissions/transitions and invalidates outstanding claims
for new provider entry, preserving their cleanup rights. No automatic recovery.
TransitionOutcome separates materializationEffect from later disposal effect.
Known-empty failed startup needs explicit retry; no silent old-model restoration.
Late cancelled/closed materialization cannot reach its owner; its ticket disposes
any returned object once. Known absence/successful disposal leaves empty/closed,
including a failed late load that left no object. Unknown cleanup stays protected.

Service/domain close only revokes admission and defers callbacks. finishClose must
be called outside host/registry locks. Late completion during legacy host teardown
cannot dispatch stop/unregister/disposer callbacks through the first close stage.
Registered callbacks, outstanding objects and the service table own deferred cleanup;
no implicit drain thread. RuntimeHost.stop keeps legacy cleanup under its existing
lock and invokes new finishClose after leaving it. STOPPED does not imply drain;
repeat stop reports pending/failed/unknown work and can finish late-confirmed work
without repeating provider release. Legacy errors and resource disposition aggregate.
