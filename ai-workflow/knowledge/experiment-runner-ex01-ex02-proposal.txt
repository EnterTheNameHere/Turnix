Definition v1 (JSON)
---------------------
{
  "schemaId": "actant.experiment.definition@1",
  "experimentId": "two-turn-demo",
  "configurations": [{
    "name": "baseline",
    "profile": "qwen-demo",
    "defaults": {"temperature": 0, "maxTokens": 24, "timeoutSeconds": 30},
    "allowedOverrides": ["maxTokens"]
  }],
  "conversation": {
    "id": "remember-word",
    "historyPolicy": "replay-answers",
    "turns": [
      {"id": "t1", "role": "user", "content": "Remember the word amber."},
      {"id": "t2", "role": "user", "content": "Which word did I ask you to remember?"}
    ]
  },
  "repetitions": 1,
  "errorPolicy": "stop",
  "contextPolicy": "fresh-best-effort"
}

Exactly one configuration and one conversation in v1; reject additional configs
or repetitions rather than silently ignoring them. At least two, at most 16 turns.
User-only input turns, each producing one assistant reply. System/tool messages,
seeded assistant messages and multimodal input are rejected in this package;
current actant.llm.messages@1 supports user/assistant only. IDs/names are exact
nonblank strings, unique in their scope, max 128 characters. Content is exact
nonempty text, at most 16384 characters per turn; no whitespace normalization.
The JSON file is capped at 1 MiB before parsing. Reject duplicate object keys,
unknown fields, nonfinite numbers, bool-as-number, null controls and invalid UTF-8.
Parsed records and nested options are copied/frozen before activation; no mutable
caller aliases can change a validated experiment or constructed outgoing query.

Each turn may additionally contain "overrides": {supported option: value}.
Only configuration.allowedOverrides keys may appear. Defaults merge with that
turn's overrides without mutating either record. allowedOverrides must be unique
and a subset of the supported option names. Required defaults: maxTokens and
timeoutSeconds; default temperature is explicitly 0.7 if absent.
Supported bounded initial options: temperature finite 0..2; maxTokens exact int
1..4096; timeoutSeconds finite >0..120; topP/minP finite 0..1; topK exact int
1..100000; repeatPenalty finite >0..10; seed signed 32-bit exact int;
reasoningFormat one of none/auto/deepseek/deepseek-legacy; reasoningEffort nonblank
text <=128 chars; chatTemplateKwargs only exact boolean enable_thinking and
preserve_reasoning in v1. Provider supports a wider kwargs surface; this narrower
Application schema is intentional. Match provider conflicts: reasoningEffort=none
and enable_thinking=true reject. Do not invent an effort effectiveness guarantee.
Validate every merged turn's options before process startup. Host policy further
caps maxTokens/timeout/turn counts; experiment bounds cannot enlarge those caps.
The real demo remains token24/context1024; general schema caps are not permission
to increase those local validation limits.

Any startup options, argv/env/path/URL/port/domain/grant selectors or REQUIRED
physical freshness/retention promises fail validation. contextPolicy only accepts
fresh-best-effort; errorPolicy only stop; historyPolicy only replay-answers.
Requested unsupported policies are explicit errors, never silent downgrades.

Trusted host boundary
-----------------------
The CLI selects an explicitly supplied local host config separately from the
definition. It is host-trusted input, never embedded in or resolved from the
experiment. A host-approved alias table maps qwen-demo to a catalog selector and
provider llama.cpp; names do not establish descriptor compatibility or grants.
Validate alias existence, all request options and resource caps before activation
or transition. Build catalog with LlamaCppCatalog.fromConfig; install immutable
LlamaCppComposition with exact EntrySelector.fromSource for the manifest provider
and app CodeEntry, restricted LlamaCppGrant(selectors, allowTransition=True).
No fallback to unmanaged/external mode or broadened grants on error.
The app resolves ctx.llm.profile and explicitly calls transitionProfile once
before first inference. Busy/draining/unknown rejects without retry or takeover.
Activation publishes capabilities but does not load a model. No lifecycle-hook
inference, helper grants, raw driver access or arbitrary Pack config authority.

History and invocation
------------------------
One Application capability/Job executes the ordered conversation. Before every
turn check cancellation. Use LlmMessages/LlmMessage to produce canonical immutable
actant.llm.messages@1 query payload; pass it to ctx.llm.run with resolved model,
merged providerOptions and FreshContext(required=False, retain=False).
Turn 1 sends [user1]. Turn 2 sends [user1, assistant1.rawText, user2]. Continue
analogously. Append only a successfully completed answer. Preserve answer text
exactly, including empty answers; reasoning metadata never enters history.
No clipping/summarization or hidden overflow rewrite: provider/budget errors stop.
Use the existing admitted estimator if needed; no independent raw tokenizer call.
Each call retains existing estimation/inference/cleanup protection. This package
does not reserve the entire conversation: other authorized work can intervene
between turns, and the next call may fail after a residency transition. Do not
automatically restore the profile. EX-03 owns exclusive multi-turn policy.

Run result v1 / minimum persistence
------------------------------------
Every invocation receives a fresh opaque runId, separate from experimentId and
definition. Proposed result schema actant.experiment.result@1 contains:
- runId, experimentId, immutable definition snapshot, definition SHA-256 over a
  documented canonical JSON encoding, configurationName and requested profile alias;
- status (succeeded/failed/cancelled), started/ended wall times and monotonic
  durationNs; Job terminal outcome remains separately recorded by the launcher;
- ordered turns with turnId, input, exact structured query snapshot, merged
  requested options, answer, separately exposed reasoning or null, bounded native
  usage/model/finish metadata, safe resolved executionProfile metadata, timing and
  executionEvidence.snapshot() when available;
- per-turn status, bounded error category/stage, and remaining turns explicitly
  not-started; failed calls have null unavailable fields, never invented evidence;
- separate cleanup evidence/status per attempted call; missing evidence remains
  unknown/unavailable, never inferred from success, cancellation or process exit;
- explicitly selected private host configuration evidence, labeled planned versus
  actual/effective unknown as supplied by composition.configurationEvidence.

Run success requires all turns and the containing Job succeed. Do not report a
successful run merely because turn 1 completed. In-flight partial deltas may be
retained privately with partial=true, bounded by host output limits; never append
them to next-turn history. No retry after errors or UNKNOWN cleanup. Preserve
primary cancellation/failure even when resource cleanup independently fails.

Minimum result seam: Application onLoad state owns a bounded, single-run recorder
containing immutable snapshots only (no invocation Context/IO/transaction/handles).
Reject overlapping runs. A read-only inspection capability retrieves that
recorder after runJob returns, including after rollback; it is explicitly ephemeral
diagnostic state, not committed authoritative mutation or crash-safe storage.
The trusted CLI atomically writes one private result JSON to an explicitly chosen
local results directory before runtime teardown. Result-write failure is reported
separately and makes CLI exit nonzero; do not claim durable archival. No automatic
saveApplication dependency or full export/archive/comparison facility. EX-04 owns
crash durability and full query-as-sent wire provenance; structured query snapshots
here are planned/application-sent data, not proof of exact HTTP serialization.
CLI defaults to runId/outcome/count/path summaries; explicit inspect shows private
content. Raw exceptions, prompts/reasoning, paths and host settings never enter
global logs/monitoring. Native task IDs, grants and live handles are not persisted.

Proposed terminal surface
---------------------------
python first-party/applications/experimentRunner/run.py validate --definition FILE --host-config FILE
python first-party/applications/experimentRunner/run.py run --definition FILE --host-config FILE --results DIRECTORY
python first-party/applications/experimentRunner/run.py inspect --result FILE
Validate performs no model launch. Host config paths never appear in the checked-in
example definition. Ctrl+C requests cancellation through a caller-retained Job
handle and waits for normal runtime cleanup; never kill a guessed PID/port.

Review / evidence boundary
----------------------------
No new reusable API is proposed. The review approved these choices:
restricted input roles/options, per-call freshness plus replayed answer history,
ephemeral failure recorder plus private CLI result file, and no conversation-wide
reservation. Assignment defines tests and actual two-turn acceptance separately.
This proposal is source inspection only: no new runtime test or real demo executed.
Actual acceptance requires two nonempty Qwen replies, not a semantically correct
memory answer. Keep launcher failure and private result-write failure separate
from original run/turn/Job outcomes; preserve partial diagnostics where possible.
