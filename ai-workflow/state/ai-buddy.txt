PROVIDES
--------
- Independent application pressure from a long-lived application which may remain
  active concurrently with Completion while temporary Materialization Test runs
  start and end.
- Concrete pressure for event-driven/scheduled execution slices, multiple concurrent
  service loops with different latency classes, queued continuation work, waiting
  work, interruption, and cancellation.
- Concrete pressure for provider-independent specialist capabilities such as ASR and
  TTS whose implementation may be local, Windows-native, dedicated-runtime, or
  remote/cloud without changing application intent.
- Concrete pressure for shared host knowledge of concurrently running applications,
  model/resource demand, and reusable cross-application drivers/Packs.

REQUIRES
--------
Shared Actant/Integration ownership is expected for reusable behavior exposed by AI
Buddy. Initial pressure overlaps Completion strongly:
- host/shared managed model and driver lifetime above one ApplicationRuntime;
- coexistence of multiple simultaneously active applications requesting shared
  Actant facilities;
- model/resource acquisition, release, replacement, and arbitration without each
  application starting mutually unaware providers;
- cancellation/interruption semantics capable of stopping active inference rather
  than merely ignoring its eventual result.

Additional AI Buddy pressure likely includes:
- scheduler/event semantics where work may be runnable, waiting, terminal, or
  continued in bounded steps while the scheduler regains control between steps;
- low-latency interrupt processing that may execute beside slower cognition work;
- specialist capability requests whose driver/provider location is an implementation
  concern rather than application semantics;
- long-lived application/host lifetime suitable for desktop use.

The host/client direction is not itself an AI Buddy requirement. However, existing
DA-28 and IS-03..IS-06 already describe RuntimeHost as a long-lived host boundary,
multiple ApplicationRuns, startup modes including host/connect/serve behavior, and
client connection surfaces. Since Completion + AI Buddy now create immediate need
for one shared running authority, Integration is advised to evaluate that design
family early instead of growing another temporary per-application hosting model.
The design may be changed substantially: current DA/IS drafts are inputs to live
implementation pressure, not reasons to preserve an idea that proves weaker than a
newer materialized solution.
