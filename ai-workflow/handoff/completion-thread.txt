DECISIONS / BOUNDARIES
----------------------
- VS Code extension owns VS Code-specific integration and supplies information only
  VS Code has authoritatively, especially unsaved editor buffers, cursor/selection,
  and open-editor state.
- Source files observed by Completion are data/resources, not CodeEntries merely
  because they contain executable source code.
- Completion should use Actant/shared model execution facilities rather than own a
  permanent Completion-specific llama.cpp authority.
- Request arrival to Actant, application activation/resource acquisition, and the
  eventual request to llama.cpp are distinct lifecycle operations.
- Expensive model residency must ultimately be releasable independently of the
  logical availability of the Completion application.
- Shared/runtime requirements discovered by Completion belong to Integration; the
  Completion branch owns application-specific iteration.
- The Completion thread cannot perform Git merges. When Integration materializes a
  dependency needed here, stop at a safe synchronization boundary and ask the user
  to merge actant-integration into actant-completion.
- Python 3.15 runtime tests likewise require the user when static reasoning is no
  longer sufficient.
