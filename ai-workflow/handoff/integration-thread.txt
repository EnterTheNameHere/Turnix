Reconciliation results
----------------------
ManualActivationPlan + mechanical PackLoader preserve the DA-14/DA-29 authority
shape and are an intentionally incomplete PackManager substitute.

CodeEntryContext substantially preserves DA-30 ModCallContext lifetime and
mediation semantics for the currently implemented facade subset.

LlmProcessingPipeline is a fixed LLM-specific partial materialization of DA-31.
The exercised Evil path correctly nests its ProcessingRun transaction under the
outer Job transaction. Direct runProcessing() against the committed root can,
however, make ProcessingRun completion the effective authoritative commit
boundary; do not make that the final generic ProcessingPipeline contract.

The previously flagged runJob() memory-before-I/O ordering is now classified
more precisely. DA-04 and DA-24 explicitly allow already committed state to
remain authoritative even when the owning OrchestrationUnit later fails. A
repository regression test deliberately requires a failed Job with
 authoritativeStateAccepted=True after managed-I/O publication failure. This is
therefore not an accidental ordering defect. The incomplete part is DA-07:
current ManagedIo is not yet the full IoManager with identity-bearing rollback
points, provider system, root enforcement, and recovery semantics. Do not claim
cross-domain memory+filesystem atomicity that does not exist.

SaveBundle/ApplicationStore match DA-20 identity shape but materialize only the
committed-value portion of the designed durable closure. Immutable generation
and current-pointer recovery mechanics are candidate implementation-spec design
for later promotion.

Producer/validity/provenance/dependency identity and SourceObservation remain
candidate newer implementation design awaiting documentation integration.

Shared llama.cpp findings
-------------------------
first-party/llmDrivers/llamaCpp is the correct shared provider for both active
applications. It owns one long-lived driver per loaded CodeEntry, supports
managed/external server operation and model switching, and exposes exact token
estimation plus streaming chat completion.

Current dedicated tests cover parallelSlots and exact token estimation only.
The provider and its test file predate the new source-documentation rules:
codeEntry.py has many undocumented classes/helpers/lifecycle functions, and
 test_llamaCpp.py lacks the required first-line path/version marker. Any code
change there must bring touched files into the current source rules and expand
coverage appropriate to the change.
