Implementation reconciliation rule
----------------------------------
Repository presence does not imply liveness. Classify design/implementation
mismatches as incomplete implementation, apparent defect/divergence, or
candidate newer design embodied in implementation. Several live files explicitly
mark producer/validity/provenance, SourceObservation, committed-value snapshot,
and SaveBundle semantics as design-significant material awaiting documentation
promotion; preserve those as candidate newer design rather than deleting them to
match older documents.

Important unresolved semantic point
-----------------------------------
ApplicationRuntime.runJob() currently commits the authoritative value
transaction before ManagedIoTransaction.commit(). authoritativeStateAccepted is
set after the value commit. If I/O publication then fails, the Job fails but the
memory mutation has already become authoritative. The intended project concept
has described the topmost orchestration unit as the successful grouping and
transaction acceptance boundary. This ordering therefore needs deliberate
design reconciliation before we build further generic orchestration/checkpoint
semantics on it. Do not silently change it without checking the relevant design
and application requirements.
