Design discovery
----------------
Actant currently has two design-document roots during the documentation
migration:

1. Legacy specification corpus under docs/, routed by
   docs/CMR-04_CANONICAL_INDEX_TURNIX_SPECIFICATION.txt.

2. Migrated/new design material under design/. Tracing has crossed this
   migration boundary: the tracing documents under design/area/ are the
   authoritative tracing design even though CMR-04 cannot index that root under
   the current CMR rules.

Do not infer a project-wide rule that design/ supersedes docs/. Treat an area
as migrated only when that transition is established. Do not add design/ to
CMR-04 merely to repair the transitional asymmetry.

The following authoring/rewrite work is excluded from implementation knowledge
and design discovery:
- docs/design/rewrite_recommendations/
- docs/design/upcoming/

Implementation evidence
-----------------------
Repository presence does not imply live implementation. Determine liveness from
imports, construction/activation paths, tests, and known consumers.

The currently exercised Evil Birthday application path is a known-good
materialized slice: the application is reported fully functional with its data
sources and the repository test suite is reported green. This establishes an
integration baseline, not design authority.

When implementation differs from current design, distinguish:
- incomplete implementation of documented design;
- apparent defect or accidental divergence;
- candidate newer design embodied in implementation but not yet propagated to
  the design corpus.

Preserve and document evidence for the third case rather than automatically
rewriting it back to older design.
