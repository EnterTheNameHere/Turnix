ACTANT - SHARED WORK INDEX
==========================

Purpose
-------
This is the routing entry point for independently contextualized Actant workstreams.
It is operational coordination metadata, not an Actant design specification and not
part of the CMR canonical index.

Canonical coordination ref
--------------------------
actant-integration

All shared coordination reads/writes MUST explicitly use this ref, even when the
conversation is implementing on another branch. The coordination ref is a storage
and routing location; it does not make Integration the owner of all coordination
material.

Design discovery
----------------
Actant currently has two design-document roots during documentation migration:

1. Legacy specification corpus under docs/, routed by
   docs/CMR-04_CANONICAL_INDEX_TURNIX_SPECIFICATION.txt.

2. Migrated/new design material under design/. Tracing has crossed this migration
   boundary: tracing documents under design/area/ are authoritative for tracing even
   though CMR-04 cannot index that root under current CMR rules.

Do not infer a project-wide rule that design/ supersedes docs/. Treat an area as
migrated only when that transition is established. Do not add design/ to CMR-04
merely to repair the transitional asymmetry.

Exclude from implementation/design discovery:
- docs/design/rewrite_recommendations/
- docs/design/upcoming/

Implementation evidence
-----------------------
Repository presence does not imply live implementation. Determine liveness from
imports, construction/activation paths, tests, and known consumers.

When implementation differs from current design, distinguish:
- incomplete implementation of documented design;
- apparent defect or accidental divergence;
- candidate newer design embodied in implementation but not yet propagated to the
  design corpus.

Preserve and document evidence for the third case rather than automatically
rewriting it back to older design.

Branch topology
---------------
Shared integration line: actant-integration

Application branches consume shared integration changes through explicit Git
synchronization. Shared framework and reusable-Pack changes ultimately belong on
actant-integration; application-specific iteration remains application-owned.

The canonical coordination ref is independent of those working branches. Mail/state
routing MUST therefore specify actant-integration explicitly rather than relying on
the caller's currently checked-out branch.
