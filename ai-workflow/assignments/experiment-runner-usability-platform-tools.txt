OBJECTIVE
---------
Make root setup.ps1 install and verify the shared development tooling Ruff and ty
alongside the existing repository-local embedded Python. This is platform-wide:
tools should be available to every Actant application/workstream, not provisioned
privately by Experiment Runner.

CURRENT BASELINE
----------------
setup.ps1 currently installs embedded Windows Python 3.15.0b4 from the tracked
vendor archive, normalizes its ._pth/sitecustomize, verifies pip, installs root
requirements.txt, and sets Git hooks. Root requirements.txt currently lists json5,
nvidia-ml-py, psutil, pytest. It does not install Ruff/ty. The accepted EX-06
Application at af595124 used separately approved native Ruff/ty binaries; that
does not establish fresh-clone readiness.

REQUIREMENTS
------------
1. Preserve existing root setup semantics, Git hook behavior and embedded Python
   selection. Install Ruff and ty using the root-owned local Python environment,
   with centrally owned, versioned dependencies/constraints appropriate to the
   installed Python version, rather than relying on global PATH or installing
   separate App-owned binaries. Prefer root python-embedded/Scripts/ executables,
   but verify actual install behavior instead of assuming launchers exist.
2. Detect and report resolved executable paths, versions and a usable invocation.
   Validate both on first install and on idempotent rerun. Report failures clearly,
   do not print 'Setup complete' when required tooling failed.
3. Keep Python 3.15 primary. Document and exercise a supported 3.14 fallback, if
   feasible and explicitly selected; do not silently downgrade or replace root
   Python. If package compatibility prevents fallback, report precise limitation.
4. Do not silently loosen root quality/lint/type policies or force Ruff/ty checks
   onto unrelated existing sources just by provisioning the tools.
5. Define a clean, generic handoff for optional Application-local first-use setup,
   so the desired user journey is a single execution of root setup.ps1 followed by
   editing App local/run.bat. Integration owns shared setup orchestration; the
   Application owns contents and behavior of its local setup. Do not make shared
   root setup depend unconditionally on Experiment Runner or perform destructive
   App workspace writes. Agree invocation/discovery details with App workstream
   before implementation. Keep installation safe for checkout with no such App.
6. Ensure private/local tool/asset paths and credentials are not committed.
