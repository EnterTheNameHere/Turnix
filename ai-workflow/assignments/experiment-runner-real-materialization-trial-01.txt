01. GOAL
--------
Exercise accepted EX-06 under a realistic, inspectable materialization task.
Measure whether a local model generates substantial Python code, what Ruff and
ty observe/correct, and what changes after one feedback inference. This is NOT
another short smoke test and NOT proof of semantic program correctness.
Run through the existing host-selected, managed llama.cpp and configured tool
interfaces; do not execute or import model-produced source.

02. ONE SELF-CONTAINED TASK
--------------------------
Generate one Python module implementing a line-oriented event-log parser plus
deterministic summary. Requirements to author as UTF-8 priming/task files (or
literal parts) for the actual procedure:

- Input records: UTC timestamp, severity, source, message, separated by '|'.
- UTC timestamp uses YYYY-MM-DDTHH:MM:SSZ; reject invalid dates/times and
  missing timezone designator.
- Severity exactly DEBUG, INFO, WARNING, ERROR.
- Source is nonempty and trimmed; reject empty source.
- Message may include escaped pipe (\\|) and backslash (\\\\); reject dangling
  backslash and unsupported escape sequences. Define explicitly whether field
  split occurs before or after unescaping and test it in manual assessment.
- Provide immutable typed Event representation.
- Provide parseLine(line: str) -> Event; parseLines(lines: Iterable[str])
  -> list[Event], where malformed input raises a meaningful ValueError with line
  context without exposing unrelated files/secrets.
- Provide summarize(events: Iterable[Event]) with deterministic ordered
  severity and per-source counts, plus formatSummary(...) -> str.
- Pure Python standard library, no network/filesystem access, no process
  execution, no third-party imports, no generated tests required.
- Python target 3.15 with working fallback semantics on Python 3.14.
- Explicit type annotations, four-space indentation, double-quoted strings;
  prefer camelCase and PascalCase identifiers.

This task is a proposed fixed benchmark fixture, not a claim that its prose or
model solution has already been validated. Freeze exact text before the run.
Use the same priming/tasks for both inferences and all repetitions.

03. TRIAL PROCEDURE
-------------------
Reuse the accepted example.procedure.json5 step pattern:
message (frozen priming/task) -> inference 'draft' -> save exactly one Python
fence -> ruff-safe-fix -> ruff-format -> ty-check -> ruff-check -> message
(current artifact + diagnostic CLI results + correction request) -> inference
'corrected'. Exactly two inference steps and four approved CLI calls.
No implicit final answer save, extra validation tool, semantic fix loop, or
model-selected tool call. Retain final response separately from saved draft and
post-Ruff working artifact in the archive.
