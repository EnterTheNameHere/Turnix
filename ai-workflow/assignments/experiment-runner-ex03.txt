Required definition / execution contract
-----------------------------------------
1. Retain one immutable conversation definition with 2..16 ordered user input
   turns and answer-only replay. Extend configurations to an ordered nonempty
   list with unique names, each with a host-approved profile alias, defaults and
   permitted turn overrides. Configuration name is a label, never a descriptor
   compatibility key. Definitions cannot grant selectors or supply startup paths,
   argv/env/ports/domain/process controls. All selected aliases and merged options
   must validate before any model startup, including an invalid LATER config.
2. repetitions is an exact positive integer, excluding bool. Deterministic order:
   configurations in definition order, then repetition indices 1..N for each.
   Do not reorder to optimize residency or run concurrently. Histories start empty
   for EVERY unit, even for identical profiles or later runs. Within each unit:
   first [user1], then [user1, assistant1.rawText, user2]. No previous unit's answer,
   partial output or separate reasoning enters its history.
3. Bound expansion and memory BEFORE startup. Suggested initial schema ceilings:
   <=8 configurations, <=10 repetitions, <=32 total conversation executions,
   <=256 total requested turn calls, existing <=1 MiB definition size. Trusted host
   limits may narrow these and existing token/time/output caps, never be enlarged
   by definitions. Worker may propose tighter limits with explicit rationale.
   Validate product bounds without silent truncation, numeric coercion or sampling.
4. Keep stop-on-first-error/cancellation policy in this package. No hidden retry,
   continue-on-failure, parallelism, automatic wait/queue, profile restoration or
   reservation spanning the whole experiment suite. Not-started units/turns remain
   explicit after early stop. Caller may initiate a NEW execution later; this is
   distinct from silently retrying an existing unit.
5. Version definition/result/envelope schema explicitly if their meaning/shape
   changes. Supply an exact example and canonical immutable hash semantics. Preserve
   the accepted single-config/single-repetition BEHAVIOR and regression coverage;
   do not add compatibility layers solely to preserve immature schema internals.
   State whether old versioned input is supported or clearly rejected, update the
   example/README and report intentional migrations. No silent reinterpretation.

Actant execution / exclusive conversation lifecycle
----------------------------------------------------
6. A suite is Application/launcher orchestration, with one caller-retained actual
   ApplicationRuntime.runJob Job per conversation execution. Preserve the actual
   Job outcome for each unit. Do not flatten turns into unrelated Jobs or pretend
   a single turn/Job success certifies the complete suite.
7. Host prepares a trusted immutable catalog and grants ONLY the selected approved
   selectors, deduplicated, to the exact real Application CodeEntry incarnation.
   Alias existence does not mint authority. Keep provider source pinning and
   explicit transition grants; no grants for arbitrary unused catalog selections.
8. For each unit, check cancellation, resolve ctx.llm.profile for its selector,
   explicitly transitionProfile before acquiring its reservation, then obtain
   ctx.llm.reserveConversation(profile). Pass that exact session to every admitted
   ctx.llm.run (and estimation/preview if used). Keep it through all turns/history
   and final per-call cleanup; close in finally on success/failure/cancellation.
   Continue FreshContext(required=False, retain=False) per call. Transcript replay
   is Application policy, not retained KV. No physical retention/freshness promise.
9. Exclusive means unrelated SAME-PROFILE calls are denied too, not only incompatible
   transitions. No inference on activation/lifecycle hooks. Do not implement a
   Python-only runner mutex as resource authority, mutate the driver/catalog or
   call provider stop/ensureModel directly. No nested/reentrant execution trick.
10. IMPORTANT EXISTING API: LlmConversationSession.close queues cleanup-only
    revocation; runtime lifetimeBoundary/finishClose drains it outside runtime
    locks. Therefore finish the conversation Job and its cleanup boundary BEFORE
    transitioning/reserving the next unit. Do not call private finishClose/drain,
    manually clear domain state or assume close synchronously proves release.
    If this composition exposes a genuine public API gap, provide a deterministic
    reproducer and ask Integration for a separately reviewed shared patch.
11. Transition and reservation are separate admissions, not an atomic switch+lock.
    Another owner may win between them. Busy/loading/draining/UNKNOWN/revocation
    remains typed failure and stops this suite without takeover/retry. Release
    exclusion between units, allowing other authorized work then. A compatible
    explicit transition is expected to reuse residency; startup changes require
    transition after the prior reservation and operations have drained. Never
    derive compatibility from equal labels/target filenames alone.
12. On uncertain provider cleanup, record UNKNOWN and stop; closing the conversation
    or a later idle/process-exit observation cannot repair claims. Host teardown
    and reservation close attempts do not certify provider quiescence. Preserve
    cancellation/failure if resource cleanup also fails. No forced disposal or
    host recovery policy. Preserve R1 post-Job interruption-safe teardown and first
    interrupt behavior throughout aggregate/final persistence paths.
