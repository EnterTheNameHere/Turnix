H-01 - FAILED SUBSCRIPTION ACQUISITION
------------------------------------
Source hypothesis: subscribe() inserts into _subscriptions before initial _collect()
and _ensureWorker(). An escaping exception can deprive the caller of a handle while
leaving the new collection claim active.

Reproduce with separate deterministic faults:
- initial collection fails before normal completion;
- worker setup fails, including failure in Thread.start() after a worker reference
  has been published;
- joining a service with existing consumers fails during acquisition.

Test first-consumer and existing-consumer cases as applicable. Inspect partial
setup, owned-provider initialization and retained data, not just the exception.
If reproduced, make acquisition atomic from the caller's perspective or reliably
revoke the failed acquisition, clear its retained monitoring data and release only
resources no longer needed. Do not revoke or reset pre-existing claims/histories,
close their providers, or leave a phantom cadence/polling requirement. Legitimately
collected shared evidence need not be erased merely because a new claim failed.
Preserve the original failure evidence even if rollback encounters a cleanup error.
Normal handled hardware unavailability remains nonfatal and explicit.
Prove that a later valid subscription succeeds after removing the injected fault.

H-02 - UNEXPECTED POLLING-WORKER TERMINATION
-------------------------------------------
Source hypothesis: _samplingLoop() clears _thread only on normal exit. An escaping
collector/scheduler/clock exception can leave a dead worker reference that prevents
_ensureWorker() from starting replacement polling.

Reproduce using deterministic one-shot failures in actual background collection and
clock/deadline handling. Distinguish these from sensor exceptions already converted
to SignalUnavailable. Check the startup fault shared with H-01 too.

If reproduced, restore truthful lifecycle bookkeeping on all relevant exits. A
stale worker must not prevent later legitimate requests from recovering collection
once the injected fault is removed. Document which explicit subscription/sampling
operations request recovery and test their behavior. Preserve at most one shared
collector and ensure a terminating worker cannot clear a newer worker's identity.
Avoid races among failure, new acquisition, revocation and final shutdown.

Do not add an unbounded automatic restart/retry loop or suppress platform failure
evidence. Preserve the existing exception-reporting path or supply explicit bounded
failure visibility, with the choice explained. Never label stale samples as fresh;
monotonic collection intervals and gaps remain honest. End all test workers and
claims deterministically, using events/barriers and bounded joins rather than
sleep-based races. Recovery must not duplicate collectors or invalidate consumers.
