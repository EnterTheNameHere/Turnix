02. AGREED FIRST SCENARIO
-------------------------
A single linear Classic experiment:
- supply priming and implementation instructions from literal UTF-8 strings,
  UTF-8 files, or selected combinations, with explicit message roles;
- inference generates a full source response;
- extract exactly one Python code fence (or fail explicitly) and save source into
  an isolated execution workspace;
- one Ruff safe automatic-fix pass, then one Ruff formatting pass;
- one ty diagnostic check and one Ruff diagnostic check;
- explicitly assemble next user message containing current modified source,
  captured tool diagnostics, and literal correction instructions;
- one final inference with ordinary growing Classic conversation history.
No automatic model-selected CLI/tool calls. Do not infer a repair loop from this
scenario. Model's old responses remain in history even when working file changes.

The first example is ONE pass and ONE correction inference, not five iterations.
The future procedure might support loops, conditions, selected immutable QueryItems,
and MVS integration, but those are NOT EX-06 implementation requirements.

03. SUPPORTED PRIMITIVES FOR A CONCRETE PLAN
--------------------------------------------
- Message: literal content and/or file content read as strict UTF-8.
- Inference: explicit execution step; append assistant response to growing history.
- Save: take identified inference output, optionally use strict Python-fence
  extraction, write a named working artifact, capture original and extracted forms.
- CLI: invoke an approved logical configured process with argv, not a shell
  command string; capture exact request, outcome, exit/stdout/stderr.
- Later message may refer explicitly to CURRENT working artifact content or prior
  CLI result; CLI outputs do not enter history implicitly.
- JSON5 is desired for authored procedure definitions. Keep stricter canonical
  JSON/archive semantics. Proposal must investigate parser dependency and
  bounded/deterministic canonicalization, not assume a library is installed.
- Existing suite configurations and repetitions remain supported.

04. RUN / EVIDENCE SEMANTICS
---------------------------
One reusable experiment source definition and shared frozen input snapshots per
run; one unique run identity per invocation; one isolated workspace per
configuration/repetition. Prefer run-directory containing self-contained EX-04
archive plus per-execution working directories; do not duplicate inputs into all
workspaces unless a CLI operation requires them.
Capture exact original JSON5 definition bytes plus normalized execution meaning,
UTF-8 input file bytes and source relationships once per run, exact model request/
response evidence, original extracted source, automatically transformed source,
CLI results and failure boundaries. Archives remain portable and inspectable
offline without source files, model, CLI tools, or active runtime.
Working files are convenient and may be retained; they are not accepted receipts.
File disappearance or mutation cannot retroactively prove successful external
execution. No automatic re-execution of a possibly executed CLI after crash.
No unsupported physical/power-loss guarantees.
