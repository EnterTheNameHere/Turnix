Offline inspection / comparison
---------------------------------
1. Offline commands need no RuntimeHost, Pack activation, model/config/assets,
   process discovery, network or execution. Remain stdlib-only where the existing
   offline reader is stdlib-only. Input archives are read-only; no repair/truncate/
   appending/resume. Corrupt input produces explicit invalid/not-comparable diagnostics
   and valid-prefix inspection; never a complete successful comparison. Unsupported
   schemas/limits fail clearly with fixed error categories, not raw private paths.
2. Select archives/units/turns and comparison mode explicitly. IDs identify records,
   not equivalent experiments. Match immutable conversation/turn content/history
   policy plus explicit configuration selection/mapping; ambiguous or absent matches
   are explicit, never zip unrelated rows by index or infer identity from labels.
   Comparing different definitions/configurations may be useful, but disclose the
   differing inputs/provenance and exact chosen scope. No accidental cross-suite join.
3. Provide small versioned exact evidence modes for completed answer TEXT, separately
   exposed reasoning TEXT, and exact serialized request BODY bytes; an explicit
   definition/options evidence view may support alignment. Expose Equal/NotEqual/
   NotComparable as a closed Application-scoped result with mode, selections and
   fixed reasons/availability. Missing/pruned/unsupported/invalid fields are not
   NotEqual, zero or empty string. Unknown reasoning is not exposed empty reasoning.
   Preserve whitespace/Unicode/exact body bytes; no silent normalization or fallback
   from actual request to reconstructed planned query, or from full to partial answer.
4. A validated committed prefix may support a narrowly selected available field
   comparison, with incomplete source and original Job/turn/resource status explicit.
   Equal selected body/text never means suite success, full-archive equality, safe
   cleanup, server consumption or equivalent effective model behavior. Failed calls
   can still have valid serialized bodies. No full-success label for missing scope.
   Corrupt archives are not silently downgraded to successful prefix comparisons.
5. Report per-config/repetition/turn outcomes, planned/attempted/completed/failed/
   cancelled/unstarted counts and unavailable cleanup explicitly. Retain original
   Job/turn/host/archive truth; selected filters never relabel the whole suite.
   Numeric summaries state units, contributing count, excluded count and exclusion
   reasons. No average of missing values as zero, successful-only table presented
   as all attempts, or aggregation across incompatible measurement definitions.
6. Keep wall timestamps, monotonic durations, native engine timings/usage and PM
   delivery/hardware observations separate. Native tokens are not delivered Unicode
   characters. No subtraction across clock epochs/hosts/browser clocks, invented
   interpolation or per-Application CPU/GPU attribution. Hardware is whole-host;
   cadence, gaps/eviction, unavailability and observed-versus-effective distinctions
   remain visible. Side-by-side numbers are descriptive, not causal speedup/quality
   proof or a benchmark standard. No semantic answer-quality oracle.

Bounded reports / exports / presentation
-----------------------------------------
7. Provide coherent documented CLI surfaces for compare/report/export alongside
   accepted validate/run/inspect/recover. A compact outcome/metric comparison table
   and structured versioned JSON report are required; bounded CSV summary export
   supplies ordinary tabular use. Exact command spelling/file split is implementer-
   owned and fixed at first checkpoint. No new GUI framework or custom browser
   dashboard needed: reuse G-02 for the selected live observation view.
8. Default reports/exports contain selected summary facts/availability, not prompts,
   answers/reasoning/raw request bytes, arbitrary asset/source paths, argv/env or
   private connection descriptors. Explicit private-content selection can include
   selected answers/reasoning and original request bytes with digest/length/media/
   encoding/availability; never label a parsed/reserialized body as original bytes.
   Do not export Authorization/cookies/bearer grants/live handles/Context even with
   private selection. Treat report output as private by default, not an auto-upload.
9. Version new report/export shapes and include immutable source archive identity,
   validated committed boundary/digest or equivalent evidence binding, exact mode/
   selection/content policy and generator/source version. A projected export is not
   a complete original archive, replay bundle, WindowExport or live authority.
   A copied same archive is not an independent repetition; retain source identity.
10. Bound archive count, selected units/turns, cumulative input/read bytes, parsed/
    retained/encoded report size, CSV rows/fields and private body/diff output before
    allocation/format expansion. Reuse EX-04 hard ceilings. Reject over-limit requests
    explicitly; never silently truncate and label a full comparison/export successful.
    Use bounded difference summaries, with explicit unavailable details/selection
    rather than unbounded quadratic textual diff algorithms.
11. Output root/file is explicit host/operator choice; archived paths/labels/refs
    cannot choose destinations or escape roots. New export collisions fail without
    overwrite/retry. Partial writes or failed publication cannot appear as completed
    report; do not add universal durability promises beyond tested behavior. Preserve
    primary exits and separate export/cleanup errors. Reads never modify source files.
    Escape untrusted text in terminal/CSV/any HTML; CSV formula-leading cells need
    a documented safe presentation policy distinct from exact private JSON content.
    No browser script/URL evaluation, shell execution, remote/CDN fetch or auto-open.
