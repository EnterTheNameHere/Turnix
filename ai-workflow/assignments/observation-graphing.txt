SOURCE FEASIBILITY FINDINGS
---------------------------
backend/packs/runtime.py: onLoad returns long-lived CodeEntry state; its context is
invalidated immediately afterward. Registration publishes after successful Pack
activation. Teardown withdraws registrations before onUnload, supplying a fresh
cleanup context; failed activation performs best-effort unload with possible None
state. This supports optional per-ApplicationRun endpoint state and cleanup, but not
retaining the onLoad context or treating application lifecycle hooks as modPack hooks.
ManualActivationPlan selects activation explicitly; no automatic Pack discovery or
activation policy is provided by this graphing direction.

backend/context/codeEntryContext.py and backend/application/applicationRuntime.py:
ordinary ctx.capabilities.call passes a payload to a freshly mediated capability
context in the same application. There is no inspected authenticated cross-application
publication router or origin attribution beyond current application composition.
Do not turn capability payload identity fields into trusted cross-application claims.

backend/observation.py: valid invocation requests sessions under an ApplicationRun
owner. APPLICATION sessions can outlive invocation, but RUN sessions are disposed on
context invalidation. Sessions expose snapshot, release, forExecution and mutable
Python object internals; they are not a read-only publication grant. No public
same-owner export/authorization check, selected-session publication registry or
revocable snapshot-reader interface exists. Owner/session private sets must not be
enumerated by a bridge. Endpoint threads must not call an expired context or invoke
fresh runtime capabilities implicitly as a substitute for independent read authority.

CONCLUSION / ACCEPTED DESIGN CHOICE
-----------------------------------
Pack endpoint lifetime is feasible. Existing contracts support application-pushed
immutable snapshots through same-application capabilities; autonomous live reading
needs a narrow additional publication-authority contract. Do not implement this
new authority merely because the HTTP mechanism can hold a Python reference.

A - EXPLICIT SNAPSHOT PUSH (SMALLEST EXISTING-CONTRACT SLICE)
A valid invocation copies selected ObservationSnapshot evidence and submits it to
a same-application bridge capability. Bridge stores only bounded immutable evidence.
HTTP readers see the last published revision and its original timestamps/age.
No retained session/context, background application callback or new backend grant
is needed. Later refresh requires another explicitly authorized application push;
HTTP polling alone cannot manufacture fresh collection. No scheduler is added.
Withdrawal revokes publication, not the application's original observation.

B - REVOCABLE READ-ONLY PUBLICATION GRANT (USER ACCEPTED, 2026-11-01)
Introduce a minimal facade-mediated export of a selected same-ApplicationRun session
while invocation authority is valid. Return a grant limited to snapshot reading;
no execution, session release, subscription creation, runtime/context or registry
access is delegated. Define export ownership, independent revocation and owner/session
teardown behavior explicitly. Export must not silently extend RUN lifetime; live
publication beyond invocation requires explicitly APPLICATION-owned observation.
Bridge unload/withdrawal relinquishes publication access and releases only claims
it actually owns. It must not dispose a caller-owned source session. Source owner
teardown revokes reading; previously copied immutable evidence follows explicitly
agreed bounded publication retention rather than becoming unbounded stale history.
Use a same-application bridge instance first; no host-wide session enumeration or
cross-application aggregation. Method/type names remain proposed, not existing APIs.

The user explicitly selected B after the feasibility review at
86bb8aec793b69a76f59a1deb996a4d14e287255. A is retained only as the considered
alternative. G-01 may implement B within these bounds:
- Valid invocation exports only a selected same-ApplicationRun session; backend
  mediation checks ownership, not caller-supplied application IDs.
- The read grant retains no invocation context and delegates no execution, source
  session release, subscription creation or registry discovery.
- No RUN lifetime extension. Source session/owner revocation stops future reads;
  publication can be independently withdrawn without disposing the source session
  or affecting another publication grant, inference or unrelated consumer.
- Bridge withdrawal/unload relinquishes only its own access/claims and stops serving
  cached publication evidence. Previously returned immutable snapshots remain in
  caller ownership; no ongoing stale snapshot service or persistence is implied.
- HTTP readers share the explicitly published evidence/grant, not new collectors.
  Initial scope is one bridge activated within the publishing application, with no
  cross-application aggregation or automatic observation of other calls.
Exact API names and synchronization mechanics are implementation choices to record
before coding; report required architectural expansion before proceeding.
G-02 follows accepted G-01 schema/authorization. G-01 worker completion is recorded
above; G-02 is not dispatched.

Primary proposed source: new first-party/observationBridge/ manifest/CodeEntry and

Provide explicit selected publication, revision/withdrawal, versioned JSON and
read-only loopback HTTP polling. Endpoint is inactive without explicit Pack activation;
activation alone never monitors inference. Use one endpoint per activated instance
with collision-safe address selection; no shared networking service is introduced.
Snapshot polling reads already-authorized bounded observations, never another
collector or hidden inference execution. Multiple readers share the same evidence.

Define a transport-independent, allowlisted schema with units, session/publication
identity, revision, monotonic clock-domain/epoch identifier, original collection
start/end, separate display wall time, stream windows/outcomes/unavailability,
explicit gaps and exact/conservative truncation markers. JSON nanosecond timestamps

lossless representation). Reconnection/host restart must not join different clock
epochs. Do not serialize arbitrary result/provider metadata, object internals,
prompts, response text, exceptions/tracebacks or unrelated application state.

Loopback is not authorization: require an explicit per-instance read credential;
avoid credentials in query strings/logs. Validate Host and browser Origin where
applicable; no wildcard credentialed cross-origin access or external bind. Specify
how the independent viewer obtains endpoint and credential without creating an
Actant data-discovery API. Keep the HTTP adapter replaceable and tightly bounded;
no general transport framework, mutation endpoints or remote network exposure.

onUnload and activation failure stop accepting reads, close/join endpoint workers,
withdraw publications and release only Pack-owned grants/claims. Do not rely on
garbage collection or valid application observation authority during teardown.

Architectural tests: actual Pack activation/unload/failure; no context retained;
expired invocation and foreign publication rejection; scoped read/revoke and source
owner teardown; unrelated app/reader/source consumer isolation; inactive/disabled
no monitoring; independent HTTP readers without duplicate collection; bad credentials,
Host/Origin/external bind rejection; withdrawal/shutdown races; bounded retention;
strict no-content schema and lossless timing; missing sensors and truncated/gapped
evidence; no automatic inference attachment. Use ephemeral loopback ports/fake
providers, not actual GPU or inference servers. Include PM regression/full tests.
