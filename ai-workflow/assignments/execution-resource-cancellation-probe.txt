----------------------------------

retain model identity privately. One managed CPU-only process, one domain, one
slot, one actual admitted request, no queued/foreign requests. Context 1024,

An operator must have the retained Popen handle and private evidence folder and

Per-case protocol
-----------------
1. Explicit host-authorized initial transition through trusted composer; retain
   exact Popen object/PID, generation token and configuration evidence. Confirm
   only the chosen slot exists and is idle before inference. Preserve baseline
   previous id_task if present, since an idle slot can retain an old task ID.
2. Open the request through normal admitted application/session authority.
   Read one partial SSE event with stable nonempty chat ID, no finish/DONE.
   While that call is the sole pending task, capture the requested owned slot
   is_processing=true and exact integer id_task, verifying process/generation
   unchanged before/after HTTP observations. The chat ID is NOT id_task.
   If active task binding cannot be captured, do not claim an active abort test.
3. At the operator-observed boundary perform ONLY the selected case below.
   Record request time, callback return time, reader exit and primary outcome
   separately. Never call generator.close concurrently with an executing reader.
4. Poll the same process/slot/task read-only at most every 0.2s for 10 seconds,
   with each HTTP read limited to 1 second. Those are observation guards, not
   promises that a stuck provider will stop. Record exact task release log if
   available and repeated same-task idle snapshots (two consecutive samples).
   Stop on changed process/generation, wrong/missing task ID, malformed replies,
   new task, deadline or process exit. Arbitrary idle is insufficient.
5. Require all local workers/callbacks to finish before any cleanup proposal.
   Report native task stopped, process idle, and claim disposition separately.
   With the unchanged adapter expect UNKNOWN even if native idle is observed.
   Do not clear its tombstone, manually finish the claim, invoke driver.stop
   around admission, or run another case on that domain. Resolve disposition
   under the operator policy before any later independently initialized case.

Case matrix
-----------
A. Baseline header-free active Job cancellation. Use actual Job.requestCancellation
   from the control worker after active binding. Observe whether closing the
   response reaches the exact task's native cancellation/release. Job CANCELLED
   does not mean provider idle; a blocked close is a recorded failure/limit.
B. Header-free early stream close. At a yielded-event boundary stop consumption
   and close the admitted iterator on its owning reader thread. Preserve early-
   exit cleanup failure; do not manufacture native finish or DONE. This is a
   distinct adapter/session test, not proof that every facade exposes streaming.
   The present validation AppPack uses ctx.llm.run; its controlled test extension
   must enter the issued session, never call a raw driver to bypass admission.
C. Actual transport timeout. Use a finite configured HTTP read timeout and record
   its real boundary. A timeout before headers/task binding is a separate
   pre-capture result. If normal token cadence prevents an active read timeout,
   classify inconclusive rather than raise a synthetic TimeoutError and call it
   native evidence. Controlled peer delay belongs to a separate transport test.
   Executed test-only extension: set 0.01s on the exact captured response socket
   AFTER active binding and peer verification, leaving all inference ceilings
   unchanged. The evidence repeat captured actual TimeoutError beneath normalized
   LlmProviderConnectionError. This private socket access is not a production API.
D. Additional candidate: an explicitly reviewed test-only adapter variant sends
   unique private X-Conversation-Id for THIS operation, verifies exact lookup
   membership, sends DELETE /v1/stream?conv_id=<URL-encoded exact ID> with bounded
   independent control IO, then observes the same native task's release. Do not
   use broad lookup matches or reuse keys. DELETE 204 is only request acceptance;
   it also occurs when no session matched. Disconnect alone now deliberately
   drains, so test that behavior distinctly. No production provider edit is
   implied. A successful D does not retroactively pass A/B/C on stock code.

Evidence classifications / follow-up
-------------------------------------
Cancellation requested: signal/close/delete issued, timestamp retained.
Task stopped: pre-bound native task's exact release observed on same live owner;
otherwise unknown (or natural completion raced, if supported by terminal logs).
Process idle: owned slot set reports idle, separately from task stop.
Claim safe to release: only a trusted adapter finalization with supported exact
evidence before UNKNOWN is finalized. Corrected d027870 can confirm bound native
cleanup; unbound transmitted aborts remain UNKNOWN. Never turn later observation
into recovery authority.
Deadline/process exit/missing correlation = blocked/failed graceful case, never
implicit success. Natural EOS/length completion after abort without cancellation
evidence proves eventual completion, not prompt cancellation.
