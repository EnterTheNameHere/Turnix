Archive contract / meaningful durability
-----------------------------------------
5. Each suite gets a new exclusive archive identity/directory under an explicitly
   host-selected private root. Do not overwrite an existing archive/colliding ID.
   Definitions cannot choose arbitrary archive paths. Keep definition hash,
   suite/unit/config/repetition/turn identities and original execution ordering.
6. Specify a small local commit format: e.g. versioned manifest plus append-only
   bounded records or immutable sequenced checkpoints and referenced artifacts.
   The implementation is worker-proposed; no database/distributed log required.
   Separate committed checkpoints from temporary/incomplete writes. Flush/sync
   acknowledged data and document tested filesystem/process-crash guarantees.
   Atomic rename alone is not a power-loss guarantee. Do not promise universal
   filesystem/power-loss durability or introduce platform-wide persistence APIs.
7. A checkpoint ACK means a fresh process can read the committed bytes and all
   referenced artifacts under the declared process-crash model. Publish artifacts
   before the record referencing them; no valid commit may reference an unwritten
   body. Detect missing/corrupt content with bounded lengths and content digests.
   Define exactly how a torn final record/temp file is ignored/reported while
   preserving valid earlier commits; interior corruption or missing referenced
   data is explicit, never silently a complete successful archive.
8. Persist validated definition/planned suite and host-selected initial provenance
   BEFORE first model transition/admission. Commit each completed turn and unit
   boundary before allowing the next turn/unit. Persist final suite and separate
   signal/host/resource cleanup disposition as subsequent evidence, not by
   rewriting previously observed original Job/turn outcomes.
9. Support bounded partial stream checkpoints with an explicit host-selected
   event/character/time policy. State maximum uncheckpointed window and distinguish
   partial from complete output. No full suite rewrite on every token. Partial
   answers/reasoning must never enter later history or be mistaken for completion.
   Observed-before-crash data not yet acknowledged may be lost; label that limit.
10. Persist outside the conversation Job's rollback scope, as explicit Application
    diagnostics/history. A failed Job must not roll back earlier archive commits.
    Never retain invocation Context/transaction/IO facade to evade its lifetime.
    A small App-owned host archive writer/checkpoint interface is allowed; name
    its actual owner, lifetime and failure channel in the plan.
11. Bound total archive bytes, record counts, artifact sizes, pending buffers and
    inspection reads using trusted host caps. Propose explicit finite defaults
    and enforce deterministic expansion limits prelaunch where possible. Reference
    immutable artifacts rather than duplicating every full suite/history snapshot.
    Runtime size/disk limits fail truthfully; do not truncate successful evidence,
    delete earlier committed data to make a run pass or grow queues without bound.
    Logical archive limits are not process RSS or available-disk guarantees.

Failure / interruption / read-only recovery
---------------------------------------------
12. Initial archive creation/commit failure prevents model launch. A later mandatory
    checkpoint failure stops further inference/admission, preserves prior commits
    and original outcomes, and drives nonzero terminal projection. If it happens
    mid-call, use the exact active Job's cooperative cancellation where needed;
    record archive failure separately from resulting Job cancellation/provider
    cleanup. No retry, takeover, forced model disposal or UNKNOWN repair.
13. Existing streamObserver exceptions are swallowed into observerErrors by the
    pipeline. A required archive sink MUST NOT rely on raising from that callback
    as its fatal failure signal. Specify a dependable explicit failure channel;
    do not change the generic best-effort observer contract for this Application.
    Also prevent raw archive exceptions/paths/payloads leaking through observer
    error tracing; fixed categories retain failure stage without private content.
14. Preserve EX-03-R1/R2: leaf signal handler/off-stack relay, exact active Job,
    no next-unit admission, primary exit captured before teardown, independent
    signalCleanupFailures, normal owned host cleanup attempts. Archive flush/close
    failures are separate secondary evidence and must not swallow that first exit.
    No fake receipt when archive finalization or provider cleanup is unconfirmed.
15. Fresh-process inspection/recovery is READ ONLY. It reports committed sequence,
    last observed per-turn/unit/Job outcomes, partial data and incomplete/interrupted/
    corrupt state with unavailable fields. Missing terminal record cannot become
    successful suite completion because the last recorded turn succeeded.
    No model launch, backend attach, process probing, automatic request replay,
    handle reconstruction, resource release/repair or active Job-state mutation.
16. Reader validates schema/version, sizes, hashes, ordering and artifact references.
    Keep reads within the selected archive: reject absolute/path-escaping references.
    Never execute archived code or interpret stored grants/IDs as authority.
    Existing historical final JSON files remain inspectable as their actual schema;
    do not relabel them as durable EX-04 archives. Version new shapes explicitly.
    No broad compatibility framework or archive migration engine required.
