===============================================================================
01. ACTANT AT A GLANCE
===============================================================================

01.01. Actant is a local-first, persistence-first, modular platform for
       running and coordinating multiple Applications.
01.02. AI is a primary motivation, but Actant is not limited to AI.
       Intended uses include assistants, AI buddies, model orchestration,
       completion, analysis, tests, games, and simulations.
01.03. Orchestration extends beyond turn-based chat and reconstructing
       state from conversational history alone.
01.04. A shared Host supports concurrent Applications with distinct
       lifecycles and shared managed facilities.


===============================================================================
02. DESIGN PRINCIPLES
===============================================================================

02.01. Platform truth is defined by contracts, authority, and guarantees,
       not one language, process layout, model, or implementation stack.
02.02. Persistence is foundational: promised state and obligations must
       remain recoverable across interruptions and failures.
02.03. Known outcomes, uncertainty, trace evidence, and authoritative
       committed values must remain distinguishable.
02.04. Domain code owns intentions and meaning; Flow orchestrates
       communication and contractual progression.
02.05. A reported Flow error does not end Actant's responsibility for
       unresolved recovery, reconciliation, or cleanup.
02.06. 'Trace or it did not happen' is an evidentiary principle:
       missing trace evidence cannot prove an event occurred.
       Trace evidence is not automatically committed state.
02.07. Architectural Tests protect correctness before optimization.
02.08. Actant protects platform integrity while respecting creators'
       freedom to experiment and choose implementation approaches.


===============================================================================
03. RUNTIME CONCEPTS
===============================================================================

03.01. The Host manages Application runtimes and shared services.
03.02. An Application has its own purpose, identity, and lifecycle.
03.03. Packs are deployable units for Applications, code, content, and
       tests. CodeEntries identify executable units within Packs.
03.04. Adapters execute CodeEntries through appropriate runtimes.
       Python is the current focus; JavaScript/TypeScript browser sandbox
       and C# are intended future directions, not completed features.
03.05. Flow coordinates Invocations, Subscriptions, Emits, relationships,
       and replaceable Transports while respecting domain authority.
03.06. MemoryValueSystem manages semantic values, revisions, transactions,
       authoritative commitment, retention, and recovery.
03.07. Tracing records structured runtime evidence for later inspection
       without inventing events not established by the evidence.


===============================================================================
04. DOCUMENTATION USE
===============================================================================

04.01. This index provides a self-contained orientation and retrieval
       guide, not the detailed requirements of every component.
04.02. design/ contains platform design. Refer to other documents for
       concepts not yet defined by a specific design/ document.
04.03. Read the design owner for the task and relevant dependencies.
       Do not interpret illustrative mechanisms as mandatory choices.
04.04. Working checkpoints preserve design discussions but are not
       automatically canonical specifications.
04.05. Distinguish intended features, implemented code, and verified
       integrated behavior. Report genuine design conflicts explicitly.
