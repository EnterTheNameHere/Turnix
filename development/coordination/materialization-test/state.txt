REAL BENCHMARK DATA
The benchmark is the EventJournal Python 3.15 materialization task.

prompts.json contains groundingReference, groundingResponseInstruction,
initialMaterialization, staticAnalysisReport, searchForBugsAndFix, and
questionnaireInstructions. The 117 questionnaire requirements exist only as
explicit semantic data files questionnaire/01.json through questionnaire/13.json.
Workflow codeEntry.py loads those fixed files through questionnaireDirectory and
validates section identity, explicit numbering, uniqueness, and total count.

CURRENT ACTANT-NATIVE IMPLEMENTATION
Workflow codeEntry.py version 9 implements initial materialization, Ruff + ty
analysis, bounded repair, self-audit with its own bounded repair budget, and the
117-question independent Native questionnaire. Native projections use only
reusable groundingReference and preserve original requirements in repair/audit.

Every source-producing prompt requires exactly one non-empty fenced Python block
with no surrounding text. Extraction remains deliberately tolerant of ordinary
prose outside one otherwise-valid fence so protocol noncompliance remains raw
scoring evidence. Generated source is never executed/imported as validation.

Analyzer candidates are exact extracted source materialized through ctx.workspace.
Ruff and ty run through host-authorized ctx.process. Nonzero exit is model/code
evidence; ProcessExecutionError is infrastructure evidence. Shared providerTiming
is authoritative for LLM benchmark duration; Materialization adds no competing
timer.

QUESTIONNAIRE / LATEST SOURCE
Questionnaire is attempted after materialization/self-audit failure when the LLM
remains callable. If no valid source exists, Native supplies explicit failure
state. A later extraction failure retains the previous valid source; a newly
extracted source remains latest legitimate source even if analyzer execution then
fails. Only LlmError is classified as questionnaire inference failure.

EXPORT / PUBLICATION
Exporter version 2 is a separate Job after accepted benchmark state is saved.
It emits <outputDirectory>/<applicationId>/<applicationRunId>/evidence.json with
format materialization-test.evidence@1. Evidence contains application identity,
exact prompt/questionnaire source documents, configuration, authoritative workflow
state, and all referenced shared ProcessingRun snapshots. Exact model-facing
queries/responses/provider timing are therefore exported from ProcessingRun truth.

RUN PATH
run.py version 3 normalizes all application-owned filesystem configuration against
the config file directory, including questionnaireDirectory. It also normalizes
host processTools executable paths when configured, while ApplicationRuntime still
requires absolute resolved executable authority. llama.cpp executable/model paths
are normalized as before. run.py saves accepted authoritative state before
propagating Job errors, then runs export as a separate Job.

No Ruff/ty executable paths are guessed or committed. A real benchmark config must
provide host-authorized processTools entries for logical tools "ruff" and "ty".
The checked-in config remains a template with MODEL_PATH.gguf and therefore is not
yet directly runnable as a benchmark without machine-specific configuration.
