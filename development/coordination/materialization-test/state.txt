CURRENT GOAL
Build the second independent Actant application consumer: an unattended local
LLM materialization benchmark. V1 finish line is:

  configure -> run -> materialize -> analyzer/fix -> self-audit/fix
  -> questionnaire -> export sufficient scoring evidence

STRATEGIES
Both strategies use the same test definition and source prompt material.

Classic reproduces the historical LM-Studio-like accumulating conversation as
closely as practical. Its questionnaire is one request containing all questions.

Actant-native reconstructs each inference from authoritative state and relevant
QueryItems. Its questionnaire performs one independent inference per question
against the same requirements and frozen latest legitimate source artifact.

PROMPT / TEST DATA
prompts.json remains deliberately simple:
- grounding: exact string
- initialMaterialization: exact string containing implementation requirements
- staticAnalysisReport: exact string/template
- searchForBugsAndFix: exact string
- questionnaire: ordered non-empty array of exact question strings

Question boundaries are explicit data. The harness does not parse numbering or
newlines to infer questions and does not introduce a prompt DSL.

CURRENT ACTANT-NATIVE IMPLEMENTATION
The application scaffold is under:

  first-party/applications/materializationTest/

The native execution path is materialized through questionnaire:
1. Initial materialization.
2. Ruff + ty analysis of exact extracted source.
3. Repair loop, maximum five source-producing calls total.
4. Self-audit only after analyzer-clean initial materialization.
5. Independent Ruff + ty repair loop, maximum five source-producing calls.
6. Questionnaire regardless of source/materialization outcome when LLM remains
   callable.

Each ProcessingRun preserves the exact model-facing query and raw response in
shared LLM pipeline evidence. Workflow state additionally records source
attempts, extraction outcomes, exact source text and SHA-256/UTF-8 identity,
generic process snapshots, phase outcomes, questionnaire questions/answers, and
ProcessingRun IDs.

SOURCE RESPONSE PROTOCOL
Every source-producing inference must return the complete file in exactly one
fenced Python code block using ```python. Prose/reasoning may occur outside it.
The completed response is parsed only after streaming finishes.

Rejected immediately as model-output failure:
- zero fenced blocks;
- more than one fenced block;
- wrong or absent language info string;
- malformed/unclosed fence;
- empty/whitespace-only source.

There is no heuristic block selection, prose extraction, fence repair, dedent,
newline normalization, or formatting retry. Exact extracted body is the source
artifact supplied to both analyzers. Generated Python is not executed/imported
as validation in v1.

ANALYZER SEMANTICS
The application uses invocation-private ctx.workspace to materialize exact
source immediately for process visibility, then ctx.process.run() for configured
Ruff and ty logical tools. Both analyzers receive the same ephemeral path.

The workspace artifact is scratch, not authoritative/persistent evidence. The
exact source and identity are retained in application state. Process result
snapshots are JSON-compatible generic evidence. Nonzero exit is ordinary
analyzer/model evidence; ProcessExecutionError is infrastructure/application
failure evidence.

Native repair projection is:
- grounding;
- current source exactly once;
- current Ruff/ty diagnostics + correction instruction;
- fixed source-output protocol.

The static-analysis report does not embed another copy of current source.

SELF-AUDIT SEMANTICS
Self-audit starts only after initial materialization reaches analyzer-clean.
Its first call sees grounding + clean current source + historical bug-search/fix
instruction + source protocol. Repairs see only grounding + latest source +
latest diagnostics/correction + source protocol. It has its own five-call limit.
The latest legitimate source remains available even if a later self-audit call
fails extraction or analyzer execution.

QUESTIONNAIRE SEMANTICS
Questionnaire is not suppressed by materialization or self-audit model-output
failure. Native questionnaire performs one independent inference per question.
Every question sees:
- grounding;
- the original initialMaterialization requirements;
- the same frozen latest legitimate source, when one exists;
- exactly one questionnaire question.

If no valid source was ever extracted, the source is replaced by explicit
failure-state text; the harness never invents an empty/fake source artifact.
Raw answers are scoring evidence and are not trusted as harness truth.

Only LLM-domain LlmError failures are converted into questionnaire
inference-failed/partially-completed outcomes. Arbitrary programming/runtime
exceptions are not swallowed as model failures; they propagate as application
failures.

Questionnaire outcomes:
- completed
- partially-completed
- inference-failed

SHARED PROCESS / WORKSPACE CONTRACTS
Shared process and ephemeral-workspace facilities are synchronized from
actant-integration. Production CodeEntryContext exposes:

  ctx.process.run(...)
  ctx.workspace.materializeText(...)
  ctx.workspace.materializeBytes(...)

Process executable authority belongs to host/runtime processTools configuration.
V1 configured executables are absolute paths. The Pack supplies logical tool
name and arguments, not arbitrary executable/environment authority.
