CONTRACT NOW AVAILABLE
Actant owns configured completed-process execution. Runtime configuration binds
logical tool names to executable authority; CodeEntry code does not supply an
executable or shell command.

Production ApplicationRuntime contexts expose:

  ctx.process.run(
      toolName,
      arguments,
      workingDirectory=...,
      timeoutSeconds=...,
  )

The return value is a JSON-compatible evidence object containing generic
execution facts including toolName, configuredExecutable, resolvedExecutable,
arguments, workingDirectory, timing, exitCode, stdout, and stderr.

A nonzero child exit code is a normally completed result. Process resolution,
launch/OS execution, communication, and timeout failures are Actant
ProcessExecutionError failures rather than analyzer findings.

Direct low-level CodeEntryContext construction without an explicitly supplied
process facade receives a deny-all empty process registry. Omission therefore
does not grant ambient subprocess authority.

V1 CONFIGURATION
The materialized v1 intentionally narrows executable configuration to an
absolute executable path. This fits the materialization requirement to point at
the exact Ruff/ty executables used by the user's Windows/VS Code environment and
avoids PATH-dependent authority/evidence in the first implementation.

Do not rely on the earlier provisional statement that a bare executable name may
resolve through host PATH. If a later consumer genuinely needs PATH lookup, add
that as explicit shared integration pressure rather than doing it inside the
Pack.

V1 process execution inherits the Actant host environment. CodeEntry cannot
supply arbitrary environment replacement/overrides.

TRANSACTION SEMANTICS
Running the external tool is irreversible. The process evidence becomes
Application authority only when the calling workflow stores and accepts it
through normal Actant transaction/orchestration boundaries. Aborting state later
cannot un-run Ruff or ty.

MATERIALIZATION OWNERSHIP
The Materialization Test remains responsible for:
- exact generated artifact/revision identity;
- argv templates and analyzer phase meaning;
- interpretation of Ruff/ty output and exit status;
- deciding whether findings trigger a repair;
- call limits and scoring semantics.

Actant remains responsible for generic tool authority and execution evidence.
