Status

The shared process/tool requirement has begun materialization on

Implemented shared substrate
-----------------------------
backend/process now contains the first production-shaped configured-tool
execution substrate:
- ProcessToolDefinition binds a logical host-authorized tool name to an absolute
  executable and optional environment overrides;
- ProcessToolRegistry owns the available logical tool bindings;
- ProcessRunner executes a configured tool with caller-supplied argv, cwd, and
  optional timeout;
- ProcessResult captures generic completed execution evidence;
- ProcessExecutionError distinguishes Actant infrastructure/execution failure
  from an ordinary nonzero tool exit.

Focused tests cover nonzero completed exits, stdout/stderr, configured
environment, unknown tools, missing executables, timeout, absolute executable
configuration, duplicate logical names, and JSON-compatible evidence.

Not usable from CodeEntry yet
-----------------------------
Do not consume this from the materialization Pack yet. The invocation-facing
ctx.process facade and ApplicationRuntime/RuntimeHost configuration propagation
are deliberately not committed until they can be added surgically without
rewriting unrelated exercised runtime behavior.

The intended CodeEntry surface remains:

    ctx.process.run(
        "ruff",
        ["check", generatedPath],
        workingDirectory=workspace,
    )

and likewise for ty. The CodeEntry will not pass an executable path.
