===============================================================================
IMPLEMENTATION SPECIFICATION IS-11 - RESOLVED PACK GRAPH AND ACTIVATION PLAN SCHEMA
===============================================================================

Status:
-------
EVOLVING

Description:
------------
Defines concrete selected graph and activation-plan record shapes used to hand
PackManager graph-preparation results to activation and runtime workflows.

The records include selected Pack entries, dependency edges, provider-role
choices, advisory evidence, accepted overrides, SaveBundle graph evidence,
source references, ordering groups, readiness evidence, failure categories,
and trace correlation fields.

Purpose:
--------
This document defines the concrete records that say what Turnix intends to use
when a Pack graph has been selected and, when needed, how that selected graph
is prepared for activation.

It defines:
- ResolvedPackGraph record shape
- ActivationPlan record shape
- graph identity, purpose, status, and context fields
- selected Pack entry fields
- dependency, provider-role, advisory, and override fields
- SaveBundle graph reference fields
- source, validation, readiness, ordering, blocker, and trace fields
- graph and activation-plan failure categories

It does NOT define:
- root discovery boundaries or filesystem scanning rules (see DA-09)
- Pack identity, hierarchy, visibility, or selected-Pack eligibility
  semantics (see DA-10)
- generic PackRequest resolution mechanics (see DA-11)
- importing or module-loading behavior (see DA-12)
- dependency, provider-role, pinned, copied, or advisory-relation semantics
  (see DA-13)
- activation lifecycle, activation callback invocation, or ModCallContext
  authority (see DA-14)
- service, capability, permission, or Job-backed capability semantics
  (see DA-16)
- user decision or remembered policy semantics (see DA-17)
- Job lifecycle, timeout, cancellation, progress, or result semantics
  (see DA-19)
- Application lifecycle, ApplicationRun lifecycle, or SaveBundle binding
  behavior (see DA-20)
- RPC, channel, or transport semantics (see DA-21)
- UI, View, or frontend runtime semantics (see DA-22)
- execution adapter authority or adapter lifecycle semantics (see DA-23 and
  DA-27)
- RuntimeHost lifecycle, Workspace ownership, startup mode, or command-surface
  semantics (see DA-28)
- PackManager semantic boundaries (see DA-29)
- concrete pack listing operation envelopes (see IS-09)
- Default Launcher behavior or ToolStateContext semantics (see IS-10)
- concrete activation executor implementation
- concrete package install/update/remove protocol
- concrete JSON Schema publication format
- concrete SaveBundle storage layout
- concrete export or bundling format

===============================================================================
01. INTERPRETATION BASIS
===============================================================================

01.1. This document expresses normative meaning through explicit,
      deterministic prose.

01.2. Normative meaning in Turnix derives from sentence structure and
      document context rather than from RFC-style keywords.

01.3. The CORE META-RULES documents define the general rule language and
      interpretation model used by this document.

01.4. This document defines implementation-level selected graph and
      activation-plan records within that shared interpretation model.


===============================================================================
02. CORE RECORD BOUNDARIES
===============================================================================

02.1. A ResolvedPackGraph answers:

          "Which concrete Pack entries and graph decisions has Turnix
           accepted for this graph purpose and context?"

02.2. An ActivationPlan answers:

          "In what accepted activation order and readiness grouping should
           the selected graph be handed to activation?"

02.3. ResolvedPackGraph is selected graph intent.

02.4. ActivationPlan is selected graph intent refined for activation ordering
      and readiness.

02.5. An ActivationPlan references exactly one ResolvedPackGraph.

02.6. One ResolvedPackGraph may have zero, one, or multiple ActivationPlan
      records over time when later workflows prepare activation for different
      contexts.

02.7. ResolvedPackGraph is not discovery, generic resolution, importing,
      activation, capability permission, execution authorization, or
      persistence authority.

02.8. ActivationPlan is not activation.

02.9. ActivationPlan does not invoke Pack activation callbacks.

02.10. ActivationPlan does not construct ModCallContext.

02.11. ActivationPlan does not load executable Pack code.

02.12. ActivationPlan does not call adapter execution entry points.

02.13. ActivationPlan does not create retained Pack gateway authority.

02.14. Mechanical loaders, importers, adapter artifact loaders, and activation
       executors consume or reference these records only through their own
       authority boundaries.

02.15. These records are evidence and intent records.

02.16. These records do not grant permission or authority by themselves.

02.17. Persistence of these records remains governed by the owning workflow
       and persistence documents.


===============================================================================
03. RESOLVEDPACKGRAPH RECORD
===============================================================================

03.1. A ResolvedPackGraph contains:
      - schemaVersion
      - graphId
      - graphPurpose
      - graphStatus
      - createdAt
      - createdBy
      - graphContext
      - selectedPacks
      - dependencyEdges
      - providerRoleChoices
      - advisoryEvidence
      - acceptedOverrides
      - saveBundleGraphReferences
      - sourceEvidence
      - validation
      - trace
      - extensions

03.2. schemaVersion identifies the schema version of this record.

03.3. graphId identifies this selected graph record.

03.4. graphPurpose explains why the graph was prepared.

03.5. graphStatus records whether graph preparation completed, completed with
      warnings, failed, or remains partial under an explicit allowed profile.

03.6. createdAt records graph record creation time when persisted or emitted.

03.7. createdBy records the operation, surface, user decision, policy, or tool
      that created the graph when available.

03.8. graphContext records RuntimeHost, Workspace, AppPack, Application,
      ApplicationRun, SaveBundle, and tooling context when applicable.

03.9. selectedPacks records concrete selected Pack entries.

03.10. dependencyEdges records dependency relationships that affected graph
       preparation.

03.11. providerRoleChoices records selected provider-role outcomes.

03.12. advisoryEvidence records supported, conflicting, and recommended Pack
       evidence considered during graph preparation.

03.13. acceptedOverrides records explicit user or policy decisions that affect
       the selected graph.

03.14. saveBundleGraphReferences records SaveBundle-specific copied, pinned,
       last-used, or last-known-good graph evidence.

03.15. sourceEvidence records root, package source, provenance, or content
       evidence when available and permitted.

03.16. validation records graph validation state.

03.17. trace records trace correlation references.

03.18. extensions is reserved for implementation-defined fields that do not
       redefine this schema.


===============================================================================
04. GRAPH PURPOSE, STATUS, AND CONTEXT
===============================================================================

04.1. graphPurpose is one of:
      - RuntimeLaunch
      - NewSaveCreation
      - ExistingSaveLoad
      - SaveCompatibilityCheck
      - SaveRepair
      - SaveExport
      - ToolingInspection
      - TestRun
      - DevelopmentDiagnostics
      - FutureActivation

04.2. RuntimeLaunch means the graph was prepared for launching an AppPack,
      Application, ApplicationRun, or runtime participant.

04.3. NewSaveCreation means the graph was prepared for a new SaveBundle or
      accepted persistence context.

04.4. ExistingSaveLoad means the graph was prepared for loading existing
      SaveBundle state.

04.5. SaveCompatibilityCheck means the graph was prepared to inspect
      SaveBundle compatibility.

04.6. SaveRepair means the graph was prepared to suggest or apply SaveBundle
      graph repair.

04.7. SaveExport means the graph was prepared for SaveBundle export or bundle
      analysis.

04.8. ToolingInspection means the graph was prepared for read-only tooling,
      diagnostics, inspection, or presentation.

04.9. TestRun means the graph was prepared for controlled test behavior.

04.10. DevelopmentDiagnostics means the graph was prepared for development-
       time diagnostics.

04.11. FutureActivation means the graph was prepared for a future activation
       rather than immediate activation.

04.12. graphPurpose does not grant authority.

04.13. graphPurpose does not define activation outcome.

04.14. graphPurpose does not define ApplicationRun lifecycle outcome.

04.15. graphStatus is one of:
       - Prepared
       - PreparedWithWarnings
       - Partial
       - Failed
       - Superseded

04.16. Prepared means graph preparation completed without graph-level
       warnings.

04.17. PreparedWithWarnings means graph preparation completed and warnings are
       present.

04.18. Partial means graph preparation produced partial graph evidence only
       under an explicit operation profile that permits partial output.

04.19. Failed means graph preparation failed and the graph is not accepted for
       activation or runtime use.

04.20. Superseded means a newer graph, newer accepted input, or higher-
       priority graph replaced this graph record.

04.21. graphStatus is not activation outcome.

04.22. graphStatus is not Job terminal outcome.

04.23. graphStatus is not Application lifecycle outcome.

04.24. graphStatus is not ApplicationRun lifecycle outcome.

04.25. graphStatus is not OrchestrationUnit outcome.

04.26. graphContext is a JSON object.

04.27. graphContext may contain:
       - runtimeHostId
       - workspaceId
       - appPackId
       - applicationId
       - applicationRunId
       - saveBundleId
       - viewId
       - requestingPackId
       - requestingSurfaceKind
       - packManagerScope
       - accessMode
       - sourceCatalogId
       - catalogSnapshotId

04.28. runtimeHostId identifies the RuntimeHost context when applicable.

04.29. workspaceId identifies the Workspace context when applicable.

04.30. appPackId identifies the AppPack context when applicable.

04.31. applicationId identifies the durable Application context when
       applicable.

04.32. applicationRunId identifies the live ApplicationRun context when
       applicable.

04.33. saveBundleId identifies the SaveBundle context when applicable.

04.34. viewId identifies the View context when applicable.

04.35. requestingPackId identifies the Pack that requested graph preparation
       when applicable.

04.36. requestingSurfaceKind identifies CLI, Launcher, PackManager View,
       Application View, remote client, AI buddy, test, or another surface.

04.37. packManagerScope uses the scope vocabulary defined by DA-29 and IS-09.

04.38. accessMode uses the accessMode vocabulary defined by IS-09 when
       applicable.

04.39. sourceCatalogId identifies the catalog used when such identity exists.

04.40. catalogSnapshotId identifies the catalog snapshot used when such
       identity exists.

04.41. graphContext does not grant authority by itself.

04.42. graphContext does not create or bind an ApplicationRun by itself.

04.43. graphContext does not load, bind, or mutate a SaveBundle by itself.


===============================================================================
05. SELECTED PACK ENTRY
===============================================================================

05.1. selectedPacks is an array of selected Pack entries.

05.2. Each selected Pack entry contains:
      - graphEntryId
      - packIdentity
      - kind
      - selectionRole
      - selectionSource
      - source
      - visibility
      - dependencyState
      - activationState
      - adapterRequirement
      - warnings
      - diagnostics
      - trace

05.3. graphEntryId identifies the selected Pack entry inside this graph.

05.4. packIdentity serializes author, packTreeId, version, canonicalPackId,
      and fingerprint when available.

05.5. kind serializes the Pack kind.

05.6. selectionRole explains why the Pack appears in the graph.

05.7. selectionRole is one of:
      - RootAppPack
      - RequiredDependency
      - ProviderRoleSelection
      - UserSelected
      - SaveBundleCopiedPack
      - SaveBundlePinnedPack
      - ToolingSelected
      - TestSelected
      - LauncherSelected
      - FutureActivationSelected

05.8. RootAppPack means the Pack is the root AppPack or primary Pack for the
      graph purpose.

05.9. RequiredDependency means the Pack satisfied a hard dependency.

05.10. ProviderRoleSelection means the Pack was selected as provider for a
       required role.

05.11. UserSelected means the user explicitly selected the Pack.

05.12. SaveBundleCopiedPack means the Pack is copied into or retained by a
       SaveBundle context.

05.13. SaveBundlePinnedPack means the Pack is selected because SaveBundle
       metadata pins that concrete identity.

05.14. ToolingSelected means a tooling workflow selected the Pack.

05.15. TestSelected means a test workflow selected the Pack.

05.16. LauncherSelected means a launcher workflow selected the Pack.

05.17. FutureActivationSelected means the Pack was selected for a future
       activation plan.

05.18. selectionSource explains which source model or graph operation selected
       the entry.

05.19. selectionSource is one of:
       - DirectRequest
       - DependencyResolution
       - SaveBound
       - GlobalPinned
       - GlobalNormal
       - ProviderRoleResolution
       - UserDecision
       - PolicyDecision
       - LastKnownGoodFallback
       - ToolingProfile
       - TestProfile

05.20. DirectRequest means the selected Pack was directly requested by the
       graph-preparation operation.

05.21. DependencyResolution means the selected Pack came from DA-13 dependency
       resolution.

05.22. SaveBound means the selected Pack came from save-bound graph evidence,
       copied Pack material, pinned Pack material, or another save-bound source
       recognized by the owning dependency and persistence rules.

05.23. SaveBound does not define DA-13 dependency-source vocabulary by itself.

05.24. GlobalPinned and GlobalNormal correspond to DA-13 dependency-resolution
       source models when applicable.

05.25. SaveBundleOnly, GlobalPinned, and GlobalNormal correspond to DA-13
       dependency-resolution source models when applicable.

05.26. ProviderRoleResolution means the selected Pack was chosen as provider
       for a role.

05.27. UserDecision means an explicit user decision selected or accepted this
       entry.

05.28. PolicyDecision means policy selected or accepted this entry.

05.29. LastKnownGoodFallback means the entry came from last-known-good
       fallback handling after activation failure.

05.30. ToolingProfile means a tooling profile selected this entry.

05.31. TestProfile means a test profile selected this entry.

05.32. source records root, SaveBundle, copied, pinned, package source, or
       other provenance evidence when available and permitted.

05.33. visibility records visibility summary evidence when applicable.

05.34. dependencyState records dependency satisfaction summary for this entry.

05.35. activationState records activation-preparation summary for this entry.

05.36. adapterRequirement records adapter requirement summary when the Pack has
       executable artifacts requiring adapter execution.

05.37. warnings records entry-level warnings.

05.38. diagnostics records entry-level diagnostics.

05.39. trace records trace correlation references.

05.40. selectionRole is explanatory evidence.

05.41. selectionSource does not redefine DA-13 source semantics.

05.42. selectionSource does not grant filesystem access.

05.43. selectionSource does not prove that current Pack material exists.

05.44. A selected Pack entry is not a manifest.

05.45. A selected Pack entry is not executable code.

05.46. A selected Pack entry does not activate the Pack.

05.47. A selected Pack entry is not a SaveBundle.

05.48. A selected Pack entry does not bind SaveBundle state.

05.49. A selected Pack entry does not grant capability authority.


===============================================================================
06. GRAPH RELATION RECORDS
===============================================================================

06.1. dependencyEdges is an array of dependency edge records.

06.2. Each dependency edge contains:
      - edgeId
      - fromGraphEntryId
      - toGraphEntryId
      - packRequest
      - dependencySource
      - dependencyStatus
      - acceptedEntry
      - failureCategory
      - trace

06.3. dependencySource records the dependency-resolution source value supplied
      by the owning dependency semantics when applicable.

06.4. dependencySource does not define DA-13 source vocabulary by itself.

06.5. dependencyStatus is one of:
      - Satisfied
      - Unsatisfied
      - Ambiguous
      - Overridden
      - NotEvaluated

06.6. dependencyEdges record evidence.

06.7. dependencyEdges do not perform resolution by themselves.

06.8. dependencyEdges do not activate Packs.

06.9. providerRoleChoices is an array of provider-role choice records.

06.10. Each provider-role choice contains:
      - providerChoiceId
      - requiredByGraphEntryId
      - roleName
      - selectedProviderGraphEntryId
      - providerStatus
      - selectionSource
      - failureCategory
      - trace

06.11. providerStatus is one of:
       - Selected
       - Missing
       - Ambiguous
       - Overridden
       - NotEvaluated

06.12. Provider-role semantics remain owned by DA-13.

06.13. Provider-role choice records do not create capability permission.

06.14. advisoryEvidence is an array of advisory evidence records.

06.15. Each advisory evidence record contains:
       - advisoryEvidenceId
       - sourceGraphEntryId
       - targetGraphEntryId
       - advisoryKind
       - packSpecifier
       - advisoryStatus
       - severity
       - message
       - acceptedOverrideId
       - trace

06.16. advisoryKind is one of:
       - Supported
       - Conflicting
       - Recommended

06.17. advisoryStatus is one of:
       - Applies
       - DoesNotApply
       - TargetMissing
       - Overridden
       - NotEvaluated

06.18. Advisory evidence does not create hard dependency semantics.

06.19. Advisory evidence does not create activation failure by itself.

06.20. Advisory evidence does not grant capability permission.

06.21. acceptedOverrides is an array of accepted override records.

06.22. Each accepted override contains:
       - overrideId
       - overrideKind
       - decisionId
       - decisionScope
       - acceptedBy
       - acceptedAt
       - affectedGraphEntryIds
       - affectedEdgeIds
       - affectedAdvisoryEvidenceIds
       - reasonCategory
       - message
       - expiresAt
       - trace

06.23. overrideKind is one of:
       - AdvisoryConflictAccepted
       - RiskAccepted
       - AmbiguityResolved
       - HardDependencyResolved
       - SourceTrustAccepted
       - UnsafeOperationAccepted
       - TestOverride

06.24. decisionScope records run, SaveBundle, global, graph, test, or another
       defined scope when available.

06.25. An accepted override does not make a risky graph safe.

06.26. An accepted override does not grant capability permission unless DA-16
       and DA-17 explicitly define that effect.

06.27. An accepted override does not grant adapter execution authorization.

06.28. HardDependencyResolved is used only when the governing dependency and
       policy rules allow explicit resolution of that hard failure.

06.29. An accepted override does not mutate SaveBundle state by itself.

07. SAVEBUNDLE, SOURCE, AND VALIDATION EVIDENCE
===============================================================================

07.1. saveBundleGraphReferences is a JSON object.

07.2. saveBundleGraphReferences may contain:
      - saveBundleId
      - lastUsedGraphId
      - lastKnownGoodGraphId
      - copiedPackReferences
      - pinnedPackReferences
      - saveBundleLocalGraphId
      - compatibilityCheckId
      - repairSuggestionIds

07.3. saveBundleId identifies the SaveBundle context when applicable.

07.4. copiedPackReferences records copied Pack references when available.

07.5. pinnedPackReferences records pinned Pack references when available.

07.6. saveBundleLocalGraphId references SaveBundle-local graph evidence when
      available.

07.7. compatibilityCheckId references SaveBundle compatibility check evidence
      when available.

07.8. repairSuggestionIds references SaveBundle graph repair suggestions when
      available.

07.9. SaveBundle graph references do not load or bind a SaveBundle.

07.10. SaveBundle graph references do not mutate SaveBundle state by
       themselves.

07.11. SaveBundle graph references do not make the SaveBundle a Pack.

07.12. SaveBundle graph references do not prove that current Pack material
       exists.

07.13. sourceEvidence is an array of source evidence records.

07.14. Each source evidence record contains:
       - sourceEvidenceId
       - graphEntryId
       - rootId
       - rootClass
       - sourceKind
       - sourcePath
       - packageSourceId
       - sourceTrustClass
       - fingerprint
       - provenanceSummary
       - trace

07.15. sourceKind records installed content, SaveBundle-local content, copied
       content, pinned global content, package index, generated metadata, or
       another defined source kind.

07.16. sourcePath records path evidence only when path exposure is permitted.

07.17. Source evidence does not prove authenticity by itself.

07.18. Source evidence does not grant authority.

07.19. sourcePath does not grant filesystem access.

07.20. sourcePath does not prove current file existence.

07.21. sourcePath does not authorize direct reads.

07.22. validation is a JSON object.

07.23. validation contains:
       - validationStatus
       - validationProfile
       - warnings
       - failures
       - expectedBreakEvidence

07.24. validationStatus is one of:
       - Valid
       - ValidWithWarnings
       - Invalid
       - Partial
       - NotEvaluated

07.25. Valid means the graph record satisfies the validation profile that was
       applied.

07.26. Valid does not mean the Packs will activate successfully.

07.27. ValidWithWarnings means warnings exist and the graph remains accepted
       under the applied validation profile.

07.28. Invalid means the graph is not accepted under the applied validation
       profile.

07.29. Partial means only partial validation evidence exists under an explicit
       profile allowing partial output.

07.30. NotEvaluated means validation was not performed.

07.31. validationStatus does not grant adapter authorization.

07.32. validationStatus does not grant capability permission.

07.33. validationStatus does not prove ApplicationRun readiness.

08. ACTIVATIONPLAN RECORD
===============================================================================

08.1. An ActivationPlan contains:
      - schemaVersion
      - activationPlanId
      - graphId
      - activationPlanStatus
      - createdAt
      - createdBy
      - activationContext
      - activationEntries
      - activationOrder
      - readiness
      - warnings
      - diagnostics
      - trace
      - extensions

08.2. schemaVersion identifies the schema version.

08.3. activationPlanId identifies the activation plan.

08.4. graphId references the ResolvedPackGraph from which the plan was
      prepared.

08.5. activationPlanStatus records plan preparation status.

08.6. createdAt records creation time when available.

08.7. createdBy records the operation, surface, policy, or tool that created
      the plan when available.

08.8. activationContext records RuntimeHost, Application, ApplicationRun,
      AppPack or AppDefinition source, SaveBundle, Workspace, and adapter
      context when available.

08.9. activationEntries records Pack activation entries.

08.10. activationOrder records deterministic activation ordering or readiness
       grouping.

08.11. readiness records readiness checks and blockers.

08.12. warnings records activation-plan warnings.

08.13. diagnostics records activation-plan diagnostics.

08.14. trace records trace correlation references.

08.15. extensions is reserved for implementation-defined fields that do not
       redefine this schema.

08.16. activationContext does not construct runtime contexts by itself.

08.17. activationContext does not bind a SaveBundle by itself.

08.18. activationPlanStatus is one of:
       - Prepared
       - PreparedWithWarnings
       - Blocked
       - Partial
       - Failed
       - Superseded

08.19. Prepared means the activation plan was prepared without warnings.

08.20. PreparedWithWarnings means the activation plan was prepared and
       warnings exist.

08.21. Blocked means activation plan preparation reached a known blocker.

08.22. Partial means the plan contains partial activation evidence under an
       explicit operation profile that permits partial output.

08.23. Failed means activation plan preparation failed.

08.24. Superseded means another activation plan replaced this activation plan.

08.25. activationPlanStatus is not activation outcome.

08.26. activationPlanStatus is not Job terminal outcome.

08.27. activationPlanStatus is not ApplicationRun lifecycle outcome.

08.28. activationPlanStatus is not adapter lifecycle outcome.

08.29. activationPlanStatus is not OrchestrationUnit outcome.


===============================================================================
09. ACTIVATION ENTRIES, ORDER, AND READINESS
===============================================================================

09.1. activationEntries is an array of activation entry records.

09.2. Each activation entry contains:
      - activationEntryId
      - graphEntryId
      - packIdentity
      - activationRole
      - adapterRequirement
      - prerequisiteEntryIds
      - blockerIds
      - activationReadinessStatus
      - warnings
      - diagnostics
      - trace

09.3. activationRole is one of:
      - AppRoot
      - Dependency
      - Provider
      - ViewParticipant
      - ToolParticipant
      - SaveBundleLocalParticipant
      - OptionalParticipant
      - TestParticipant

09.4. AppRoot means the AppPack, AppDefinition source, or primary Pack that
      roots the activation plan.

09.5. SaveBundleLocalParticipant means a SaveBundle-local copied or pinned
      participant.

09.6. activationRole is explanatory and ordering-related.

09.7. activationRole does not grant ModCallContext authority, adapter
      authority, capability permission, or execution authorization.

09.8. An activation entry does not activate the Pack.

09.9. An activation entry does not load executable Pack code by itself.

09.10. An activation entry does not invoke Pack activation callbacks.

09.11. An activation entry does not construct ModCallContext.

09.12. An activation entry does not grant adapter authority.

09.13. activationOrder is a JSON object.

09.14. activationOrder contains:
       - orderModel
       - orderedEntryIds
       - groups
       - orderingEvidence

09.15. orderModel is one of:
       - StrictSequence
       - GroupedSequence
       - Deferred

09.16. StrictSequence means orderedEntryIds defines the full deterministic
       activation order recorded by the plan.

09.17. GroupedSequence means groups define deterministic groups and each group
       defines its own internal order or readiness boundary.

09.18. Deferred means activation order is not fully prepared yet and further
       accepted input is required before activation.

09.19. Activation order preparation does not activate Packs.

09.20. Activation order remains constrained by DA-14.

09.21. Activation order does not invoke adapter execution.

09.22. Activation order does not imply OrchestrationUnit execution.

09.23. An activation order group contains:
       - groupId
       - groupKind
       - entryIds
       - groupReadinessStatus
       - orderingEvidence

09.24. groupKind is one of:
       - DependencyGroup
       - ProviderGroup
       - AdapterEntryGroup
       - CyclicDependencyGroup
       - PhaseBarrierGroup
       - ViewGroup
       - ToolGroup
       - DeferredGroup
       - TestGroup

09.25. CyclicDependencyGroup records graph-preparation evidence for entries
       participating in one hard-dependency cycle.

09.26. PhaseBarrierGroup records a readiness barrier consumed by an activation
       workflow.

09.27. Groups do not imply concurrent activation unless a future authoritative
       concurrency mode defines that behavior.

09.28. Groups are ordering and readability structures by default.

09.29. Groups do not grant scheduling authority.

09.30. Groups do not grant adapter lifecycle authority.

09.31. Groups do not grant OrchestrationUnit execution authority.

09.32. A CyclicDependencyGroup does not prove the cycle is logically correct.

09.33. A PhaseBarrierGroup does not run lifecycle phases by itself.

09.34. readiness is a JSON object.

09.35. readiness contains:
       - readinessStatus
       - blockers
       - warnings

09.36. readinessStatus is one of:
       - Ready
       - ReadyWithWarnings
       - Blocked
       - Deferred
       - NotEvaluated

09.37. Ready means the plan is ready for activation under the applied
       readiness profile.

09.38. ReadyWithWarnings means the plan is ready and warnings exist.

09.39. Blocked means one or more blockers prevent activation.

09.40. Deferred means more input is required before activation readiness can be
       decided.

09.41. NotEvaluated means readiness was not evaluated.

09.42. Ready does not guarantee activation success.

09.43. Ready does not guarantee adapter success.

09.44. Ready does not guarantee capability availability.

09.45. Ready does not guarantee ApplicationRun readiness.

09.46. Ready does not grant execution authorization.


===============================================================================
10. BLOCKERS AND FAILURE CATEGORIES
===============================================================================

10.1. A blocker contains:
      - blockerId
      - blockerCategory
      - relatedGraphEntryIds
      - relatedActivationEntryIds
      - relatedDecisionId
      - message
      - trace

10.2. blockerCategory is one of:
      - MissingDependency
      - VersionMismatch
      - VisibilityDenied
      - ProviderRoleMissing
      - ProviderRoleAmbiguous
      - PolicyDecisionRequired
      - PermissionDenied
      - AdapterUnavailable
      - ExecutionAuthorizationDenied
      - SourceUnavailable
      - SaveBundleGraphMismatch
      - UnsupportedActivationCycle
      - Unknown

10.3. Blockers do not perform decision handling by themselves.

10.4. Blockers do not become activation failure unless activation is attempted
      or the owning workflow classifies the plan as failed.

10.5. Blockers do not mutate SaveBundle state.

10.6. UnsupportedActivationCycle records a preparation blocker.

10.7. UnsupportedActivationCycle does not execute cyclic activation handling.

10.8. Graph failure categories include:
      - InvalidGraphRequest
      - CatalogUnavailable
      - PackResolutionFailed
      - DependencyUnsatisfied
      - ProviderRoleUnsatisfied
      - VisibilityDenied
      - PolicyDenied
      - UserDecisionUnavailable
      - SourceUnavailable
      - SaveBundleGraphMismatch
      - MalformedGraphRecord
      - GraphSuperseded
      - InternalGraphError

10.9. Activation-plan failure categories include:
      - InvalidActivationPlanRequest
      - GraphUnavailable
      - GraphInvalid
      - ActivationOrderingFailed
      - ActivationReadinessBlocked
      - AdapterUnavailable
      - ExecutionAuthorizationDenied
      - UnsupportedActivationCycle
      - PolicyDenied
      - MalformedActivationPlanRecord
      - ActivationPlanSuperseded
      - InternalActivationPlanError

10.10. Failure categories classify graph or plan preparation failures.

10.11. Failure categories do not replace DA-11 resolution errors, DA-13
       dependency failures, DA-14 activation failures, DA-16 capability
       failures, or DA-19 Job terminal outcomes.

10.12. Failure categories do not grant permission to retry weaker semantics and
       present the result as if it answered the original request.

11. TRACE, STORAGE, AND IMPLEMENTATION RELATION
===============================================================================

11.1. ResolvedPackGraph and ActivationPlan creation remain trace-visible.

11.2. Graph preparation uses PackManager-domain trace reasons owned by DA-29.

11.3. Activation-plan preparation may use PackManager-domain trace reasons and
      activation-domain ordering evidence where appropriate.

11.4. Serialized trace records use IS-08 when written through the shared trace
      record envelope.

11.5. Graph records include trace references sufficient to link to:
      - catalog listing evidence
      - resolution evidence
      - dependency evidence
      - advisory evidence
      - decision evidence
      - policy evidence
      - SaveBundle graph evidence
      - RuntimeHost operation evidence
      - Application operation evidence when applicable
      - ApplicationRun operation evidence when applicable

11.6. ActivationPlan records include trace references sufficient to link to:
      - ResolvedPackGraph evidence
      - activation ordering evidence
      - adapter readiness or authorization evidence when available
      - blocker evidence
      - decision evidence when applicable

11.7. Graph and activation-plan trace references do not replace the underlying
      trace records.

11.8. Trace references do not define committed-state truth.

11.9. Trace references do not prove completeness beyond retained evidence.

11.10. SaveBundle workflows may store ResolvedPackGraph references or graph
       records as last-used graph evidence.

11.11. SaveBundle workflows may store ResolvedPackGraph references or graph
       records as last-known-good graph evidence.

11.12. This document defines the graph record shape.

11.13. This document does not define the SaveBundle storage layout.

11.14. Last-known-good fallback remains governed by DA-13 and activation
       behavior.

11.15. A stored graph record does not guarantee that the same Pack material is
       currently available.

11.16. A stored graph record does not bypass fresh dependency resolution where
       DA-13 requires fresh resolution.

11.17. A stored graph record may be used as evidence for compatibility checks,
       repair suggestions, fallback handling, export, and inspection.

11.18. A stored graph record does not load or bind a SaveBundle.

11.19. A stored graph record does not mutate SaveBundle state by itself.

11.20. Future implementation specifications may define:
       - concrete JSON Schema for ResolvedPackGraph
       - concrete JSON Schema for ActivationPlan
       - concrete identifier formats
       - concrete graph storage layout
       - concrete graph hashing or fingerprinting rules
       - concrete activation executor input envelope
       - concrete SaveBundle graph storage layout
       - concrete export or bundling representation
       - concrete PackManager command and RPC envelopes

11.21. Future implementation specifications do not redefine graph records as
       activation.

11.22. Future implementation specifications do not redefine activation plans
       as activation.

11.23. Future implementation specifications do not redefine dependency,
       advisory, resolution, activation, capability, persistence, SaveBundle,
       Application, or ApplicationRun semantics.

11.24. If an implementation requires a semantic rule not defined here, this
       document is updated first or alongside that implementation
       specification.

14. LOCKED SUMMARY
===============================================================================

14.1. LOCKED:
      - ResolvedPackGraph records selected graph intent.
      - ActivationPlan records activation ordering and readiness derived from
        one ResolvedPackGraph.
      - ResolvedPackGraph is not discovery, generic resolution, importing,
        activation, capability permission, execution authorization, or
        persistence authority.
      - ActivationPlan is not activation.
      - ActivationPlan does not invoke Pack activation callbacks.
      - ActivationPlan does not construct ModCallContext.
      - ActivationPlan does not load executable Pack code.
      - ActivationPlan does not call adapter execution entry points.
      - An ActivationPlan references exactly one ResolvedPackGraph.
      - ResolvedPackGraph records graph purpose, graph context, selected Packs,
        dependency edges, provider-role choices, advisory evidence, accepted
        overrides, SaveBundle graph references, source evidence, validation,
        and trace references.
      - ActivationPlan records activation entries, activation order, readiness,
        blockers, warnings, diagnostics, and trace references.
      - Selected Pack entries are listing or graph projections, not
        manifests or executable code.
      - Selected Pack entries are not SaveBundles.
      - Dependency edges record evidence and do not perform resolution.
      - Advisory evidence does not create hard dependency semantics or
        activation failure by itself.
      - Accepted overrides do not make risky graphs safe.
      - Accepted overrides do not grant capability permission or adapter
        execution authorization.
      - Valid graph validation does not guarantee activation success.
      - Ready activation plan readiness does not guarantee activation success.
      - SaveBundle graph references do not load, bind, or mutate SaveBundles by
        themselves.
      - Stored graph evidence does not prove that current Pack material exists.
      - Stored graph evidence does not bypass fresh dependency resolution where
        DA-13 requires fresh resolution.
      - Source evidence and sourcePath do not grant filesystem access or direct
        read authority.
      - Activation order groups do not imply concurrent activation.
      - Activation order groups do not grant scheduling, adapter lifecycle, or
        OrchestrationUnit execution authority.
      - Graph and activation-plan records remain trace-visible and use IS-08
        serialization when serialized through the shared trace record envelope.

14.2. OPEN:
      - concrete identifier formats, graph hashing, JSON Schema publication,
        storage layouts, activation executor envelopes, validation/readiness
        vocabularies, ordering evidence, warning/diagnostic vocabularies, and
        export/bundling representation.
