===============================================================================
IMPLEMENTATION SPECIFICATION IS-07 - RUNTIME HOST TRACE SCHEMA
===============================================================================

Status:
-------
EVOLVING

Description:
------------
Defines the concrete RuntimeHost-domain trace field schema used by
RuntimeHost lifecycle, Workspace ownership, command surface, startup mode,
LAN exposure, client connection, and RuntimeHost operation trace evidence.

This document implements RuntimeHost trace-context obligations and provides
shared field naming for RuntimeHost-adjacent implementation specifications.

Purpose:
--------
This document defines the concrete field vocabulary for RuntimeHost-domain
trace evidence so RuntimeHost-adjacent implementation specifications do not
invent incompatible trace payload shapes.

It defines:
- RuntimeHost trace record field vocabulary
- common RuntimeHost trace context fields
- RuntimeHost, TurnixRuntime, and process identity fields
- Workspace ownership trace fields
- command trace fields
- startup-mode trace fields
- entry-surface and client-connection trace fields
- LAN exposure trace fields
- RuntimeHost operation trace fields
- Application, ApplicationRun, and SaveBundle correlation fields
- error, reason, and outcome field conventions
- trace correlation field conventions
- schema extension rules

It does NOT define:
- trace event structure, trace DAG semantics, span mechanics, storage, or
  query behavior (see DA-03)
- RuntimeHost semantics or RuntimeHost trace reason ownership (see DA-28)
- Workspace ownership and host-lock behavior (see IS-03)
- command-surface behavior or command result envelope behavior (see IS-04)
- startup-mode behavior or startup result envelope behavior (see IS-05)
- LAN exposure and client-connection behavior (see IS-06)
- Application or ApplicationRun trace reason ownership
- RPC trace correlation semantics (see DA-21)
- UI-domain trace reason ownership (see DA-22)
- adapter-domain trace reason ownership (see DA-27)
- OrchestrationUnit trace reason ownership (see DA-24)
- concrete JSON serialization format for the full trace store
- concrete trace file layout
- concrete UI display of trace records
- security policy, authentication policy, or redaction rules

===============================================================================
01. INTERPRETATION BASIS
===============================================================================

01.01. This document expresses normative meaning through explicit,
      deterministic prose.

01.02. Normative meaning in Turnix derives from sentence structure and
      document context rather than from RFC-style keywords.

01.03. The CORE META-RULES documents define the general rule language and
      interpretation model used by this document.

01.04. This document defines implementation-level RuntimeHost-domain trace
      field schema within that shared interpretation model.

01.05. This implementation specification does not create new trace substrate
      semantics.

01.06. This implementation specification defines RuntimeHost-domain field
      vocabulary layered onto domain semantics owned by other documents.


===============================================================================
02. CORE CONCEPT
===============================================================================

02.01. RuntimeHost trace schema answers:

          "Which concrete fields identify RuntimeHost-domain trace evidence
           across host lifecycle, Workspace ownership, commands, startup
           modes, clients, LAN exposure, and host-level operations?"

02.02. RuntimeHost trace schema provides field vocabulary.

02.03. RuntimeHost trace schema does not own trace event storage.

02.04. RuntimeHost trace schema does not own trace DAG semantics.

02.05. RuntimeHost trace schema does not own span mechanics.

02.06. RuntimeHost trace schema does not own trace reason meanings.

02.07. DA-03 owns the trace substrate.

02.08. DA-28 owns RuntimeHost-domain trace reason identifiers and their
      semantic meaning.

02.09. IS-07 defines concrete RuntimeHost-domain trace fields used by
      RuntimeHost implementation specifications.

02.10. Field presence depends on event kind, available context, and owning
       workflow.

02.11. Absence of a field does not imply absence of the represented domain
       fact unless the emitting schema or workflow requires that field.


===============================================================================
03. RUNTIMEHOST TRACE FIELD GROUPS
===============================================================================

03.01. RuntimeHost-domain trace fields are grouped by purpose.

03.02. Field groups include:
      - base trace fields
      - RuntimeHost identity fields
      - Workspace fields
      - ownership fields
      - startup-mode fields
      - command fields
      - RuntimeHost operation fields
      - entry-surface fields
      - client-connection fields
      - LAN and exposure fields
      - transport and channel fields
      - cross-domain correlation fields
      - error, reason, and outcome fields
      - trace correlation fields
      - extension fields

03.03. Field grouping is for schema organization and implementation clarity.

03.04. Field grouping does not create separate trace event classes by itself.

03.05. One RuntimeHost-domain trace record may contain fields from multiple
      groups when the event crosses multiple domains.

03.06. Fields from another domain may appear only as correlation fields unless
      the owning domain document permits more detailed inclusion.

03.07. Correlation fields do not transfer authority or ownership from the
      referenced domain into RuntimeHost trace evidence.


===============================================================================
04. BASE TRACE FIELDS
===============================================================================

04.01. A RuntimeHost-domain trace record contains base trace context fields
      supplied by the trace substrate, projected by the RuntimeHost trace
      emission layer, or represented as RuntimeHost-domain attributes.

04.02. RuntimeHost-layer base field vocabulary includes:
      - schemaVersion
      - traceRecordId
      - traceReason
      - timestampUtc
      - traceLevel
      - sourceDomain
      - message
      - details

04.03. schemaVersion identifies the RuntimeHost trace field schema version.

04.04. traceRecordId identifies one trace record when the trace substrate or
      serialization surface exposes record identity through that name.

04.05. traceReason contains the RuntimeHost-domain trace reason identifier or a
      permitted implementation-specific trace reason extension.

04.06. timestampUtc records when the trace evidence was emitted or accepted by
      the trace substrate when that projected name is used.

04.07. traceLevel classifies severity or presentation level when such
      classification is supported.

04.08. sourceDomain is RuntimeHost for RuntimeHost-domain trace records when
      source-domain projection is emitted.

04.09. message contains a human-facing summary when available.

04.10. details contains structured event-specific data when available.

04.11. These names are RuntimeHost trace-schema field names.

04.12. These names do not define canonical DA-03 serialization names.

04.13. When a RuntimeHost-layer field corresponds to a DA-03-owned substrate
       field, IS-07 treats that name as a projection, alias, or attribute
       mapping only.

04.14. Concrete trace substrate fields remain governed by DA-03.

04.15. IS-07 defines only the RuntimeHost-domain field vocabulary layered onto
       the trace substrate.


===============================================================================
05. DA-03 FIELD LAYERING AND SERIALIZATION MAPPING
===============================================================================

05.01. IS-07 consumes the DA-03 trace event model.

05.02. DA-03-owned trace substrate fields retain their DA-03 meaning when used
      by RuntimeHost-domain trace records.

05.03. DA-03-owned trace substrate fields include:
      - eventId
      - timestamp
      - level
      - domain
      - message
      - reason
      - attributes
      - parentEventIds

05.04. IS-07 does not redefine DA-03-owned trace substrate fields.

05.05. IS-07 does not define a competing canonical substrate schema.

05.06. IS-07 defines RuntimeHost-domain field vocabulary layered onto the
      DA-03 trace event model.

05.07. RuntimeHost-domain fields are represented as trace attributes unless a
      trace serialization implementation specification defines a direct
      serialized field mapping.

05.08. Trace serialization implementation specifications may define concrete
      serialized names, aliases, nesting, indexing, and storage layout for
      DA-03 substrate fields and IS-07 RuntimeHost-domain fields.

05.09. Serialization mapping does not change DA-03 trace substrate semantics.

05.10. Serialization mapping does not change DA-28 RuntimeHost-domain trace
       reason meanings.

05.11. Serialization mapping does not change IS-07 RuntimeHost-domain field
       meanings.

05.12. A field alias does not create a second authority source for the same
       trace fact.


===============================================================================
06. RUNTIMEHOST IDENTITY FIELDS
===============================================================================

06.01. RuntimeHost identity fields identify the host-level context.

06.02. RuntimeHost identity fields include:
      - runtimeHostId
      - runtimeId
      - runtimeHostLifecyclePhase
      - runtimeHostActiveSpanId
      - runtimeHostStartRequestId
      - kernelContextId
      - processId
      - processIdentity

06.03. runtimeHostId identifies the RuntimeHost boundary when such identity is
      defined.

06.04. runtimeId identifies the TurnixRuntime execution when such identity is
      exposed to RuntimeHost-domain trace emission.

06.05. runtimeHostLifecyclePhase records the RuntimeHost lifecycle phase when
      the emitting workflow exposes it.

06.06. runtimeHostActiveSpanId identifies the RuntimeHost active-region span
      when applicable.

06.07. runtimeHostStartRequestId identifies the request that caused
      RuntimeHost startup when applicable.

06.08. kernelContextId identifies the active Kernel or KernelContext when such
      identity is defined.

06.09. processId records the operating-system process identifier when
      available.

06.10. processIdentity records implementation-defined process identity context
       when processId alone is insufficient.

06.11. runtimeHostId remains distinct from runtimeId.

06.12. kernelContextId does not make KernelContext a mandatory architecture
       object.

06.13. RuntimeHost identity fields do not grant Kernel authority.


===============================================================================
07. WORKSPACE FIELDS
===============================================================================

07.01. Workspace fields identify the Workspace or runtime scope bound to the
      RuntimeHost.

07.02. Workspace fields include:
      - workspaceId
      - workspacePath
      - workspaceIdentitySource
      - workspaceBindingStatus
      - workspaceBindingErrorCategory

07.03. workspaceId identifies the Workspace when a stable Workspace identity is
      available.

07.04. workspacePath records the path or path summary when safe and available.

07.05. workspaceIdentitySource records how Workspace identity was derived when
      the implementation distinguishes identity sources.

07.06. workspaceBindingStatus records binding status when the trace record is
      about Workspace binding.

07.07. workspaceBindingErrorCategory records a binding-specific error category
      when Workspace binding fails.

07.08. workspacePath is not a substitute for workspaceId when workspaceId is
      defined.

07.09. workspaceId is not runtimeHostId.

07.10. workspaceId is not runtimeId.

07.11. workspacePath is trace evidence only.

07.12. workspacePath does not grant filesystem authority, Workspace
       ownership, persistence authority, or committed-state mutation authority.


===============================================================================
08. OWNERSHIP FIELDS
===============================================================================

08.01. Ownership fields describe Workspace ownership evidence under IS-03.

08.02. Ownership fields include:
      - ownershipMode
      - accessMode
      - ownershipStatus
      - ownerRuntimeId
      - existingOwnerRuntimeId
      - ownerRuntimeHostId
      - existingOwnerRuntimeHostId
      - ownerToken
      - ownerNonce
      - lockState
      - hostMachineId
      - userId
      - coordinatorProcessId
      - coordinatorProcessStartIdentity
      - startedAtUtc
      - heartbeatAtUtc
      - requestedOwnershipMode
      - ownershipResult
      - staleOwnerEvidenceCategory
      - recoveryResult

08.03. ownershipMode records writable ownership mode when writable ownership
      exists.

08.04. accessMode records access behavior such as read-only inspection when no
      writable ownership is created.

08.05. ownershipStatus records the current ownership interpretation for the
      event.

08.06. ownerRuntimeId records the TurnixRuntime execution identity in an
      ownership claim when available.

08.07. existingOwnerRuntimeId records an already-present runtime owner when a
      second owner is rejected or recovery is considered.

08.08. ownerRuntimeHostId records the RuntimeHost boundary identity in an
      ownership claim when that identity is retained separately.

08.09. existingOwnerRuntimeHostId records an already-present RuntimeHost
      boundary identity when that identity is retained separately.

08.10. ownerRuntimeHostId is not a substitute for ownerRuntimeId when both
       identities are defined.

08.11. ownerToken records the unpredictable ownership claim token when
       available.

08.12. ownerNonce records an implementation-defined ownership nonce when that
       value is distinct from ownerToken.

08.13. lockState records the ownership record lock state under IS-03.

08.14. hostMachineId records the owner machine identity when available.

08.15. userId records owner user identity evidence when available.

08.16. coordinatorProcessId records the operating-system process that
       represents the owning runtime execution when available.

08.17. coordinatorProcessStartIdentity records process lifetime identity when
       the implementation distinguishes a concrete process lifetime from PID
       reuse.

08.18. startedAtUtc records when the ownership claim began.

08.19. heartbeatAtUtc records the latest heartbeat time observed or written.

08.20. requestedOwnershipMode records the requested ownership mode.

08.21. ownershipResult records the result of an ownership attempt or ownership
       recovery attempt.

08.22. staleOwnerEvidenceCategory classifies stale owner evidence when
       available.

08.23. recoveryResult records stale-owner recovery outcome when available.

08.24. Read-only inspection uses accessMode rather than ownershipMode.

08.25. Ownership fields distinguish Workspace identity, TurnixRuntime
       execution identity, RuntimeHost boundary identity, process identity,
       machine identity, user identity, and owner token identity.

08.26. Ownership trace fields do not grant Workspace ownership by themselves.

08.27. Ownership trace fields do not grant persistence authority or
       committed-state mutation authority by themselves.

===============================================================================
19. FIELD PRESENCE RULES
===============================================================================

19.01. RuntimeHost-domain trace records include runtimeHostId when the event is
      associated with an existing RuntimeHost identity.

19.02. RuntimeHost-domain trace records may omit runtimeHostId when the event
      occurs before RuntimeHost identity exists.

19.03. RuntimeHost-domain trace records include runtimeId when the event is
      associated with an existing TurnixRuntime execution identity and that
      identity is exposed to trace emission.

19.04. Startup classification records include startupRequestId when a startup
      request identity exists.

19.05. Command records include commandId when command identity exists.

19.06. Workspace ownership records include workspaceId when Workspace identity
      exists.

19.07. Workspace ownership records include ownerRuntimeId when writable
      ownership evidence includes runtime execution identity.

19.08. Workspace ownership records include ownershipMode when writable
      ownership exists.

19.09. Read-only inspection records include accessMode when access mode is
      recorded.

19.10. Client connection records include clientConnectionId when client
       connection identity exists.

19.11. LAN exposure records include bindScope when exposure or bind scope is
       being classified.

19.12. RuntimeHost operation records include runtimeOperationId when operation
       identity exists.

19.13. Application-related records include applicationId when Application
       identity exists and the emitting workflow exposes it.

19.14. ApplicationRun-related records include applicationRunId when
       ApplicationRun identity exists and the emitting workflow exposes it.

19.15. SaveBundle-related records include saveBundleId when SaveBundle
       identity exists and the emitting workflow exposes it.

19.16. Error records include the most specific available errorCategory or
       reason category.

19.17. Records do not invent unknown identities merely to fill optional
       fields.

19.18. Records do not copy stale or inferred identities into fields as if they
       were confirmed.

19.19. Records may include unavailable, unknown, or redacted markers only when
       the concrete trace schema defines those markers.


===============================================================================
20. EVIDENCE-ONLY IDENTITY AND REDACTION LIMITS
===============================================================================

20.01. Identity-looking fields in RuntimeHost trace records are trace evidence.

20.02. Trace evidence does not grant authority by itself.

20.03. userId, authenticatedPrincipalId, frontendClientId,
      remoteEndpointSummary, workspacePath, localBindAddressSummary,
      lanBindAddressSummary, pairingId, commandSourceIdentity, and related
      fields do not let a client or trace emitter forge identity.

20.04. These fields do not grant command authority.

20.05. These fields do not grant capability permission.

20.06. These fields do not grant authenticated principal status.

20.07. These fields do not grant user identity.

20.08. These fields do not grant Application identity.

20.09. These fields do not grant ApplicationRun identity.

20.10. These fields do not grant Workspace ownership.

20.11. These fields do not grant SaveBundle ownership.

20.12. These fields do not grant committed-state mutation authority.

20.13. Paths, endpoint summaries, user identifiers, principal identifiers, bind
       addresses, and pairing identifiers are security-sensitive trace
       material.

20.14. Exact redaction rules remain outside this document unless a later
       security or serialization specification defines them.

20.15. Redaction does not authorize fabrication of replacement evidence.

20.16. When redaction affects interpretation, the trace record preserves that
       limitation when the concrete trace schema supports doing so.


===============================================================================
21. EXTENSION FIELDS
===============================================================================

21.01. RuntimeHost-domain trace records may include extension fields when a
      later implementation specification defines them.

21.02. Extension fields do not redefine fields defined by this document.

21.03. Extension fields do not redefine DA-28 trace reason meanings.

21.04. Extension fields do not redefine DA-03 trace substrate semantics.

21.05. Extension field names are namespaced or otherwise made distinguishable
      from base IS-07 fields.

21.06. Implementation-specific extension fields are not required for portable
      RuntimeHost trace interpretation unless a later specification promotes
      them into this document.

21.07. Extension fields do not create compatibility loopholes around field
      meanings defined by this document.


===============================================================================
22. RELATION TO IMPLEMENTATION SPECIFICATIONS
===============================================================================

22.01. IS-03 uses IS-07 ownership and Workspace fields when emitting Workspace
      ownership trace evidence.

22.02. IS-04 uses IS-07 command and RuntimeHost operation fields when emitting
      command-surface trace evidence.

22.03. IS-05 uses IS-07 startup-mode fields when emitting startup-mode trace
      evidence.

22.04. IS-06 uses IS-07 entry-surface, client-connection, LAN exposure,
      transport, and channel fields when emitting LAN and client trace
      evidence.

22.05. RuntimeHost implementation specifications use IS-07 field names unless
      they define and justify a compatible extension.

22.06. Trace-store implementation specifications may define concrete
      serialization, storage, indexing, and query behavior while preserving
      the field meanings defined here.

22.07. Security and redaction specifications may define how sensitive fields
      are filtered, summarized, omitted, or marked.

22.08. Such filtering does not change the field meanings defined here.


===============================================================================
23. WHAT IS EXPLICITLY NOT SUPPORTED
===============================================================================

23.01. The following are not supported:
      - using IS-07 to redefine DA-03 trace substrate semantics
      - using IS-07 to redefine DA-28 RuntimeHost trace reason meanings
      - using RuntimeHost trace fields as authority grants
      - treating cross-domain correlation fields as ownership transfer
      - treating commandStatus as Job terminal outcome
      - treating startupStatus as commandStatus replacement by default
      - treating runtimeOperationStatus as commandStatus replacement by default
      - treating ownershipMode as read-only inspection mode
      - treating accessMode as writable ownership
      - treating ownerRuntimeHostId as ownerRuntimeId replacement by default
      - treating bindScope as command authority
      - treating clientConnectionId as user identity
      - treating authenticatedPrincipalId as capability permission
      - treating frontendClientId as Application or ApplicationRun identity
      - treating saveBundleId as persistence authority
      - treating activeAppPackId as universal AppDefinition identity
      - treating transport fields as RPC semantic ownership
      - extension fields redefining IS-07 base fields
      - implementation-specific trace extensions replacing domain-owned trace
        evidence
      - trace redaction fabricating evidence that was not observed

25. LOCKED SUMMARY
===============================================================================

25.01. LOCKED:
      - IS-07 defines RuntimeHost-domain trace field vocabulary.
      - IS-07 does not define trace substrate semantics.
      - DA-03 owns trace substrate, trace DAG, and span semantics.
      - DA-28 owns RuntimeHost-domain trace reason identifiers and their
        semantic meaning.
      - RuntimeHost trace records use sourceDomain RuntimeHost when
        source-domain projection is emitted.
      - RuntimeHost-layer field names do not redefine DA-03 canonical
        substrate field meanings.
      - runtimeHostId is distinct from runtimeId, workspaceId, commandId,
        startupRequestId, runtimeOperationId, clientConnectionId,
        applicationId, applicationRunId, saveBundleId, viewId, adapter
        identity, RPC message identity, transactionId, and decisionId.
      - ownerRuntimeHostId is not a substitute for ownerRuntimeId when both
        identities are defined.
      - read-only inspection uses accessMode rather than ownershipMode.
      - commandStatus, startupStatus, and runtimeOperationStatus remain
        distinct.
      - status and outcome fields do not redefine owning-domain outcomes.
      - cross-domain correlation fields do not transfer authority or semantic
        ownership into RuntimeHost trace evidence.
      - cross-domain correlation fields do not replace trace evidence owned by
        the referenced domain.
      - transport and channel fields are correlation fields and do not redefine
        DA-21 semantics.
      - identity-looking, client, principal, endpoint, path, bind address, and
        pairing fields are trace evidence only.
      - extension fields do not redefine IS-07 base fields, DA-28 trace reason
        meanings, DA-03 trace substrate semantics, or portable RuntimeHost
        trace interpretation.
      - IS-03, IS-04, IS-05, and IS-06 use IS-07 field names for RuntimeHost-
        domain trace evidence.

25.02. OPEN:

        vocabulary, owner token/nonce relationship, extension namespace
        convention, JSON schema publication, trace-store serialization, and
        redaction rules.
