==============================================================================
01. VERDICT
==============================================================================

Recommendation verdict:
    Correct in substance, with current-name translation required.

    The recommendation correctly preserves DA-26's central model: DA-26 owns
    comparison, equality modes, ComparisonResult, Replay, Resume, Retry, and audit
    workflow claims over retained finalized Window-derived artifacts. It consumes
    DA-08 Window semantics, DA-25 artifact/export semantics, DA-04 committed-state
    restoration boundaries, DA-05 retained value representation semantics, DA-07
    persistent-I/O authority, DA-19 Job lifecycle semantics, and DA-24
    OrchestrationUnit semantics.

    The recommendation still uses stale AppInstance wording in Retry constraints
    and cross-session wording in audit workflow names. Translate those to current
    Application / ApplicationRun / SaveBundle / cross-run terminology where the
    final DA or DA-26 workflow vocabulary needs it.

Document verdict:
    Keep with small terminology and upstream-boundary fixes.

DA-26 is architecturally strong and should not be heavily rewritten.

The target already preserves the most important workflow semantics:
ComparisonResult is three-valued, equality mode is part of the claim, NotComparable
is distinct from NotEqual, Replay is restoration rather than re-running, Resume
and Retry are new work, and audit workflows do not mutate state.

The main required fixes are:

    - add DA-05 and DA-07 to the upstream list or otherwise make them visible as
      consumed representation / persistent-I/O boundaries
    - normalize Orchestration Unit to OrchestrationUnit where the first-class type
      is meant
    - translate AppInstance in Retry constraints to ApplicationRun / Application
      where appropriate
    - update cross-session audit workflow wording if DA-26 uses current
      cross-run, cross-Application, or cross-SaveBundle vocabulary
    - preserve DA-04 as owner of committed-state truth and restoration boundary
    - preserve DA-05 as owner of payload identity, Chunk, ChunkId, ValueRef,
      decode, integrity, and retained value representation
    - preserve DA-07 as owner of persistent-I/O authority, Reader/Writer providers,
      filesystem rules, storage roots, backup/snapshot behavior, and streaming I/O
    - preserve DA-08 as owner of Window finalization
    - preserve DA-25 as owner of WindowManifest, WindowExport, Minimal Audit
      Bundle, digest representation, partial export, missing material, and offline
      inspection artifact semantics
    - preserve strict Replay / Resume / Retry meanings without letting other docs
      use those terms as casual synonyms
    - avoid final-document version/process metadata leakage

Primary conclusion:
    Keep DA-26 as the offline comparison, equality modes, ComparisonResult,
    Replay, Resume, Retry, and audit workflow semantics document. Apply targeted
    owner-boundary and terminology fixes only.

==============================================================================
01A. OBSOLETE-PRESERVATION CHECK
==============================================================================

DA-26 should not keep older terminology merely because it appears in older source
material or recommendations.

Specifically, the rewrite should not preserve:

    - Orchestration Unit as spaced informal wording where OrchestrationUnit is the
      current first-class type
    - AppInstance as runtime identity vocabulary
    - cross-session audit workflow as the primary current workflow phrase if
      current architecture wants cross-run, cross-Application, or cross-SaveBundle
      wording
    - replay as a synonym for re-running external effects
    - replay as a synonym for deterministic reconstruction of uncommitted
      ActiveWindow activity
    - resume as a live continuation of retained handles
    - retry as the same execution as the earlier attempt
    - boolean equality API for finalized artifacts
    - NotComparable as NotEqual
    - NotComparable as Equal
    - optional digests as identities
    - optional digests as authority
    - digest computation or structural comparison as redefining payload identity
    - digest computation or structural comparison as redefining storage identity
    - audit evidence as committed state
    - audit workflow output as committed-state mutation authority
    - missing material silently becoming Equal, NotEqual, replayable, or resumable
    - trace evidence as committed state
    - trace persistence as guaranteed forever

Canonical translations:

    Orchestration Unit -> OrchestrationUnit when the first-class type is meant
    AppInstance -> ApplicationRun where live runtime incarnation is meant
    AppInstance -> Application where durable Application identity is meant
    cross-session audit workflow -> cross-run, cross-Application, or cross-
        SaveBundle audit workflow if that is the current DA-26 vocabulary

The useful part of the older recommendation is not old naming. The useful part is
this workflow boundary:

    DA-26 owns workflow claims. It does not add authority to workflow inputs,
    redefine retained material representation, redefine persistent-I/O authority,
    redefine Window finalization, or redefine committed-state truth.

==============================================================================
01B. DOCUMENT-METADATA LEAKAGE CHECK
==============================================================================

The final DA-26 document should read as architecture documentation, not as audit,
version, or rewrite-process metadata.

Do not include statements such as:

    - This is V3 design.
    - In V3, Replay is restoration, not re-running.
    - The new design moved artifacts to DA-25.
    - This rewrite added DA-05 and DA-07 boundaries.
    - Unlike V2, Retry is new work.
    - Codex kept AppInstance wording.
    - This audit decided DA-26 should not own persistent I/O.
    - DA-26 was rewritten because of the audit.

Those facts may be useful in audit files, migration notes, compatibility notes,
branch notes, changelogs, or explicitly historical documents. They do not belong
in the architecture document itself.

The final DA-26 should simply define workflow inputs, authority boundaries,
ComparisonResult, equality modes, NotComparable, digest use, Replay, Resume,
Retry, audit workflows, workflow trace visibility, explicit missing-material
handling, unsupported behaviors, open questions, and locked summary.

==============================================================================
02. WHAT DA-26 GETS RIGHT
==============================================================================

02.1. DA-26 owns workflow claims
--------------------------------

DA-26 correctly defines what Turnix tools and workflows may claim when they
compare, replay, resume, retry, or audit retained finalized Window-derived
artifacts.

Preserve this.

02.2. Workflow inputs do not add authority
------------------------------------------

DA-26 correctly says workflow input does not add authority to the material
consumed, evidence artifacts remain evidence artifacts, export packaging remains
packaging, and workflows do not infer authority from filename, archive format,
digest presence, presentation, or transport origin.

Preserve this strongly.

02.3. ComparisonResult is three-valued
--------------------------------------

DA-26 correctly defines ComparisonResult as exactly:

    - Equal
    - NotEqual
    - NotComparable

It correctly forbids boolean, integer, float, or open-ended string-set equality
results and does not provide a convenience boolean equality API.

Preserve this strongly.

02.4. Equality mode is part of the claim
----------------------------------------

DA-26 correctly says a comparison result without equality mode is incomplete,
that equality mode is part of the semantic claim, and that default mode is
StateEquality unless another mode is explicitly requested.

Preserve this.

02.5. NotComparable is not NotEqual
-----------------------------------

DA-26 correctly says NotComparable is returned when required retained material is
missing, unavailable, unsupported, or unusable, and that tools do not treat
NotComparable as NotEqual or Equal.

Preserve this strongly.

02.6. Optional digest use is narrow
-----------------------------------

DA-26 correctly says DA-25 defines optional digest representation and DA-26 owns
how comparison workflows may use optional digests.

It correctly says digest fields are accelerators, not identities and not authority.

Preserve this.

02.7. Replay is restoration, not re-running
-------------------------------------------

DA-26 correctly says Replay is deterministic reconstruction of retained
SafePointWindow committed state together with retained causal story where
available.

It correctly says Replay does not imply re-running external effects,
reconstructing uncommitted ActiveWindow activity, resuming retained Job execution,
resuming retained OrchestrationUnit execution, restarting retained adapter
execution, or reconnecting retained RPC channels, transports, Views, or frontend
participants.

Preserve this strongly.

02.8. Resume is new work after restoration
------------------------------------------

DA-26 correctly says Resume is an attempt to continue execution after restoring a
retained SafePointWindow, is explicit, is trace-visible, is not deterministic in
outcome, does not reuse closed lifecycle identities, and begins new work from a
restored committed boundary.

Preserve this.

02.9. Retry is new work
-----------------------

DA-26 correctly says Retry is new orchestration attempt, trace-visible, not
implied by Replay, not implied by Resume unless Resume policy explicitly selects
Retry, and does not reuse previous jobId or previous orchestrationUnitId.

Preserve this strongly.

02.10. Replay / Resume / Retry remain distinct
----------------------------------------------

DA-26 correctly says Replay is not Resume, Resume is not Retry unless policy
explicitly chooses Retry as part of Resume, and Retry is not Replay.

Preserve this.

02.11. Audit workflows do not mutate state
------------------------------------------

DA-26 correctly says audit workflows do not mutate state, do not require journal
completeness, do not assume replayability, remain honest about retained gaps, and
do not control original runtime participants.

Preserve this strongly.

02.12. Missing material remains explicit
----------------------------------------

DA-26 correctly says missing material is explicit in comparison, Replay, Resume,
Retry, and audit workflow output when it affects the selected workflow.

It correctly says missing material does not silently become Equal, NotEqual,
replayable, or resumable.

Preserve this.

==============================================================================
03. REQUIRED FIX: ADD DA-05 AND DA-07 UPSTREAM VISIBILITY
==============================================================================

The target body already says DA-26 workflows consume DA-05 payload identity and
DA-07 persistent-I/O boundaries.

However, DA-05 and DA-07 are missing from the upstream document list.

Recommended fix:

    Add DA-05 and DA-07 to Upstream Documents.

Preserve or add this stop-line:

    DA-26 may define comparison, Replay, Resume, Retry, and audit workflow claims
    over retained committed material, exported closures, retained evidence,
    optional digests, and missing material.

    DA-26 does not define payload identity, Chunk, ChunkId, ValueRef, decode,
    integrity, or retained value representation contracts.

    DA-05 owns those meanings.

    DA-26 does not define persistent-I/O authority, Reader/Writer providers,
    root boundaries, filesystem rules, storage safety, backup/snapshot behavior,
    streaming I/O, import/export storage, or concrete file access behavior.

    DA-07 owns those meanings.

This prevents workflows from becoming hidden representation or storage authority.

==============================================================================
04. REQUIRED FIX: ORCHESTRATIONUNIT TERMINOLOGY
==============================================================================

DA-26 still uses spaced `Orchestration Unit` wording in several places.

Normalize to:

    OrchestrationUnit

where the first-class current architecture type is meant.

Preserve these semantics:

    - retained OrchestrationUnit lifecycle evidence may be compared when included
      by selected evidence closure
    - equality of retained OrchestrationUnit evidence does not imply resumed or
      replayable OrchestrationUnit execution
    - Replay does not resume retained OrchestrationUnit execution
    - Resume does not reuse closed OrchestrationUnit lifecycle identity
    - Retry does not reuse previous orchestrationUnitId
    - audit workflows may correlate retained OrchestrationUnit evidence with
      retained trace evidence
    - audit workflows do not control original OrchestrationUnits

DA-24 owns OrchestrationUnit lifecycle and mutation-authority semantics.

DA-26 owns workflow claims involving retained OrchestrationUnit evidence, not the
OrchestrationUnit lifecycle model.

==============================================================================
05. REQUIRED FIX: APPLICATION / APPLICATIONRUN TERMINOLOGY
==============================================================================

DA-26 still uses AppInstance in Retry constraints.

Replace:

    AppInstance

with:

    ApplicationRun

where live runtime incarnation constraints are meant, or with:

    Application

where durable Application identity is meant.

Likely replacement for Retry constraint wording:

    Retry remains constrained by current policy, capability, adapter,
    ApplicationRun, state, configuration, persistence, artifact, and workflow rules
    at the time of retry.

If durable Application or SaveBundle rules are also relevant, name them
separately rather than preserving AppInstance.

DA-20 owns Application/ApplicationRun lifecycle and runtime identity details.
DA-26 may reference those identities only to scope workflow claims.

==============================================================================
06. REQUIRED FIX: CROSS-SESSION AUDIT WORKFLOW WORDING
==============================================================================

The target title and body use cross-session audit workflow wording.

Session has been removed from the Turnix core model, so the phrase should be
reviewed.

Possible current replacements:

    - cross-run audit workflows
    - cross-ApplicationRun audit workflows
    - cross-Application audit workflows
    - cross-SaveBundle audit workflows
    - retained-artifact audit workflows

Use the narrowest phrase that matches the intended workflow.

If DA-26 intentionally keeps `cross-session` as a compatibility/user-facing term,
add a short compatibility note that it does not reintroduce Session as a Turnix
core architecture object.

Do not let cross-session wording reintroduce MainSession, HiddenSession,
TemporarySession, SessionRegistry, Session-owned Pipeline, Session-owned memory,
or ctx.sessions semantics.

==============================================================================
07. DA-04 RESTORATION BOUNDARY
==============================================================================

DA-26 should preserve DA-04 committed-state authority:

    Replay restores retained committed state within DA-04 restoration boundaries.

    Replay may present retained causal evidence, but evidence remains evidence.

    Resume begins new work from restored committed boundary.

    Retry begins new work and may reference earlier retained evidence.

    None of Replay, Resume, Retry, comparison, or audit workflow output becomes
    committed-state truth by itself.

    Audit workflow output remains evidence presentation unless a higher authority
    explicitly defines a committed-state mutation path that consumes it.

Do not let workflow reports become state authority.

==============================================================================
08. DA-25 ARTIFACT BOUNDARY
==============================================================================

DA-26 should preserve DA-25 artifact/export ownership:

    DA-25 defines WindowManifest, WindowExport, Minimal Audit Bundle, optional
    digest representation, partial export, missing material, and offline inspection
    artifact semantics.

    DA-26 defines workflow claims over those artifacts.

    DA-26 does not redefine artifact structure, export closure, partial-export
    marker semantics, missing-material marker structure, or offline inspection
    artifact semantics.

    A WindowManifest, WindowExport, Minimal Audit Bundle, digest, or missing-
    material marker may affect a DA-26 workflow outcome, but it does not define
    the workflow outcome by itself.

==============================================================================
09. DIGEST WATCH
==============================================================================

Preserve digest semantics:

    - DA-25 defines optional digest representation as artifact feature
    - DA-26 defines how comparison workflows may use optional digests
    - optional digest fields are accelerators
    - optional digest fields are not identities
    - optional digest fields do not add authority
    - digest mismatch in one equality mode does not imply mismatch in every
      equality mode
    - digest computation does not redefine DA-04 committed-state truth
    - digest computation does not redefine DA-05 payload identity, Chunk identity,
      ValueRef identity, or retained value representation
    - digest computation does not redefine DA-07 storage identity or persistent-I/O
      authority

Concrete digest algorithms and exact canonical serialization remain implementation
specification territory unless explicitly fixed.

==============================================================================
10. TRACE WORDING
==============================================================================

Follow the DA-03 cross-document trace wording check.

Workflow trace requirements are workflow-domain emission obligations.

Trace retention, trace pruning, trace loss, event structure, trace DAG semantics,
span mechanics, and trace storage semantics remain owned by DA-03.

DA-26 trace requirements apply when comparison, Replay, Resume, Retry, or audit
workflows are performed inside a running Turnix environment.

External offline reports do not become Turnix trace evidence unless imported or
recorded through a defined Turnix path.

Do not let workflow trace wording imply that trace evidence is committed state or
that trace persistence is guaranteed forever.

==============================================================================
11. WHAT TO PRESERVE FROM CURRENT DA-26
==============================================================================

Preserve these boundaries, translating stale terminology where present:

    - DA-26 owns comparison, Replay, Resume, Retry, and audit workflow claims over
      retained finalized Window-derived artifacts
    - workflow input does not add authority to consumed material
    - ComparisonResult has exactly Equal, NotEqual, and NotComparable
    - ComparisonResult is not boolean/integer/float/open string set
    - no convenience boolean equality API is provided
    - user-facing presentation distinguishes NotComparable from NotEqual
    - ComparisonResult without equality mode is incomplete
    - equality mode is part of the semantic claim
    - StateEquality compares retained committed key/value pairs only
    - StateEquality ignores revision history and non-authoritative evidence
    - StrictStateEquality returns NotComparable when required strict material is
      missing
    - unsupported strict submodes return NotComparable and do not silently degrade
      to StateEquality
    - EvidenceEquality is not state equality
    - ExportEquality is packaged-closure equality, not state equality by default
    - NotComparable is not NotEqual and not Equal
    - tools do not silently weaken equality mode after comparison failure
    - optional digests are comparison accelerators only
    - Replay restores retained committed state and retained causal story where
      available
    - Replay does not re-run external effects
    - Replay does not reconstruct uncommitted ActiveWindow activity
    - Replay does not resume retained live handles
    - Resume is explicit new work after restoration and is not deterministic in
      outcome
    - Resume does not reuse closed lifecycle identities
    - Retry is new work
    - Retry does not reuse previous jobId or orchestrationUnitId
    - Replay, Resume, and Retry remain distinct
    - audit workflows do not mutate state
    - audit workflows do not require journal completeness
    - audit workflows do not assume replayability
    - missing material remains explicit
    - external offline reports do not become Turnix trace evidence unless imported
      or recorded through defined Turnix path

Add DA-05 and DA-07 to the upstream list or otherwise make them visible as

12.2. Normalize OrchestrationUnit

12.5. Preserve DA-25 / DA-26 split

computation implementation, workflow file access, workflow import/export storage,
or workflow I/O behavior unless an owning implementation specification fixes them.

15. FINAL EDITOR INSTRUCTION
==============================================================================

Keep DA-26.

Do not perform a heavy conceptual rewrite.

Do perform targeted terminology and owner-boundary fixes:

    - add DA-05 and DA-07 to upstream/reference visibility
    - preserve DA-05 ownership of payload identity, Chunk, ChunkId, ValueRef,
      decode, integrity, and retained value representation
    - preserve DA-07 ownership of persistent-I/O authority and storage mechanics
    - normalize Orchestration Unit to OrchestrationUnit
    - translate AppInstance to ApplicationRun/Application where appropriate
    - replace or explicitly scope cross-session audit workflow wording so it does
      not reintroduce Session as a core object
    - preserve strict Replay / Resume / Retry formal meanings
    - preserve three-value ComparisonResult and explicit equality modes
    - preserve NotComparable as distinct from NotEqual
    - preserve missing-material explicitness

Use REWRITE-DA-26 only as translated boundary-preservation guidance. Do not copy
process metadata or obsolete wording into the final DA.

Do not include audit/source metadata or version/process framing in the final
DA-26 documentation. The final DA-26 should not say this is V3 design, in V3,
new design, old design, rewritten design, created by Codex, decided by audit, or
part of a rewrite-history process.

DA-26 should remain the comparison, equality modes, ComparisonResult, Replay,
Resume, Retry, and audit workflow semantics document.

DA-26 should not become:

    - committed-state authority specification
    - payload identity / ValueRef / Chunk representation specification
    - persistent-I/O authority specification
    - Window finalization specification
    - Window artifact/export specification
    - trace substrate specification
    - Job lifecycle specification
    - OrchestrationUnit lifecycle or mutation-authority specification
    - execution adapter boundary specification
    - concrete comparison API / replay implementation / audit UI specification

The main work is to preserve DA-26's strong workflow-claim model while making
representation, persistent-I/O, Window, artifact/export, Job, OrchestrationUnit,
and current runtime-identity boundaries explicit.
