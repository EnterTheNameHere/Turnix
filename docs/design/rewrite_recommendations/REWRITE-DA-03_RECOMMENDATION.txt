SUMMARY
=======

DA-03 is mostly Dv3-compatible.

No heavy rewrite is recommended.

Required DA-03 changes:

    1. Clarify trace emission obligation versus trace persistence guarantee.

    2. Add a compact source-level boundary saying DA-03 owns the trace
       substrate, while subject-owning documents own domain-specific trace
       obligations and trace reasons.

    3. Add or preserve a compact source-level rule that trace wording in other
       documents means domain trace emission obligation unless stronger
       persistence semantics are explicitly defined under DA-03.

Required preservation rules:

    - Trace is evidence, not committed state.
    - Trace loss weakens evidential completeness.
    - Trace loss does not by itself change committed-state correctness.
    - Trace retention and loss remain policy-governed.
    - DA-03 should not become the catalog of all domain trace reasons.
    - Optional diagnostic trace enrichment remains non-authoritative.

Overall recommendation:

    KEEP BUT CLARIFY TRACE EMISSION VS TRACE PERSISTENCE

ACTUAL DA-03 CHANGE 1: CLARIFY TRACE EMISSION VS TRACE PERSISTENCE
==================================================================

Current issue:

    Section 11 says trace data is best-effort, non-blocking, bounded, rotating,
    and safe to drop under pressure.

    It also says failure to write trace evidence does not block execution and
    does not affect committed-state correctness.

This is correct only if trace persistence is kept separate from trace emission
obligation.

Required distinction:

    Trace emission obligation:
        A subject-owning document may require that a domain attempt to emit
        trace evidence for a meaningful action.

    Trace persistence guarantee:
        The trace substrate does not guarantee that all emitted trace evidence
        is durably retained forever.

Recommended source change:

    Add wording to section 11 distinguishing emission obligation from
    persistence guarantee.

Suggested DA-03 wording:

    11.x. A subject-owning document may require that a domain attempt to emit
          trace evidence for a meaningful action.

    11.x. Such an obligation is an emission obligation, not a guarantee that
          trace persistence cannot fail.

    11.x. If required trace evidence cannot be persisted, retained trace
          evidence records the known loss, failure, or incompleteness when
          possible.

    11.x. Failure to retain trace evidence weakens evidential completeness; it
          does not by itself change committed-state correctness.


ACTUAL DA-03 CHANGE 2: ADD CROSS-DOCUMENT TRACE WORDING STOP-LINE
=================================================================

DA-03 should contain a compact source-level stop-line for trace wording used by
other documents.

Recommended source-level boundary:

    When a subject-owning document says an action is trace-visible, requires
    trace evidence, records trace evidence, or preserves trace/audit/
    observability evidence, that wording means a domain trace emission
    obligation unless stronger persistence semantics are explicitly defined
    under DA-03.

    Trace retention and trace loss remain governed by DA-03.

    Trace evidence remains evidence, not committed-state authority.

This belongs in DA-03 because DA-03 owns the trace substrate and the general
meaning of trace emission, trace retention, and trace loss.

Do not expand this into a catalog of every domain trace reason.


PRESERVATION RULE 1: TRACE IS EVIDENCE, NOT COMMITTED STATE
===========================================================

Preserve DA-03's authority split:

    Trace = causal/evidential proof within retained trace evidence.

    Memory/state system = authoritative committed state.

    SavePack/persistence = durable committed state package.

    Replay = requires trace plus state/checkpoints/domain semantics, not trace
    alone.

Do not rewrite DA-03 to make trace into:

    - committed state
    - committed-state restoration
    - replay semantics
    - rollback eligibility by itself
    - object lifecycle truth outside retained trace evidence

Correct doctrine:

    If trace is absent, trace cannot prove the action happened.

    If trace was lost, loss must itself be represented honestly when possible.

Incorrect doctrine to avoid:

    If trace was lost, reality did not happen.

    If trace persistence failed, committed state is invalid.

DA-04 owns committed-state authority.


PRESERVATION RULE 2: TRACE HONESTY
==================================

Preserve the no-heuristic-trace-suppression doctrine.

Turnix should not:

    - infer reasons without recording them
    - fabricate causal links from temporal ordering
    - hide known trace loss
    - present incomplete trace evidence as complete


PRESERVATION RULE 3: DEVELOPMENT-MODE TRACE ENRICHMENT IS NON-AUTHORITATIVE
===========================================================================

Preserve the distinction between:

    - optional diagnostic / verbose trace
    - domain-required trace evidence

Development-mode trace enrichment may include:

    - verbose traces
    - speculative branches
    - why-not-chosen explanations
    - layer-resolution breakdowns
    - debugger-specific annotations

Development-mode enrichment must remain:

    - explicit
    - non-authoritative
    - not behavior-changing
    - not additional authority
    - not a replacement for domain-owned trace obligations


PRESERVATION RULE 4: DA-03 OWNS TRACE SUBSTRATE, NOT EVERY DOMAIN TRACE REASON
==============================================================================

Preserve the ownership split:

    DA-03 owns the trace substrate.

    Subject-owning documents own domain-specific trace obligations and trace
    reasons.

DA-03 should define:

    - trace event model
    - trace relationships
    - trace storage and loss rules
    - trace access principles
    - diagnostics role
    - error correlation role
    - trace honesty rules
    - general meaning of trace emission, retention, and loss

DA-03 should not define every concrete trace reason for every runtime domain.


REWRITE-BOUNDARY GUARDRAILS, NOT SUGGESTED DA-03 CONTENT
=========================================================

This section is not suggested DA-03 wording.

It exists to prevent architectural drift during rewrite when the editor knows
DA-03 but may not have every related document loaded.

Use these as guardrails only.

Domain ownership guardrails:

    State and transaction trace obligations belong in DA-04.

    Discovery trace obligations belong in DA-09.

    Resolution trace obligations belong in DA-11.

    Dependency trace obligations belong in DA-13.

    Activation trace obligations belong in DA-14.

    Capability and permission trace obligations belong in DA-16.

    Decision and policy trace obligations belong in DA-17.

    Job trace obligations belong in DA-19.

    RPC trace obligations belong in DA-21 and RPC implementation/spec
    documents.

    AppInstance trace obligations belong in DA-20.

    ExecutionAdapter and adapter lifecycle trace obligations belong in DA-23
    and DA-27.

    OrchestrationUnit trace obligations belong in DA-24.

    RuntimeHost trace obligations belong in DA-28.

    PackManager trace obligations belong in DA-29.

    Window trace obligations belong in DA-08.

Local rewrite guardrails:

    Do not make trace persistence guaranteed forever.

    Do not make retained trace evidence required for committed-state
    correctness.

    Do not make trace evidence authoritative committed state.

    Do not make trace loss invalidate committed state.

    Do not let observability replace the owning domain's evidence.

    Do not let diagnostic output become authority merely because it is
    trace-like.

    Do not make a transport/update/subscription/UI view become truth merely
    because it reports trace-like information.

    Do not make DA-03 a mini-index of all runtime activity.

    Do not repeat the full DA-03 trace rule in every later rewrite
    recommendation.

Future rewrite notes should usually say only:

    Trace wording should follow the DA-03 cross-document trace wording check.

Then explain only the local consequence.


CURRENT FINAL RECOMMENDATION
============================

Keep DA-03.

Do not rewrite it heavily.

Clarify section 11 so domain trace obligations may require attempted emission
of trace evidence, while trace persistence remains policy-governed and may fail
or be lossy when loss is represented honestly.

Add or preserve a compact source-level cross-document trace wording stop-line:

    trace-visible / trace evidence / audit evidence / observability evidence
    means domain trace emission obligation unless stronger persistence
    semantics are explicitly defined under DA-03.

Do not make trace authoritative committed state.

Do not make DA-03 own every domain-specific trace obligation.

Use DA-03 as the central document for trace substrate, trace retention, trace
loss, and the cross-document trace wording check.
