ACTUAL DA-03 CHANGE 1: CLARIFY TRACE EMISSION VS TRACE PERSISTENCE
==================================================================

Current issue:

    Section 11 says trace data is:

        - best-effort persistence
        - non-blocking
        - bounded or rotating
        - safe to drop under pressure

    It also says failure to write trace evidence does not block execution and
    does not affect committed-state correctness.

This is coherent if trace is evidence rather than committed state.

However, without an explicit distinction, a reader or machine assistant may
misread this as:

    domain trace obligations are optional

That is not the intended Dv3 model.

Required distinction:

    trace emission obligation
        A domain may be required to attempt to emit trace evidence for a
        meaningful action.

    trace persistence guarantee
        The trace substrate does not guarantee that all emitted trace evidence
        is durably retained forever.

Recommended DA-03 change:

    Add wording to section 11 distinguishing emission obligation from
    persistence guarantee.

Suggested DA-03 addition:

    11.x. A subject-owning document may require that a domain attempt to emit
          trace evidence for a meaningful action.

    11.x. Such an obligation is an emission obligation, not a guarantee that
          trace persistence cannot fail.

    11.x. If required trace evidence cannot be persisted, retained trace
          evidence records the known loss, failure, or incompleteness when
          possible.

    11.x. Failure to retain trace evidence weakens evidential completeness; it
          does not by itself change committed-state correctness.

Reason:

    This prevents "trace data is best-effort" from being misread as "domain
    trace obligations are optional."

    It also prevents the opposite mistake, where required trace emission is
    misread as guaranteed durable trace retention.


PRESERVATION RULE 1: TRACE IS EVIDENCE, NOT COMMITTED STATE
===========================================================

Preserve DA-03's authority split:

    Trace = causal/evidential proof within retained trace evidence.

    Memory/state system = authoritative committed state.

    SavePack/persistence = durable committed state package.

    Replay = requires trace plus state/checkpoints/domain semantics, not trace
    alone.

Do not rewrite DA-03 to make trace into:

    - committed state
    - committed-state restoration
    - replay semantics
    - rollback eligibility by itself
    - object lifecycle truth outside retained trace evidence

Correct doctrine:

    If trace is absent, trace cannot prove the action happened.

    If trace was lost, loss must itself be represented honestly when possible.

Incorrect doctrine to avoid:

    If trace was lost, reality did not happen.

    If trace persistence failed, committed state is invalid.

DA-04 owns committed-state authority.


PRESERVATION RULE 2: TRACE HONESTY
==================================

Preserve the no-heuristic-trace-suppression doctrine.

Turnix should not:

    - infer reasons without recording them
    - fabricate causal links from temporal ordering
    - hide known trace loss
    - present incomplete trace evidence as complete

This protects the meaning of trace as structured evidence.


PRESERVATION RULE 3: DEVELOPMENT-MODE TRACE ENRICHMENT IS NON-AUTHORITATIVE
===========================================================================

Preserve the distinction between:

    - optional diagnostic/verbose trace
    - domain-required trace evidence

Development-mode trace enrichment may include:

    - verbose traces
    - speculative branches
    - why-not-chosen explanations
    - layer-resolution breakdowns
    - debugger-specific annotations

But development-mode enrichment must remain:

    - explicit
    - non-authoritative
    - not behavior-changing
    - not additional authority
    - not a replacement for domain-owned trace obligations

This prevents optional diagnostics from being mistaken for authoritative domain
trace evidence.


PRESERVATION RULE 4: DA-03 OWNS TRACE SUBSTRATE, NOT EVERY DOMAIN TRACE REASON
==============================================================================

Preserve the domain ownership split:

    DA-03 owns the trace substrate.

    Subject-owning documents own domain-specific trace obligations.

DA-03 should define the common trace substrate, trace event model, trace
relationships, trace storage/loss rules, trace access principles, diagnostics
role, error correlation role, and trace honesty rules.

DA-03 should not define every domain-specific trace reason.

Do not rewrite DA-03 into:

    - a catalog of state trace reasons
    - a catalog of discovery trace reasons
    - a catalog of resolution trace reasons
    - a catalog of dependency trace reasons
    - a catalog of activation trace reasons
    - a catalog of capability trace reasons
    - a catalog of Job trace reasons
    - a catalog of RPC trace reasons
    - a catalog of adapter trace reasons
    - a catalog of RuntimeHost trace reasons
    - a catalog of PackManager trace reasons
    - a debugger/replay trace specification

Those details belong to their subject-owning documents.

CROSS-DOCUMENT TRACE WORDING CHECK
==================================

Use DA-03 as the central document for checking trace wording across other
documents.

Several domain documents use wording such as:

    - trace-visible
    - trace evidence is required
    - trace evidence records
    - trace evidence preserves causal links
    - trace obligations
    - audit evidence
    - reproducibility evidence
    - observability evidence
    - diagnostic evidence

General audit rule:

    When any document says a domain action is trace-visible or requires trace
    evidence, interpret and/or rewrite that as a domain trace emission
    obligation unless the document explicitly defines stronger persistence
    semantics under DA-03.

The document should not accidentally imply:

    - trace persistence is guaranteed forever
    - retained trace evidence is required for committed-state correctness
    - trace evidence is authoritative committed state
    - loss of trace evidence invalidates committed state
    - observability replaces the owning domain's evidence
    - a transport/update/subscription/UI view becomes truth merely because it
      reports trace-like information
    - diagnostic output becomes authority merely because it is trace-like

The document should preserve:

    - DA-03 owns the trace substrate
    - subject-owning documents own domain-specific trace obligations
    - trace emission may be required by the owning domain
    - trace retention/loss remains policy-governed by DA-03
    - trace loss weakens evidential completeness
    - trace loss does not by itself change committed-state correctness
    - trace evidence preserves causal links where retained evidence exists
    - domain-specific trace reasons do not replace other domain trace reasons

This check applies broadly to domain documents, including:

    - state and transaction documents
    - discovery, identity, visibility, resolution, dependency, importing, and
      activation documents
    - service, capability, permission, and policy documents
    - RPC and transport documents
    - adapter and direct-call optimization documents
    - Job and OrchestrationUnit documents
    - RuntimeHost documents
    - PackManager documents
    - debugger, window, replay, and diagnostic documents

Recommendation for future rewrite notes:

    Do not repeat a full DA-03 trace clarification in every rewrite
    recommendation.

    In future audit notes, write only a short local note when needed:

        Trace wording should follow the DA-03 cross-document trace wording
        check.

    Then explain only what is specific to that document.


CURRENT FINAL RECOMMENDATION
============================

Keep DA-03.

Do not rewrite it heavily.

Clarify section 11 so domain trace obligations may require attempted emission
of trace evidence, while trace persistence remains policy-governed and may fail
or be lossy when loss is represented honestly.

Do not make trace authoritative committed state.

Do not make DA-03 own every domain-specific trace obligation.

Use DA-03 as the central document for the cross-document trace wording check.

Future audit notes should not repeat the full trace emission/persistence
clarification unless a document has a document-specific trace problem.

Instead, future audit notes should reference the DA-03 cross-document trace
wording check and then explain only the local consequence.
