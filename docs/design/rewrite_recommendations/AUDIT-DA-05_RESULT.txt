==============================================================================
01. VERDICT
==============================================================================

Recommendation verdict:
    Mostly correct, with small terminology translation required.

    The recommendation correctly preserves DA-05's central model: committed values
    are represented through immutable payload references, not live runtime object
    identity; ValueRef is immutable and decodes deterministic committed payload
    material; Chunk is immutable; ChunkId is stable, content-derived,
    format-aware, and storage-neutral; arbitrary file-path and network references
    are not ValueRef forms; corrupt payload material is not authoritative; schema
    linkage is optional; reachability is a retention-safety input; and persistent
    I/O authority remains outside DA-05.

    The recommendation still uses stale SavePack wording in examples around
    repackaging and retained roots. Translate that to SaveBundle / SaveBundle-
    local retained material where durable persistence closure is meant.

Document verdict:
    Keep with small reference and terminology fixes.

DA-05 is architecturally strong and should not be heavily rewritten.

The target already preserves the main storage-neutral committed-value
representation model.

The main required fixes are:

    - replace stale `savePack` / `SavePack` examples with SaveBundle or
      SaveBundle-local retained material wording
    - update vague `later design areas` references to explicit DA-08 / DA-25 /
      DA-26 ownership boundaries
    - optionally add a Downstream Documents section for navigation
    - normalize locally confusing subsection numbering
    - preserve closed ValueRef forms and avoid external-reference drift
    - preserve DA-04 committed-state authority and DA-07 persistent-I/O authority
    - preserve DA-03 trace wording for representation-domain trace obligations
    - avoid final-document version/process metadata leakage

Primary conclusion:
    Keep DA-05 as the payload identity, Chunk, ChunkId, ValueRef, storage-neutral
    committed-value representation, integrity, schema-linkage, retained-root
    reachability, and representation/persistence-authority boundary document.
    Apply targeted terminology and cross-reference fixes only.

==============================================================================
01A. OBSOLETE-PRESERVATION CHECK
==============================================================================

DA-05 should not keep older terminology merely because it appears in the older
source document or recommendation.

Specifically, the rewrite should not preserve:

    - SavePack as durable persistence identity
    - savePack repackaging as current primary architecture wording
    - savePack manifests as current retained-root terminology
    - SavePack-local material as ordinary current Pack/persistence terminology
    - arbitrary file-path references as ValueRef forms
    - arbitrary network references as ValueRef forms
    - mutable runtime object identity as committed value identity
    - filesystem path, database row identity, runtime pointer identity, machine
      identity, timestamp, or storage-container identity as Chunk identity
    - trace completeness, journal completeness, or transactional layers as
      required for ValueRef decode
    - integrity failure as tolerable authoritative variation
    - decode failure as valid authoritative content
    - semantic similarity as Chunk identity equivalence
    - raw chunk reuse as semantic equivalence unless committed value meaning is
      preserved
    - reachability as artifact authority

Canonical translations:

    SavePack -> SaveBundle where durable persistence closure is meant

    savePack repackaging -> SaveBundle packaging, SaveBundle persistence
    closure movement, or storage relocation that preserves the same payload
    material, depending on exact meaning

    savePack manifests -> SaveBundle manifests / SaveBundle-retained root
    manifests, if the root belongs to durable persistence closure

The useful part of the older recommendation is not the old SavePack terminology.
The useful part is this boundary:

    DA-05 defines representation identity. It does not define committed-state
    truth, transaction authority, persistent I/O authority, artifact/export
    authority, comparison authority, Replay/Resume/Retry semantics, capability
    permission, or Pack authority.

==============================================================================
01B. DOCUMENT-METADATA LEAKAGE CHECK
==============================================================================

The final DA-05 document should read as architecture documentation, not as audit,
version, or rewrite-process metadata.

Do not include statements such as:

    - This is V3 design.
    - In V3, SaveBundle replaces SavePack.
    - The new design uses DA-25 for exports.
    - This rewrite updated later design area references.
    - Unlike V2, ValueRef is closed.
    - Codex kept SavePack wording.
    - This audit decided that ChunkId is storage-neutral.
    - DA-05 was rewritten because of the audit.

Those facts may be useful in audit files, migration notes, compatibility notes,
branch notes, changelogs, or explicitly historical documents. They do not belong
in the architecture document itself.

The final DA-05 should simply define payload identity, Chunk, ChunkHeader,
ChunkId, ValueRef, InlineValueRef, ChunkValueRef, codecId, optional schema
linkage, static-origin representation, payload sharing, reachability, persistent
I/O boundary, optional storage capabilities, open encoding choices, and locked
summary.

==============================================================================
02. WHAT DA-05 GETS RIGHT
==============================================================================

02.1. Storage-neutral committed value representation
----------------------------------------------------

DA-05 correctly says Turnix does not treat committed state as live runtime object
identity.

It correctly says committed values are represented through immutable payload
references and runtime objects are decoded views of committed payload material.

Preserve this strongly.

02.2. DA-05 owns representation, not authority outside representation
---------------------------------------------------------------------

DA-05 correctly says it defines representation semantics for committed values
but does not grant transaction authority, persistence authority, trace authority,
capability permission, Pack authority, Window finalization authority, export
authority, comparison authority, Replay, Resume, or Retry authority.

Preserve this.

02.3. Chunk identity is storage-neutral
---------------------------------------

DA-05 correctly says ChunkId is stable across export/import, copying between
storage backends, and storage relocation that preserves the same payload material.

It correctly says ChunkId does not depend on filesystem path, database row
identifier, timestamp, machine identity, wall-clock time, transport, or storage-
container identity.

Preserve this.

02.4. Integrity failure is explicit
-----------------------------------

DA-05 correctly says integrity verification is performed by recomputing
contentHash from payload bytes and comparing it with stored contentHash.

It correctly says corrupt payload material is not authoritative and Turnix does
not silently accept corrupt retained payload material as valid committed
representation.

Preserve this.

02.5. Chunk identity is format-aware
------------------------------------

DA-05 correctly says different encodings produce different ChunkIds unless a
later authoritative rule explicitly defines a canonical equivalence model.

It correctly prevents silent semantic-equivalence canonicalization.

Preserve this.

02.6. ValueRef is immutable and closed-form
-------------------------------------------

DA-05 correctly says a ValueRef is immutable once created, not a pointer to live
runtime memory, and a deterministic decoding contract for one committed value
payload.

It correctly says ValueRef is exactly one of:

    - InlineValueRef
    - ChunkValueRef

It correctly excludes arbitrary network references and arbitrary file-path
references from ValueRef.

Preserve this strongly.

02.7. Schemaless default is strong
----------------------------------

DA-05 correctly says committed values are schemaless by default, and schema
linkage is optional committed-value representation metadata.

It correctly says schema-aware decode failure is explicit unless later
authoritative policy explicitly permits fallback, and fallback remains
trace-visible.

Preserve this.

02.8. Static origin does not bypass representation
--------------------------------------------------

DA-05 correctly says static origin does not exempt committed values from the
committed representation contract.

It correctly says Patch and Copy semantics apply at committed-value meaning level
rather than raw chunk storage identity.

Preserve this.

02.9. Payload sharing does not change authority
-----------------------------------------------

DA-05 correctly says payload chunks may be shared across retained artifacts, but
sharing does not change authority boundaries.

It correctly says reachability determines retention safety and does not redefine
root artifact kind.

Preserve this.

02.10. Persistent I/O authority remains outside DA-05
-----------------------------------------------------

DA-05 correctly says it does not define who may read or write persistent payload
material directly.

It correctly says persistent access to retained Chunk material or committed
ValueRef payload routes through centralized persistent I/O authority defined
elsewhere, and Packs do not resolve or write chunk storage directly.

Preserve this.

02.11. Optional storage capabilities do not change identity
----------------------------------------------------------

DA-05 correctly says compression, encryption at rest, chunk streaming, logical
chunk packing, paging, and partial retrieval do not change Chunk or ValueRef
identity semantics.

Preserve this.

==============================================================================
03. REQUIRED FIX: SAVEBUNDLE TERMINOLOGY
==============================================================================

The target and recommendation still contain SavePack-era examples:

    - savePack repackaging
    - savePack manifests
    - SavePack repackaging
    - SavePack manifests

Proposal P02 establishes SaveBundle as the durable persistence closure of an
Application. SaveBundle is not a Pack.

Replace SavePack wording with SaveBundle/persistence wording while preserving the
intended representation semantics.

Recommended replacements:

    savePack repackaging
        -> SaveBundle packaging, SaveBundle persistence-closure movement, or
           storage relocation that preserves the same payload material

    SavePack repackaging
        -> SaveBundle packaging or storage relocation that preserves the same
           payload material

    savePack manifests
        -> SaveBundle manifests or SaveBundle-retained root manifests, if the
           root belongs to durable persistence closure

    SavePack manifests
        -> SaveBundle manifests or SaveBundle-retained root manifests

Do not classify SaveBundle as a Pack.

Do not make SaveBundle storage authority part of DA-05. DA-05 defines payload
identity and representation. SaveBundle/persistence documents own durable
persistence closure, retained material, storage, compatibility, and recovery
rules.

==============================================================================
04. REQUIRED FIX: WINDOW / ARTIFACT / WORKFLOW CROSS-REFERENCES
==============================================================================

The target currently says it does not define:

    windows, manifests, exports, or audit-bundle semantics
    (see later design areas)

This should become explicit now that the downstream documents exist.

Recommended replacement:

    DA-05 does not define:

        - Window, ActiveWindow, SafePointWindow, AbortedWindow, Window sequence,
          or Window finalization semantics (see DA-08)

        - WindowManifest, WindowExport, Minimal Audit Bundle, digest
          representation, partial export, missing material, export creation, or
          offline-inspection artifact semantics (see DA-25)

        - equality modes, ComparisonResult, Replay, Resume, Retry, or audit
          workflow semantics (see DA-26)

This is a cross-document reference update, not a conceptual rewrite.

==============================================================================
05. OPTIONAL NAVIGATION FIX: DOWNSTREAM DOCUMENTS
==============================================================================

DA-05 currently lists upstream documents but has no downstream section.

A downstream section is optional, but useful.

Recommended downstream list:

    Downstream Documents:
    ---------------------
    - DA-07
    - DA-08
    - DA-25
    - DA-26
    - future persistence implementation specifications
    - future export implementation specifications
    - future comparison implementation specifications

Reason:
    DA-05 is consumed by persistence, Window history, Window artifact/export,
    comparison, Replay, Resume, Retry, and audit-workflow documents.

This should remain navigation only. It should not make DA-05 the owner of those
other domains.

==============================================================================
06. NUMBERING AND REFERENCE USABILITY
==============================================================================

DA-05 has local numbering problems that may confuse references:

    - 04.6 followed by 04.6.1
    - section 08 then subsection headings 08.1 and 08.2 reused as headings

This is mostly formatting, but stable reference usability matters in architecture
files.

Recommended fix:

    Normalize subsection numbering without changing semantics.

Do not treat this as an architecture change.

==============================================================================
07. TRACE WORDING
==============================================================================

Follow the DA-03 cross-document trace wording check.

DA-05 trace requirements are representation-domain emission obligations when
integrity failure, decode failure, garbage collection, schema fallback,
corruption, or representation-affecting actions occur in a running Turnix context.

Trace retention, trace pruning, trace loss, event structure, trace DAG semantics,
span mechanics, and trace storage semantics remain owned by DA-03.

Do not let DA-05 wording imply that trace completeness is required for ValueRef
decode.

ValueRef explicitly does not depend on trace completeness.

==============================================================================
08. AUTHORITY STOP-LINES
==============================================================================

DA-05 should preserve these authority stop-lines:

    DA-04 owns committed-state authority, transaction semantics, and commit
    semantics.

    DA-05 owns representation contracts for committed values.

    DA-07 owns persistent I/O authority.

    DA-08 owns Window kinds and Window finalization.

    DA-25 owns artifact/export semantics.

    DA-26 owns ComparisonResult, equality modes, Replay, Resume, Retry, and audit
    workflow semantics.

    DA-16 owns capability and permission semantics.

    SaveBundle/persistence documents own durable persistence closure, retained
    material, storage, compatibility, and recovery semantics.

DA-05 may name these domains to preserve representation boundaries, but it should
not define their detailed behavior.

==============================================================================
09. WHAT TO PRESERVE FROM CURRENT DA-05
==============================================================================

Preserve these boundaries, translating SavePack terminology where present:

    - committed values are represented through immutable payload references
    - committed state references immutable payload bytes, not live runtime object
      identity
    - runtime objects are decoded views of immutable payload material
    - ValueRef is immutable once created
    - ValueRef is a deterministic decoding contract for one committed value
      payload
    - ValueRef forms are exactly InlineValueRef and ChunkValueRef
    - arbitrary file-path and network references are not ValueRef forms
    - Chunk is immutable
    - ChunkId is stable, content-derived, format-aware, and storage-neutral
    - ChunkId is independent of filesystem path, database row identity, machine
      identity, timestamp, wall-clock time, runtime pointer identity, and
      storage-container identity
    - integrity failure is explicit
    - corrupt payload material is not authoritative
    - committed values are schemaless by default
    - schema linkage is optional representation metadata
    - schema-aware failure is explicit unless later authoritative policy allows
      fallback
    - static origin does not bypass committed representation
    - payload sharing does not change authority boundaries
    - reachability determines retention safety, not artifact authority
    - garbage collection does not delete chunks reachable from authoritative
      retained roots
    - persistent I/O authority remains outside DA-05
    - Packs do not resolve chunk storage directly
    - Packs do not write payload bytes referenced by authoritative committed
      ValueRefs directly
    - optional storage capabilities do not change Chunk or ValueRef identity
    - exact ChunkId encoding, digest algorithms, canonical serialization rules,
      codec implementation, concrete storage layout, and optional storage
      capabilities remain open unless fixed by an owning implementation spec

13. FINAL EDITOR INSTRUCTION
==============================================================================

Keep DA-05.

Do not perform a heavy conceptual rewrite.

Do perform targeted reference and terminology fixes:

    - replace SavePack/savePack examples with SaveBundle/persistence terminology
    - update `later design areas` references to explicit DA-08 / DA-25 / DA-26
      ownership boundaries
    - optionally add a Downstream Documents section
    - normalize local subsection numbering
    - preserve closed ValueRef forms
    - preserve storage-neutral ChunkId identity
    - preserve integrity/decode failure as explicit non-authoritative failure
    - preserve DA-04 committed-state authority and DA-07 persistent-I/O authority

Use REWRITE-DA-05 only as translated boundary-preservation guidance. Do not copy
process metadata or obsolete wording into the final DA.

Do not include audit/source metadata or version/process framing in the final
DA-05 documentation. The final DA-05 should not say this is V3 design, in V3,
new design, old design, rewritten design, created by Codex, decided by audit, or
part of a rewrite-history process.

DA-05 should remain the payload identity, Chunk, ChunkId, ChunkHeader, ValueRef,
InlineValueRef, ChunkValueRef, schema-linkage, static-origin, reachability,
payload-sharing, and representation / persistent-I/O boundary document.

DA-05 should not become:

    - committed-state authority specification
    - transaction specification
    - persistent I/O authority specification
    - trace substrate specification
    - configuration schema or migration specification
    - Window lifecycle/finalization specification
    - artifact/export specification
    - comparison / Replay / Resume / Retry / audit workflow specification
    - SaveBundle storage/recovery specification
    - capability/permission specification
    - Pack authority specification
    - concrete serialization / digest / codec / storage implementation spec

The main work is to preserve DA-05's strong storage-neutral representation model
while translating old SavePack references and tightening explicit downstream
ownership boundaries.
