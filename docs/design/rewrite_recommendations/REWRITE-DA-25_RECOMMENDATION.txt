SUMMARY
=======

DA-25 is strong and Dv3-compatible.

Keep it as the Window artifact, export, Minimal Audit Bundle, optional digest,
partial export, missing-material, and offline inspection boundary document.

Preserve the central rule:

    Artifact representation does not add authority.

    Exported form changes portability, not semantics.

    Offline inspection reads retained artifact contents. It does not run Turnix
    orchestration logic.

DA-25 consumes finalized Window semantics from DA-08.

DA-25 does not redefine:

    - committed-state truth
    - payload identity, ChunkId, Chunk, ValueRef, decode, or retained value
      representation contracts
    - persistent I/O authority, Reader / Writer providers, filesystem rules, or
      storage-root authority
    - Window finalization
    - trace substrate
    - Job lifecycle
    - OrchestrationUnit lifecycle
    - equality modes
    - Replay
    - Resume
    - Retry
    - cross-session audit workflow semantics

Current required source-level changes:

    None required beyond preserving existing DA-25 direction.

Current recommendation-level update:

    Preserve the already-present DA-05 and DA-07 source boundaries in this
    rewrite recommendation, because DA-25 artifacts refer to retained payloads,
    retained value representations, external payload availability, export
    closure material, and offline decoding behavior.

Overall recommendation:

    KEEP WITH SMALL DIGEST / PARTIAL-EXPORT / PAYLOAD-IO TAXONOMY WATCH


CURRENT CLASSIFICATION
======================

KEEP WITH SMALL DIGEST / PARTIAL-EXPORT / PAYLOAD-IO TAXONOMY WATCH

DA-25 should not be rewritten heavily.

Future edits should preserve:

    - WindowManifest represents exactly one finalized Window
    - WindowManifest never represents an ActiveWindow
    - manifest immutability preserves representation stability only
    - manifest existence does not create authority
    - SafePointWindowManifest authority comes only from the retained
      committed-state closure it represents
    - AbortedWindowManifest is non-authoritative abort evidence
    - WindowExport is a portable immutable closure of one finalized
      WindowManifest
    - export changes portability, not semantics
    - export does not add authority
    - export does not imply replayability, resumability, or evidence
      completeness
    - export does not redefine ValueRef, Chunk, ChunkId, decode, payload
      identity, or retained value representation semantics
    - export does not redefine persistent I/O authority, Reader / Writer
      behavior, storage roots, or filesystem rules
    - Minimal Audit Bundle is non-authoritative evidence
    - Minimal Audit Bundle is not restoration artifact, replay guarantee, or
      completeness guarantee
    - optional digests are comparison accelerators, not identities or authority
    - offline inspection does not control original runtime participants
    - missing, pruned, corrupt, partial, unavailable, unsupported, or omitted
      material remains explicit


ACTUAL DA-25 CHANGE 1: PRESERVE DA-05 PAYLOAD / VALUEREF BOUNDARY
=================================================================

DA-25 source already says it does not define:

    payload identity, ChunkId, or ValueRef representation contracts

This should be preserved and, if future edits expand retained payload or decode
wording, made slightly more complete.

Recommended source-level wording if touched:

    DA-25 may name retained payload references, retained committed-state
    closures, exported payload material, missing external payload material, and
    offline decode behavior.

    DA-25 does not define payload identity, Chunk, ChunkId, ValueRef, decode,
    integrity, or retained value representation contracts.

    DA-05 owns those meanings.

Reason:

    DA-25 exports and inspects retained material.

    DA-25 does not own the identity or representation model of retained payload
    material.

    A WindowExport containing value material does not make export identity the
    same thing as payload identity or committed-state identity.


ACTUAL DA-25 CHANGE 2: PRESERVE DA-07 PERSISTENT-I/O BOUNDARY
=============================================================

DA-25 source already says it does not define:

    concrete persistent I/O authority, Readers, Writers, or filesystem rules

This should be preserved and, if future edits expand packaging or export tooling
wording, made slightly more complete.

Recommended source-level wording if touched:

    DA-25 defines artifact and export semantics.

    DA-25 does not define persistent I/O authority, Reader / Writer providers,
    root boundaries, filesystem rules, backup/snapshot mechanics, streaming I/O,
    or storage safety.

    DA-07 owns those meanings.

Reason:

    DA-25 can say what a WindowExport, WindowManifest, or Minimal Audit Bundle
    means.

    DA-25 should not become the authority that decides how files are read,
    written, streamed, stored, backed up, or recovered.

    Export packaging does not bypass IoManager authority.


ACTUAL DA-25 CHANGE 3: PRESERVE DA-08 WINDOW BOUNDARY
=====================================================

DA-25 consumes finalized Window semantics from DA-08.

Preserve:

    DA-25 owns artifact and export semantics derived from finalized Windows.

    DA-08 owns Window, ActiveWindow, SafePointWindow, AbortedWindow, Window
    ordering, Window finalization, and finalized runtime history semantics.

    DA-25 does not define when a SafePointWindow or AbortedWindow exists.

    DA-25 does not make an ActiveWindow exportable as a finalized Window
    artifact.

Reason:

    DA-25 begins after Window finalization.

    DA-25 must not become an alternate Window finalization path.


ACTUAL DA-25 CHANGE 4: PRESERVE DA-26 WORKFLOW BOUNDARY
=======================================================

DA-25 already names equality, ComparisonResult, Replay, Resume, Retry, and
cross-session audit workflow semantics as DA-26-owned.

Preserve this boundary.

Recommended source-level wording if touched:

    DA-25 defines artifact/export representation and offline inspection
    boundaries.

    DA-26 defines equality modes, ComparisonResult, Replay, Resume, Retry, and
    cross-session audit workflow semantics.

    A WindowManifest, WindowExport, Minimal Audit Bundle, digest, or
    missing-material marker may affect DA-26 workflow outcomes, but it does not
    define them by itself.

Reason:

    DA-25 artifacts can be input material for DA-26 workflows.

    DA-25 does not own DA-26 workflow outcomes.


PRESERVATION RULE 1: ARTIFACT REPRESENTATION DOES NOT ADD AUTHORITY
===================================================================

Preserve artifact authority boundaries.

Authority derives from the finalized Window kind and retained roots represented
by the artifact.

Authority does not derive from:

    - manifest existence
    - export existence
    - archive format
    - packaging format
    - digest
    - filename
    - presentation format

A SafePointWindow artifact represents an authoritative committed boundary only
through its retained committed-state closure.

Optional retained evidence roots remain non-authoritative evidence roots.

AbortedWindow artifacts remain non-authoritative evidence artifacts.

Minimal Audit Bundles remain non-authoritative evidence artifacts.

Committed-state excerpts included in evidence artifacts remain excerpts, not
restoration authority.

Export does not convert non-authoritative evidence into authoritative state.

Packaging does not hide missing data, pruning, corruption, or partial-export
limitations.


PRESERVATION RULE 2: WINDOWMANIFEST REPRESENTS ONE FINALIZED WINDOW
===================================================================

Preserve WindowManifest semantics.

A WindowManifest is an immutable manifest representing exactly one finalized
Window.

Manifest immutability preserves representation stability only.

Manifest immutability does not by itself create authority.

Authority derives from the Window kind and retained roots represented.

A WindowManifest never represents an ActiveWindow.

A WindowManifest is exactly one of:

    - SafePointWindowManifest
    - AbortedWindowManifest

A WindowManifest does not preserve:

    - transactional layer contents
    - live execution handles

A WindowManifest does not define by itself:

    - payload identity
    - persistent I/O authority
    - replay
    - resume
    - retry
    - equality workflow semantics


PRESERVATION RULE 3: SAFEPOINTWINDOWMANIFEST AUTHORITY COMES ONLY FROM COMMITTED CLOSURE
=======================================================================================

Preserve SafePointWindowManifest semantics.

A SafePointWindowManifest includes:

    - safePointWindowId
    - windowType = SafePointWindow
    - committedStateRoot

committedStateRoot identifies the retained committed-state closure for that
SafePointWindow through representation contracts defined elsewhere.

DA-05 owns retained value representation contracts.

DA-04 owns committed-state truth.

A SafePointWindowManifest may additionally include, by policy:

    - traceRoot
    - journalRoot
    - revisionRoot
    - mabRoot

Optional roots are explicitly labeled as non-authoritative evidence roots.

Optional roots do not add authority to the SafePointWindowManifest.

mabRoot, when present, is an evidence root only.

mabRoot does not add authority to the SafePointWindowManifest.

A SafePointWindowManifest is not complete if retained identity and committed
scope evidence are insufficient to identify the represented SafePointWindow and
its committed scope.

Missing optional evidence roots are explicit when the manifest claims a policy
or export mode that would otherwise require them.


PRESERVATION RULE 4: ABORTEDWINDOWMANIFEST IS NON-AUTHORITATIVE ABORT EVIDENCE
==============================================================================

Preserve AbortedWindowManifest semantics.

An AbortedWindowManifest includes:

    - abortedWindowId
    - windowType = AbortedWindow

The default AbortedWindowManifest form includes traceRoot.

An AbortedWindowManifest may additionally include:

    - journalRoot
    - mabRoot

An AbortedWindowManifest does not define committedStateRoot.

If traceRoot is absent, the AbortedWindowManifest declares that absence
explicitly together with the reason category for that absence.

An AbortedWindowManifest does not become authoritative merely because it is
finalized and immutable.

An AbortedWindowManifest represents finalized non-authoritative evidence of an
aborted Window region.

Missing trace, journal, or audit evidence remains explicit when it affects
interpretation of the retained abort evidence.


PRESERVATION RULE 5: WINDOWEXPORT CHANGES PORTABILITY, NOT SEMANTICS
====================================================================

Preserve WindowExport semantics.

A WindowExport is a portable immutable serialization of one WindowManifest
closure.

A WindowExport is derived from exactly one finalized WindowManifest.

A WindowExport is exactly one of:

    - SafePointWindowExport
    - AbortedWindowExport

Export does not add authority.

Export does not convert non-authoritative evidence into authoritative state.

Export does not preserve transactional layer contents.

Exported form changes portability, not semantics.

Export is self-contained with respect to retained payloads required to decode
the exported closure unless explicit partial-export policy is used.

If partial-export policy is used, missing material is explicit.

Explicit missing material affects comparison and inspection outcomes where the
selected workflow requires that material.

Export identity is not the same concept as committed-state identity.

Export identity is not payload identity.

Export closure remains compatible with DA-05 payload and reachability
contracts.

Export storage and export file I/O remain subject to DA-07 persistent I/O
authority.

A WindowExport does not imply:

    - replayability
    - resumability
    - evidence completeness


PRESERVATION RULE 6: SAFEPOINTWINDOWEXPORT IS ONLY RESTORABLE IF REQUIRED COMMITTED MATERIAL IS PRESENT
=====================================================================================================

Preserve SafePointWindowExport semantics.

A SafePointWindowExport is a WindowExport derived from one
SafePointWindowManifest.

A SafePointWindowExport includes the retained committed-state closure required
by the represented SafePointWindowManifest unless explicit partial-export policy
is used.

Optional evidence roots included in a SafePointWindowExport remain
non-authoritative evidence roots.

Missing committed-state material required for deterministic restoration is
explicit.

A partial SafePointWindowExport that lacks required committed-state material is
not a deterministic restoration artifact.

A SafePointWindowExport does not add authority beyond the retained
committed-state closure it carries.

A SafePointWindowExport does not replace DA-26 Replay or Resume semantics.

A SafePointWindowExport may provide material used by DA-26 workflows, but DA-26
defines those workflow outcomes.


PRESERVATION RULE 7: ABORTEDWINDOWEXPORT IS NOT RESTORATION OR REPLAY PROOF
===========================================================================

Preserve AbortedWindowExport semantics.

An AbortedWindowExport is a WindowExport derived from one AbortedWindowManifest.

An AbortedWindowExport does not include committedStateRoot.

An AbortedWindowExport may carry retained trace, journal, and audit evidence
according to export policy.

An AbortedWindowExport remains non-authoritative evidence of an abort region.

An AbortedWindowExport is not a restoration artifact.

An AbortedWindowExport is not replay proof.


PRESERVATION RULE 8: MINIMAL AUDIT BUNDLE IS NON-AUTHORITATIVE EVIDENCE
=======================================================================

Preserve Minimal Audit Bundle semantics.

A Minimal Audit Bundle is a non-authoritative export artifact intended to
support:

    - audit
    - explanation
    - offline inspection

A Minimal Audit Bundle is not:

    - authoritative state
    - a WindowManifest
    - a restoration artifact
    - a replay guarantee
    - a completeness guarantee

A Minimal Audit Bundle includes:

    - one or more retained trace roots
    - all retained trace events reachable within the retained trace closure
      selected for the bundle from those roots
    - metadata required to interpret retained trace reasons
    - enough correlation metadata to relate retained evidence to relevant
      AppInstance, session, OrchestrationUnit, Job, Window, or export identity

A Minimal Audit Bundle may additionally include:

    - selected journal entries referenced by trace evidence
    - selected committed-state excerpts as read-only evidence
    - selected revision metadata without full value payloads
    - selected Job lifecycle evidence
    - selected OrchestrationUnit lifecycle evidence
    - selected adapter lifecycle evidence
    - selected RPC correlation evidence
    - selected View or frontend lifecycle evidence

Committed-state excerpts included in a Minimal Audit Bundle are labeled
non-authoritative evidence excerpts.

A Minimal Audit Bundle does not include:

    - transactional layers
    - uncommitted mutations
    - executable code
    - capability implementations
    - secrets or credentials
    - live Job execution handles
    - live OrchestrationUnit execution handles
    - live adapter execution handles
    - live RPC channels or transports

A Minimal Audit Bundle preserves retained causal structure exactly for the trace
evidence it includes.

Missing data is explicit.

Missing data, pruning, corruption, and retained gaps do not silently disappear
behind presentation, packaging, or export format.

Absence of data in a Minimal Audit Bundle does not imply absence of behavior.

Minimal Audit Bundle creation failure is trace-visible.

Minimal Audit Bundle creation failure does not affect runtime state.

Minimal Audit Bundle creation may occur while Turnix is running.

Minimal Audit Bundle creation does not pause execution by default.

Minimal Audit Bundle creation does not block orchestration by default.

If Minimal Audit Bundle creation requires a quiescent or finalized boundary,
that requirement is explicit and owned by the creating workflow or export
policy.


PRESERVATION RULE 9: DIGESTS ARE OPTIONAL ACCELERATORS, NOT IDENTITIES
======================================================================

Preserve digest semantics.

Finalized artifacts may include optional digest fields.

Optional digest fields are accelerators for comparison and inspection work.

Optional digest fields are not identities.

Optional digest fields do not add authority.

A digest field is emitted only when canonical serialization rules for that
digest type are defined.

If canonical serialization rules for a digest type are not defined, that digest
type is not emitted.

Digest categories may include:

    - stateDigest
    - strictStateDigest
    - evidenceDigest
    - exportManifestDigest

Each digest category corresponds to a distinct comparison scope.

A digest category name is not reused for a different comparison scope unless an
explicit coordinated revision changes that meaning.

DA-26 owns equality modes and ComparisonResult semantics.

DA-25 owns digest representation as an artifact feature, not the complete
comparison workflow.

Digest canonicalization must not redefine DA-05 payload identity or DA-07
storage identity.


PRESERVATION RULE 10: OFFLINE INSPECTION DOES NOT CONTROL ORIGINAL RUNTIME PARTICIPANTS
======================================================================================

Preserve offline inspection boundaries.

WindowManifests, WindowExports, and Minimal Audit Bundles are inspectable
offline within the limits of their retained contents.

Offline inspection may resolve retained payload references and decode retained
value representations without running Turnix orchestration logic.

DA-05 owns retained payload reference and value representation semantics.

Offline inspection does not require capability calls.

Offline inspection does not require journal completeness.

Offline inspection treats retained evidence as evidence only.

Offline inspection does not promote evidence roots, evidence excerpts, or
exported packaging into authoritative state.

Lack of orchestration at inspection time does not weaken the authority boundary
defined by the represented artifact.

If retained material is partial, pruned, corrupt, or unavailable, offline
inspection reports that limitation explicitly.

Offline inspection of retained Job evidence does not resume, cancel, supersede,
or otherwise control the original Job.

Offline inspection of retained OrchestrationUnit evidence does not resume,
cancel, supersede, or otherwise control the original OrchestrationUnit.

Offline inspection of retained adapter evidence does not resume, cancel,
supersede, or otherwise control the original adapter.

Offline inspection of retained RPC evidence does not reconnect, replay, or
otherwise control the original transport or channel.

Offline inspection of retained View or frontend evidence does not reconnect or
control the original frontend participant.

Offline inspection does not become DA-26 Replay merely because it reads retained
evidence.


PRESERVATION RULE 11: PARTIAL EXPORT AND MISSING MATERIAL ARE EXPLICIT
======================================================================

Preserve partial-export and missing-material rules.

Partial export policy is explicit.

Partial export policy is represented in the exported artifact.

Missing material is represented explicitly with enough reason category
information to distinguish:

    - policy pruning
    - partial export
    - corruption
    - unavailable external payload
    - unsupported format
    - intentionally omitted sensitive material

Missing material does not silently become:

    - NotEqual
    - Equal
    - complete
    - authoritative

Missing material affects inspection and comparison workflows according to the
workflow semantics defined by DA-26.

Unavailable external payload material does not redefine DA-05 payload identity.

Unavailable external payload material does not redefine DA-07 persistent I/O
authority.

Export presentation does not hide explicit missing-material markers.

Export tools preserve missing-material markers when repackaging or transforming
retained artifacts.


WATCH ITEM: DIGEST ALGORITHMS AND CANONICAL SERIALIZATION
=========================================================

DA-25 leaves exact digest algorithms and exact canonical serialization rules
open.

Future implementation specifications must preserve:

    - digest fields are optional
    - digest fields are comparison accelerators
    - digest fields are not identity
    - digest fields do not add authority
    - a digest type is emitted only when canonical serialization rules for that
      digest type are defined
    - each digest category keeps a distinct comparison scope
    - digest canonicalization must not redefine DA-05 payload identity,
      committed-value representation, or DA-07 storage identity

Do not introduce digest semantics that bypass DA-26 equality and
ComparisonResult rules.


WATCH ITEM: MISSING-MATERIAL REASON TAXONOMY
============================================

DA-25 leaves exact missing-material reason taxonomy open.

Future implementation specifications should define the taxonomy without
weakening the current categories:

    - policy pruning
    - partial export
    - corruption
    - unavailable external payload
    - unsupported format
    - intentionally omitted sensitive material

Missing-material markers must remain visible through presentation, repackaging,
offline inspection, and comparison workflows.

Missing-material reason taxonomy must not silently become DA-05 payload
identity taxonomy or DA-07 persistent I/O error taxonomy.


WATCH ITEM: MINIMAL AUDIT BUNDLE NAME
=====================================

Minimal Audit Bundle can sound stronger than it is.

Preserve the meaning:

    Minimal Audit Bundle is non-authoritative evidence.

    Minimal Audit Bundle is not authoritative state.

    Minimal Audit Bundle is not a restoration artifact.

    Minimal Audit Bundle is not replay guarantee.

    Minimal Audit Bundle is not completeness guarantee.

If later naming or UI wording changes, keep this semantic boundary explicit.


WATCH ITEM: TRACE WORDING
=========================

Follow the DA-03 cross-document trace wording check.

DA-25 consumes retained trace evidence and may require trace-backed artifact
interpretation, but DA-03 owns trace substrate, retention, loss, event schema,
span semantics, and trace storage semantics.

Do not let artifact/export wording imply that trace evidence is committed state
or that trace persistence is guaranteed forever.

Preserve:

    Artifact representation preserves or packages retained evidence.

    It does not redefine trace truth or trace retention.


REWRITE-BOUNDARY GUARDRAILS, NOT SUGGESTED DA-25 CONTENT
========================================================

Use these as rewrite guardrails only.

Do not treat manifest existence as authority.

Do not treat export packaging as authority.

Do not treat archive format, filename, presentation format, or digest as
authority.

Do not treat export identity as committed-state identity.

Do not treat export identity as payload identity.

Do not treat optional digests as payload identities.

Do not let digest canonicalization redefine payload identity.

Do not let digest canonicalization redefine storage identity.

Do not treat Minimal Audit Bundle as authoritative state.

Do not treat Minimal Audit Bundle as restoration artifact.

Do not treat Minimal Audit Bundle as replay guarantee.

Do not treat Minimal Audit Bundle as completeness guarantee.

Do not hide missing data behind export presentation.

Do not promote evidence excerpts into committed state.

Do not treat committed-state excerpts in evidence bundles as restoration
authority.

Do not preserve transactional layers as export authority.

Do not export live Job handles.

Do not export live OrchestrationUnit handles.

Do not export live adapter execution handles.

Do not export live RPC channels or transports.

Do not use offline inspection to control original runtime participants.

Do not infer replayability merely because an export exists.

Do not infer resumability merely because an export exists.

Do not infer evidence completeness merely because an export exists.

Do not let DA-25 redefine payload identity, Chunk, ChunkId, ValueRef, decode, or
retained value representation contracts owned by DA-05.

Do not let DA-25 redefine persistent I/O authority, Reader / Writer providers,
filesystem rules, storage roots, backup/snapshot behavior, or streaming I/O
owned by DA-07.

Do not let DA-25 redefine Window finalization owned by DA-08.

Do not let DA-25 redefine equality, ComparisonResult, Replay, Resume, Retry, or
cross-session audit workflow semantics owned by DA-26.

Do not let DA-25 redefine committed-state truth owned by DA-04.

Do not let DA-25 redefine Job lifecycle owned by DA-19.

Do not let DA-25 redefine OrchestrationUnit lifecycle or mutation authority
owned by DA-24.


CURRENT FINAL RECOMMENDATION
============================

Keep DA-25.

No heavy rewrite is recommended.

Recommended future edits:

    - keep DA-25 focused on artifact, export, Minimal Audit Bundle, digest,
      partial export, missing-material, and offline inspection semantics derived
      from finalized Windows
    - preserve DA-08 ownership of Window kind, Window ordering, and Window
      finalization
    - preserve DA-04 ownership of committed-state truth
    - preserve DA-05 ownership of payload identity, Chunk, ChunkId, ValueRef,
      decode, integrity, and retained value representation contracts
    - preserve DA-07 ownership of persistent I/O authority, Reader / Writer
      providers, filesystem rules, storage roots, backup/snapshot behavior, and
      streaming I/O
    - preserve DA-26 ownership of equality, ComparisonResult, Replay, Resume,
      Retry, and cross-session audit workflow semantics
    - preserve export as portability, not authority
    - preserve Minimal Audit Bundle as non-authoritative evidence only
    - preserve optional digests as comparison accelerators only
    - preserve explicit partial-export and missing-material behavior
    - define concrete packaging, serialization, digest algorithms, canonical
      serialization, missing-material taxonomy, export storage, and retained
      material decoding implementation later without changing these authority
      boundaries
