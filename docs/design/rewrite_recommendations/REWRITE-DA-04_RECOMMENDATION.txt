SUMMARY
=======

DA-04 is Dv3-compatible.

No heavy rewrite is recommended.

DA-04 should remain the authoritative memory, state, transaction, and commit
model document.

Preserve the central rule:

    Committed state is authority.

    Non-committed material is evidence, staging, observation, lifecycle state,
    presentation, representation support, artifact packaging, workflow output,
    or tooling output unless committed through DA-04.

Required DA-04 clarifications:

    1. "Trace-visible" state mutation should mean a state/transaction trace
       emission obligation.

       It should not mean retained trace evidence is required for
       committed-state correctness.

       It should not mean trace evidence becomes committed-state authority.

    2. Add or preserve a compact committed-state stop-line that explicitly
       excludes payload representation, effectiveConfig, UI/View presentation,
       debugger views, artifact/export packaging, comparison output, Replay
       reports, Resume attempts, and Retry attempts from committed-state
       authority unless relevant material is committed through DA-04.

Overall recommendation:

    KEEP WITH SMALL TRACE-WORDING / COMPLETED-DOMAIN STOP-LINE CLARIFICATION

ACTUAL DA-04 CHANGE 1: TRACE-VISIBLE STATE MUTATION
===================================================

Current issue:

    DA-04 says authoritative state mutation and transaction outcomes remain
    trace-visible.

This is correct, but after DA-03, "trace-visible" should be interpreted using
the DA-03 cross-document trace wording check.

Correct meaning:

    trace-visible = the state/transaction domain has a trace emission obligation

Not:

    retained trace evidence is required for committed-state correctness

Not:

    trace evidence becomes committed-state authority

Recommended DA-04 clarification:

    State and transaction trace obligations are emission obligations.

    Trace retention and loss are governed by DA-03.

    Loss of trace evidence affects evidential completeness, not committed-state
    correctness.

Reason:

    This prevents a reader or machine assistant from turning trace evidence into
    committed-state authority.

    It also prevents the opposite error, where "trace may be lossy" is misread
    as "state mutation trace obligations are optional."


ACTUAL DA-04 CHANGE 2: COMMITTED-STATE STOP-LINE
================================================

DA-04 should contain a compact source-level boundary statement.

Recommended source-level boundary:

    Committed state is authoritative state.

    Runtime memory, transactional staging layers, trace, progress, tool views,
    debugger views, UI/View presentation, frontend state, adapter state,
    RuntimeHost command-surface output, PackManager presentation, Job lifecycle
    state, OrchestrationUnit lifecycle state, capability invocation records,
    RPC acknowledgement, diagnostic output, Window evidence, journal evidence,
    retained historical evidence, artifact packaging, export packaging,
    Minimal Audit Bundle material, comparison output, Replay reports, Resume
    attempts, and Retry attempts are not committed-state authority unless their
    relevant material is committed through the DA-04 commit model.

    Persistence protects committed truth but does not define truth.

    Trace explains or reports what happened where evidence is retained; trace
    does not define committed truth.

This stop-line belongs in DA-04 because DA-04 owns committed-state authority.


ACTUAL DA-04 CHANGE 3: COMPLETED DOMAIN ALIGNMENT
=================================================

DA-04 now has completed downstream documents for payload representation,
configuration, persistence, Windows, artifacts, comparison, Replay, Resume,
Retry, UI, debugger, adapters, RuntimeHost, OrchestrationUnit, Job, and
PackManager.

Recommended source-level alignment:

    DA-04 may name these domains only to preserve committed-state authority.

    DA-04 should not define their detailed behavior.

    DA-04 should preserve these compact boundary rules:

        DA-05 owns payload identity, Chunk, ChunkId, ValueRef, decode,
        integrity, and reachability representation.

        Payload material participates in committed-state restoration only when
        it is retained authoritative material referenced by committed state.

        DA-06 owns configuration scope, schema, materialization, migration,
        effectiveConfig, and policy-file placement semantics.

        Committed configuration is authoritative when committed through DA-04.

        effectiveConfig is a runtime-visible derived view, not a separate
        authority class.

        DA-07 owns persistent I/O authority.

        Persistence protects committed state but does not define committed
        truth.

        DA-08 owns Window kinds and Window finalization.

        SafePointWindow contains committed boundary material, but optional
        retained evidence inside it does not add committed-state authority.

        DA-25 owns WindowManifest, WindowExport, Minimal Audit Bundle, digest,
        partial export, and missing-material artifact semantics.

        Artifact/export representation does not add committed-state authority.

        DA-26 owns ComparisonResult, equality modes, Replay, Resume, Retry, and
        audit workflow semantics.

        ComparisonResult does not define committed-state truth.

        Replay restores retained committed state within DA-04 boundaries; it
        does not create new committed truth by itself.

        Resume and Retry are new work and do not retroactively commit prior
        uncommitted activity.

        DA-22 owns UI, View, frontend runtime, and frontend presentation
        semantics.

        UI/View presentation does not define committed truth.

        DA-18 owns debugger inspection, breakpoint, manual-pause, safe-point,
        debugger mutation, and debugger-originated control semantics.

        Debugger mutation that affects authoritative state still uses DA-04
        transaction and commit rules.

Reason:

    This prevents later-domain terms from being pulled into DA-04 as hidden
    committed-state authority.

This is a source-level boundary clarification, not a rewrite of those domains.


PRESERVATION RULE 1: COMMITTED STATE IS AUTHORITATIVE TRUTH
===========================================================

Preserve DA-04's core authority split:

    memory = runtime representation

    state = committed authority

    trace = evidence / observation

    persistence = protection

Runtime memory is not authoritative merely because it is:

    - resident
    - visible
    - active
    - currently in use

Committed state becomes authoritative only after crossing the explicit commit
boundary defined by DA-04.

Do not rewrite DA-04 to make any of these committed-state authority by
themselves:

    - trace
    - runtime memory
    - logs
    - journals
    - debugger views
    - UI/View presentation
    - frontend state
    - tool views
    - adapter state
    - RuntimeHost command-surface output
    - PackManager views
    - Job lifecycle state
    - OrchestrationUnit existence or lifecycle state
    - capability invocation records
    - RPC acknowledgement
    - diagnostic output
    - ActiveWindow evidence
    - AbortedWindow evidence
    - retained historical evidence
    - WindowManifest
    - WindowExport
    - Minimal Audit Bundle
    - optional digest values
    - ComparisonResult
    - Replay report
    - Resume attempt
    - Retry attempt
    - audit workflow report

Payload material may participate in authoritative committed state only when it
is retained authoritative material referenced by committed state under the
DA-04 / DA-05 representation boundary.

Committed configuration is authoritative when committed through DA-04.

effectiveConfig is not separate committed-state authority.


PRESERVATION RULE 2: TRACE IS NOT COMMITTED STATE
=================================================

Preserve the DA-03 / DA-04 split:

    Trace can prove or explain within retained evidence.

    Trace does not define committed truth.

    Trace loss does not corrupt committed state.

    Committed state is restorable without requiring non-authoritative
    observational history.

Do not rewrite DA-04 to make committed-state correctness depend on trace
completeness.

Keep the explicit non-requirement:

    no trace-backed correctness


PRESERVATION RULE 3: AUTHORITY CLASSES REMAIN BINARY
====================================================

Preserve the two authority classes:

    Authoritative

    Non-authoritative

Avoid introducing:

    - semi-authoritative
    - partially-authoritative
    - soft-authoritative
    - trace-authoritative-for-state
    - diagnostic-authoritative
    - view-authoritative
    - lifecycle-authoritative-for-state
    - artifact-authoritative
    - comparison-authoritative
    - replay-authoritative

Material may be important, required to attempt, useful for explanation, or
required by policy, but for committed-state truth it is either authoritative or
non-authoritative.


PRESERVATION RULE 4: TRANSACTIONS DEFINE MUTATION STAGING
=========================================================

Preserve DA-04's transaction model:

    A transaction is a temporary staging overlay.

    Staged mutation is not authoritative.

    A transaction resolves only by commit or abort.

    Commit and abort are atomic.

    Partial propagation does not occur.

    A transaction does not remain half-committed.

Nested transaction rule to preserve:

    Child transaction commits propagate into parent transactions, not directly
    into committed layers while an enclosing transaction exists.

    Only the outermost transaction commit mutates committed layers.


PRESERVATION RULE 5: NO SILENT CONFLICT RECONCILIATION
======================================================

Preserve deterministic conflict handling.

A transaction records the base committed revision visible when a key was first
touched.

Commit conflicts occur when committed existence or committed revision changed.

A conflicting commit fails deterministically.

Turnix must not silently use:

    - merge
    - last-write-wins
    - heuristic reconciliation

Any override requires explicit user decision or explicit policy elsewhere.


PRESERVATION RULE 6: PERSISTENCE PROTECTS TRUTH, BUT DOES NOT DEFINE TRUTH
=========================================================================

Preserve DA-04's persistence model:

    Persistence protects committed state against loss.

    Persistence does not define what state truth is.

    Committed state truth is determined by the commit model.

    Persistence failure does not silently redefine committed-state truth.

Clean stack to preserve:

    Commit model decides truth.

    Persistence protects truth.

    Trace explains or reports what happened.

DA-07 owns persistent I/O authority.

DA-05 owns retained payload representation.

DA-04 owns committed-state truth.


PRESERVATION RULE 7: STATIC DATA MUTATION INTENT REMAINS EXPLICIT
=================================================================

Preserve the Patch vs Copy distinction.

Static data is read-only by default.

Mutation intent must be explicit:

    Patch:
        original key remains authoritative
        patch is applied on read
        patch is persisted as overlay data

    Copy:
        new key is created
        data is copied and modified
        original remains unchanged

Turnix must not silently substitute Patch for Copy or Copy for Patch.

This matters for packs, mods, content, prompt fragments, defaults, templates,
and SavePack-local copied material.


PRESERVATION RULE 8: LATEST COMMITTED STATE REMAINS RESTORABLE
==============================================================

Preserve the revision-retention rule:

    Revision retention may be policy-driven.

    Older revisions may be removed.

    Garbage collection must not remove data required to reconstruct the latest
    committed state for each committed key.

History can be bounded.

Current committed truth cannot be silently rewritten by retention policy.

Payload GC must preserve retained payload material required by authoritative
committed state.

Persistence cleanup must not remove material needed for latest committed-state
restoration.


PRESERVATION RULE 9: TOOLING DOES NOT BYPASS COMMIT AUTHORITY
=============================================================

Preserve tooling mutation constraints.

Tooling can inspect through controlled surfaces.

Tooling-initiated mutation occurs inside a transaction and follows the same
commit/abort rules as runtime mutation.

Tooling does not bypass authority boundaries merely because it is privileged
tooling.

This applies to:

    - debugger
    - memory viewer
    - CLI inspection
    - PackManager tools
    - editor-like tools
    - artifact export tools
    - comparison tools
    - Replay tooling
    - Resume tooling
    - Retry tooling
    - audit tooling
    - future management Views
    - RuntimeHost command surfaces

The debug UI and management UI must not become separate state authority paths.


PRESERVATION RULE 10: RESTORATION BOUNDARY STAYS LIMITED
========================================================

Preserve DA-04's restoration boundary.

Turnix supports deterministic restoration of committed state from retained
authoritative material.

This does not imply:

    - deterministic reconstruction of in-flight activity
    - deterministic replay of external side effects
    - reproducibility of uncommitted activity
    - replay of pending Job execution
    - replay of active OrchestrationUnit execution
    - restoration of adapter runtime state
    - restoration of RuntimeHost command output
    - restoration of UI/View/frontend state as committed truth
    - restoration of debugger views as committed truth
    - restoration of Window evidence as committed truth
    - restoration of WindowExport as committed truth
    - restoration of Minimal Audit Bundle as committed truth
    - restoration of comparison output as committed truth
    - restoration of Resume or Retry outcome from prior evidence

Correct model:

    Restore committed state: yes.

    Reconstruct uncommitted runtime activity: no.

    Replay external side effects: no.

    Resume or Retry live handles: no.


WATCH ITEM: DA-05 PAYLOAD REPRESENTATION
========================================

DA-04 already excludes payload identity, ChunkId, and ValueRef representation
contracts from its scope.

Preserve this split.

DA-04 owns committed-state authority.

DA-05 owns payload identity, Chunk, ChunkId, ValueRef, decode, integrity, and
reachability representation.

Payload material may be required for committed-state restoration when committed
state references that material.

That does not make DA-04 the owner of ValueRef / Chunk representation semantics.

Do not let storage layout, chunk location, digest representation, or payload
reachability redefine committed-state authority.


WATCH ITEM: DA-06 CONFIGURATION BOUNDARY
========================================

DA-04 includes committed configuration as authoritative material.

Preserve this split.

DA-04 owns the fact that committed configuration is authoritative when committed
through DA-04.

DA-06 owns:

    - configuration scopes
    - schema use
    - defaults
    - overrides
    - effectiveConfig
    - materialization
    - migration
    - storage layout
    - policy-file placement

effectiveConfig is runtime-visible derived view, not separate authority.

Do not let configuration storage layout, schema, defaults, overrides, or
computed transforms bypass DA-04 commit authority.


WATCH ITEM: DA-25 / DA-26 ARTIFACT AND WORKFLOW BOUNDARY
========================================================

Preserve artifact/workflow separation from committed-state truth.

DA-25 owns:

    - WindowManifest
    - WindowExport
    - Minimal Audit Bundle
    - optional digests
    - partial export
    - missing material
    - offline-inspection artifact semantics

DA-26 owns:

    - ComparisonResult
    - equality modes
    - Replay
    - Resume
    - Retry
    - audit workflows

These domains may consume committed-state material.

They do not define committed-state truth.

Replay restores retained committed state within DA-04 boundaries.

Replay does not re-run external effects.

Resume and Retry are new work.

Do not let artifacts, exports, digests, comparison output, Replay reports,
Resume attempts, Retry attempts, or audit reports become committed-state
authority by presentation or packaging.


WATCH ITEM: TRACE WORDING
=========================

Follow the DA-03 cross-document trace wording check.

State and transaction trace requirements are DA-04-domain emission obligations.

DA-03 owns trace substrate, retention, loss, event structure, trace DAG
semantics, span mechanics, and trace storage semantics.

Do not let DA-04 trace wording imply that trace evidence is committed state or
that trace persistence is guaranteed forever.
