==============================================================================
01. VERDICT
==============================================================================

Recommendation verdict:
    Correct in substance.

    The recommendation correctly preserves DA-25's central model: artifact
    representation does not add authority; exported form changes portability, not
    semantics; offline inspection reads retained artifact contents but does not run
    Turnix orchestration logic; WindowManifest represents exactly one finalized
    Window; WindowExport is a portable immutable closure of one finalized
    WindowManifest; Minimal Audit Bundle is non-authoritative evidence only;
    optional digests are comparison accelerators only; missing material remains
    explicit; and DA-26 owns equality, ComparisonResult, Replay, Resume, Retry,
    and audit workflow semantics.

Document verdict:
    Keep with small terminology and stop-line fixes.

DA-25 is architecturally strong and should not be heavily rewritten.

The target already correctly keeps DA-25 focused on Window artifacts, Window
exports, Minimal Audit Bundles, optional digest accelerators, partial export,
missing material, and offline inspection boundaries.

The main required fixes are:

    - normalize Orchestration Unit to OrchestrationUnit where the first-class type
      is meant
    - preserve DA-05 ownership of payload identity, Chunk, ChunkId, ValueRef,
      decode, integrity, and retained value representation contracts
    - preserve DA-07 ownership of persistent-I/O authority, Reader/Writer
      providers, filesystem rules, storage roots, backup/snapshot behavior, and
      streaming I/O
    - preserve DA-08 ownership of Window kind, Window ordering, Window finalization,
      and finalized runtime history
    - preserve DA-26 ownership of equality modes, ComparisonResult, Replay,
      Resume, Retry, and audit workflow semantics
    - preserve Minimal Audit Bundle as non-authoritative evidence, not a
      restoration artifact, replay guarantee, or completeness guarantee
    - preserve optional digest fields as comparison accelerators only, not
      identities or authority
    - preserve explicit partial-export and missing-material behavior
    - keep concrete packaging, serialization, digest algorithms, canonical
      serialization, export storage, missing-material taxonomy, and audit-tooling
      presentation open unless implementation specifications fix them
    - avoid final-document version/process metadata leakage

Primary conclusion:
    Keep DA-25 as the Window artifact, export, Minimal Audit Bundle, optional
    digest, partial export, missing-material, and offline inspection boundary
    document. Apply targeted terminology and owner-stop-line fixes only.

==============================================================================
01A. OBSOLETE-PRESERVATION CHECK
==============================================================================

DA-25 should not keep older terminology merely because it appears in older source
material or recommendations.

Specifically, the rewrite should not preserve:

    - Orchestration Unit as spaced informal wording where OrchestrationUnit is the
      current first-class type
    - cross-session audit workflow as a current phrase if DA-26 uses current
      ApplicationRun / Application / SaveBundle terminology instead
    - AppInstance or session as correlation identity vocabulary unless explicitly
      retained as compatibility aliases
    - manifest existence as authority
    - export existence as authority
    - archive format, packaging format, digest, filename, or presentation format
      as authority
    - export identity as committed-state identity
    - export identity as payload identity
    - optional digest fields as identities
    - optional digest fields as authority
    - digest canonicalization as redefining DA-05 payload identity
    - digest canonicalization as redefining DA-07 storage identity
    - Minimal Audit Bundle as authoritative state
    - Minimal Audit Bundle as restoration artifact
    - Minimal Audit Bundle as replay guarantee
    - Minimal Audit Bundle as completeness guarantee
    - committed-state excerpts in evidence bundles as restoration authority
    - transactional layers as export authority
    - live Job handles, live OrchestrationUnit handles, live adapter execution
      handles, live RPC channels, or live transports as exported material
    - offline inspection as a way to control original runtime participants
    - export existence as replayability, resumability, or evidence completeness

Canonical translations:

    Orchestration Unit -> OrchestrationUnit when the first-class type is meant
    cross-session audit workflow -> current DA-26 terminology for cross-run,
        cross-Application, or cross-SaveBundle audit workflow if DA-26 defines one
    AppInstance -> ApplicationRun where live runtime incarnation is meant
    AppInstance -> Application where durable application identity is meant
    session -> ApplicationRun, Window, trace scope, or DA-26 workflow scope,
        depending on the intended current meaning

The useful part of the older recommendation is not old naming. The useful part is
this boundary:

    DA-25 artifacts package and preserve retained material. They do not add
    authority, redefine committed state, define payload identity, define
    persistent-I/O authority, define Window finalization, or define DA-26 workflow
    outcomes.

01B. DOCUMENT-METADATA LEAKAGE CHECK
==============================================================================

The final DA-25 document should read as architecture documentation, not as audit,
version, or rewrite-process metadata.

Do not include statements such as:

    - This is V3 design.
    - In V3, Minimal Audit Bundle is non-authoritative.
    - The new design moved Replay to DA-26.
    - This rewrite clarified digest semantics.
    - Unlike V2, export does not add authority.
    - Codex kept Orchestration Unit wording.
    - This audit decided DA-25 should not own Replay.
    - DA-25 was rewritten because of the audit.

Those facts may be useful in audit files, migration notes, compatibility notes,
branch notes, changelogs, or explicitly historical documents. They do not belong
in the architecture document itself.

The final DA-25 should simply define WindowManifest, SafePointWindowManifest,
AbortedWindowManifest, WindowExport, SafePointWindowExport,
AbortedWindowExport, Minimal Audit Bundle, optional digest fields, offline
inspection, partial export, missing material, unsupported behaviors, open
questions, and locked summary.

==============================================================================
02. WHAT DA-25 GETS RIGHT
==============================================================================

02.1. Artifact representation does not add authority
----------------------------------------------------

DA-25 correctly says authority derives from finalized Window kind and retained
roots represented by the artifact, not from manifest existence, export existence,
archive format, packaging format, digest, filename, or presentation format.

Preserve this strongly.

02.2. DA-25 consumes DA-08 finalized Window semantics
-----------------------------------------------------

DA-25 correctly says it consumes finalized Window semantics from DA-08 and does
not redefine the Window model, SafePointWindow, ActiveWindow, AbortedWindow, or
Window finalization semantics.

Preserve this.

02.3. WindowManifest semantics are strong
-----------------------------------------

DA-25 correctly says a WindowManifest is immutable, represents exactly one
finalized Window, never represents an ActiveWindow, and is exactly one of
SafePointWindowManifest or AbortedWindowManifest.

Preserve this.

02.4. SafePointWindowManifest authority is scoped correctly
-----------------------------------------------------------

DA-25 correctly says a SafePointWindowManifest includes committedStateRoot and
that optional roots such as traceRoot, journalRoot, revisionRoot, and mabRoot are
non-authoritative evidence roots.

Preserve this.

02.5. AbortedWindowManifest is non-authoritative abort evidence
---------------------------------------------------------------

DA-25 correctly says an AbortedWindowManifest has no committedStateRoot and does
not become authoritative merely because it is finalized and immutable.

Preserve this.

02.6. WindowExport changes portability, not semantics
-----------------------------------------------------

DA-25 correctly says a WindowExport is portable immutable serialization of one
WindowManifest closure, export does not add authority, and export does not imply
replayability, resumability, or evidence completeness.

Preserve this.

02.7. SafePointWindowExport restoration boundary is strong
----------------------------------------------------------

DA-25 correctly says a SafePointWindowExport is only a deterministic restoration
artifact when required committed-state material is present.

It correctly says a partial SafePointWindowExport lacking required committed-state
material is not a deterministic restoration artifact.

Preserve this.

02.8. AbortedWindowExport is not restoration or replay proof
------------------------------------------------------------

DA-25 correctly says an AbortedWindowExport remains non-authoritative evidence,
is not a restoration artifact, and is not replay proof.

Preserve this.

02.9. Minimal Audit Bundle is non-authoritative evidence
--------------------------------------------------------

DA-25 correctly says Minimal Audit Bundle is not authoritative state, not a
WindowManifest, not a restoration artifact, not a replay guarantee, and not a
completeness guarantee.

Preserve this strongly.

02.10. Minimal Audit Bundle excludes live handles and executable authority
-------------------------------------------------------------------------

DA-25 correctly excludes transactional layers, uncommitted mutations, executable
code, capability implementations, secrets/credentials, live Job handles, live
OrchestrationUnit handles, live adapter handles, and live RPC channels/transports.

Preserve this.

02.11. Optional digest semantics are strong
-------------------------------------------

DA-25 correctly says optional digest fields are accelerators for comparison and
inspection work, not identities and not authority.

Preserve this.

02.12. Offline inspection boundaries are strong
-----------------------------------------------

DA-25 correctly says offline inspection resolves retained material and decodes
retained values without running Turnix orchestration logic, does not require
capability calls, treats retained evidence as evidence only, and does not control
original Jobs, OrchestrationUnits, adapters, RPC transports, Views, or frontends.

Preserve this.

02.13. Missing material is explicit
-----------------------------------

DA-25 correctly says partial export policy is explicit, missing material is
explicit, missing material does not silently become Equal, NotEqual, complete, or
authoritative, and export presentation does not hide missing-material markers.

Preserve this.

==============================================================================
03. REQUIRED FIX: ORCHESTRATIONUNIT TERMINOLOGY
==============================================================================

DA-25 still uses spaced `Orchestration Unit` wording in several places.

Normalize to:

    OrchestrationUnit

where the first-class current architecture type is meant.

Preserve these semantics:

    - retained OrchestrationUnit lifecycle evidence may be included as evidence
    - live OrchestrationUnit execution handles are not exported
    - offline inspection of retained OrchestrationUnit evidence does not resume,
      cancel, supersede, or control the original OrchestrationUnit
    - retained OrchestrationUnit evidence remains non-authoritative unless it is
      also committed state under DA-04

DA-24 owns OrchestrationUnit lifecycle and mutation-authority semantics.

DA-25 may package retained OrchestrationUnit evidence, but does not define
OrchestrationUnit behavior.

==============================================================================
04. DA-05 PAYLOAD / VALUEREF BOUNDARY
==============================================================================

DA-25 correctly references payload identity, ChunkId, and ValueRef as outside its
scope.

Preserve and strengthen this boundary when retained payload, decode, export
closure, or offline inspection wording is touched:

    DA-25 may name retained payload references, retained committed-state
    closures, exported payload material, missing external payload material, and
    offline decode behavior.

    DA-25 does not define payload identity, Chunk, ChunkId, ValueRef, decode,
    integrity, or retained value representation contracts.

    DA-05 owns those meanings.

    A WindowExport containing value material does not make export identity the
    same thing as payload identity or committed-state identity.

==============================================================================
05. DA-07 PERSISTENT-I/O BOUNDARY
==============================================================================

DA-25 correctly says it does not define concrete persistent I/O authority,
Readers, Writers, or filesystem rules.

Preserve and strengthen this boundary when export tooling, packaging, archive,
streaming, or offline material loading is touched:

    DA-25 defines artifact and export semantics.

    DA-25 does not define persistent-I/O authority, Reader/Writer providers, root
    boundaries, filesystem rules, backup/snapshot mechanics, streaming I/O, or
    storage safety.

    DA-07 owns those meanings.

    Export packaging does not bypass persistent-I/O authority.

==============================================================================
06. DA-08 WINDOW BOUNDARY
==============================================================================

DA-25 begins after Window finalization.

Preserve this boundary:

    DA-25 owns artifact and export semantics derived from finalized Windows.

    DA-08 owns Window kind, Window ordering, ActiveWindow, SafePointWindow,
    AbortedWindow, Window finalization, and finalized runtime history semantics.

    DA-25 does not define when a SafePointWindow or AbortedWindow exists.

    DA-25 does not make an ActiveWindow exportable as a finalized Window artifact.

    A WindowManifest represents exactly one finalized Window.

==============================================================================
07. DA-26 WORKFLOW BOUNDARY
==============================================================================

DA-25 artifacts can be inputs to DA-26 workflows, but DA-25 does not own those
workflow outcomes.

Preserve this boundary:

    DA-25 defines artifact/export representation and offline inspection
    boundaries.

    DA-26 defines equality modes, ComparisonResult, Replay, Resume, Retry, and
    audit workflow semantics.

    A WindowManifest, WindowExport, Minimal Audit Bundle, digest, partial-export
    marker, or missing-material marker may affect DA-26 workflow outcomes, but it
    does not define those outcomes by itself.

Do not let DA-25 define Equal, NotEqual, Replay eligibility, Resume eligibility,
Retry semantics, or audit workflow status.

==============================================================================
08. MINIMAL AUDIT BUNDLE CORRELATION TERMINOLOGY
==============================================================================

The target already uses ApplicationRun in Minimal Audit Bundle correlation
metadata, which is good.

Still normalize remaining adjacent wording:

    Orchestration Unit -> OrchestrationUnit

If any old examples reintroduce AppInstance or session in Minimal Audit Bundle
correlation metadata, translate them to current concepts:

    ApplicationRun:
        live runtime incarnation correlation

    Application:
        durable application identity correlation

    SaveBundle:
        durable persistence closure / saved Application correlation

    Window:
        finalized Window or retained Window artifact correlation

Do not use session as a current architecture identity unless DA-26 explicitly
retains it as a compatibility/audit-workflow term.

==============================================================================
09. DIGEST WATCH
==============================================================================

Preserve digest semantics:

    - digest fields are optional
    - digest fields are comparison accelerators
    - digest fields are not identities
    - digest fields do not add authority
    - a digest type is emitted only when canonical serialization rules for that
      digest type are defined
    - each digest category keeps a distinct comparison scope
    - digest canonicalization must not redefine DA-04 committed-state truth
    - digest canonicalization must not redefine DA-05 payload identity or
      committed-value representation
    - digest canonicalization must not redefine DA-07 storage identity
    - digest semantics do not bypass DA-26 equality and ComparisonResult rules

Concrete digest algorithms and exact canonical serialization remain implementation
specification territory unless explicitly fixed.

==============================================================================
10. PARTIAL EXPORT AND MISSING MATERIAL WATCH
==============================================================================

Preserve partial-export and missing-material semantics:

    - partial export policy is explicit
    - partial export policy is represented in the exported artifact
    - missing material is explicit
    - missing material reason category is explicit enough to distinguish policy
      pruning, partial export, corruption, unavailable external payload,
      unsupported format, and intentionally omitted sensitive material
    - missing material does not silently become Equal, NotEqual, complete, or
      authoritative
    - missing material affects inspection/comparison according to DA-26 workflow
      semantics
    - export presentation does not hide missing-material markers
    - export tools preserve missing-material markers when repackaging or
      transforming retained artifacts

Do not let missing-material taxonomy become DA-05 payload identity taxonomy or
DA-07 persistent-I/O error taxonomy.

==============================================================================
11. TRACE WORDING
==============================================================================

Follow the DA-03 cross-document trace wording check.

DA-25 consumes retained trace evidence and may require trace-backed artifact
interpretation.

Trace retention, trace pruning, trace loss, event structure, trace DAG semantics,
span mechanics, and trace storage semantics remain owned by DA-03.

DA-25 trace requirements are artifact/export-domain emission obligations where
DA-25-owned artifact creation, export creation, Minimal Audit Bundle creation,
partial export, missing material, corruption, unsupported format, omitted
sensitive material, digest emission, or offline inspection failure occurs in a
running Turnix context.

Do not let artifact/export trace wording imply that trace evidence is committed
state or that trace persistence is guaranteed forever.

==============================================================================
12. WHAT TO PRESERVE FROM CURRENT DA-25
==============================================================================

Preserve these boundaries, translating stale terminology where present:

    - DA-25 owns artifact and export semantics derived from finalized Windows
    - DA-25 consumes DA-08 Window finalization semantics
    - artifact representation does not add authority
    - exported form changes portability, not semantics
    - offline inspection reads retained artifact contents and does not run Turnix
      orchestration logic
    - missing/pruned/corrupt/partial/unavailable retained material is explicit
    - WindowManifest is immutable and represents exactly one finalized Window
    - WindowManifest never represents ActiveWindow
    - SafePointWindowManifest includes committedStateRoot
    - optional roots are non-authoritative evidence roots
    - AbortedWindowManifest has no committedStateRoot
    - AbortedWindowManifest is non-authoritative abort evidence
    - WindowExport is portable immutable serialization of one WindowManifest
      closure
    - WindowExport is SafePointWindowExport or AbortedWindowExport
    - WindowExport does not add authority
    - WindowExport does not imply replayability, resumability, or completeness
    - SafePointWindowExport lacking required committed-state material is not a
      deterministic restoration artifact
    - AbortedWindowExport is not a restoration artifact and not replay proof
    - Minimal Audit Bundle is non-authoritative evidence
    - Minimal Audit Bundle is not authoritative state, WindowManifest,
      restoration artifact, replay guarantee, or completeness guarantee
    - Minimal Audit Bundle does not contain executable code, capability
      implementations, secrets/credentials, or live handles
    - optional digest fields are comparison accelerators only
    - offline inspection does not control original runtime participants
    - partial export and missing material remain explicit
    - DA-26 owns equality modes, ComparisonResult, Replay, Resume, Retry, and

==============================================================================
13. WHAT TO ADD OR CHANGE IN THE REVISED DA-25
==============================================================================

13.1. Normalize OrchestrationUnit
---------------------------------

Use OrchestrationUnit consistently where the first-class type is meant.

13.2. Preserve DA-05 and DA-07 stop-lines
-----------------------------------------

Keep or strengthen the payload/ValueRef and persistent-I/O boundaries from
sections 04 and 05.

13.3. Preserve DA-08 and DA-26 stop-lines
-----------------------------------------

Keep DA-25 scoped after Window finalization and before comparison/replay/resume/
retry workflow outcomes.

13.4. Keep Minimal Audit Bundle non-authoritative
-------------------------------------------------

Keep this explicit because the name may sound stronger than its semantics.

13.5. Keep digest semantics narrow
----------------------------------

Keep digest fields optional, non-authoritative, and scoped to comparison
acceleration.

13.6. Keep missing-material markers explicit
--------------------------------------------

Do not hide missing material in presentation, export, repackaging, or offline
inspection.

13.7. Keep implementation details open
--------------------------------------

Do not define concrete packaging format, concrete archive format, exact digest
algorithms, canonical serialization, missing-material taxonomy, export storage,
retained material decoding implementation, or audit-tooling evidence presentation
unless an owning implementation specification fixes them.

==============================================================================
16. FINAL EDITOR INSTRUCTION
==============================================================================

Keep DA-25.

Do not perform a heavy conceptual rewrite.

Do perform targeted terminology and owner-boundary fixes:

    - normalize Orchestration Unit to OrchestrationUnit
    - preserve DA-05 ownership of payload identity, Chunk, ChunkId, ValueRef,
      decode, integrity, and retained value representation
    - preserve DA-07 ownership of persistent-I/O authority and storage mechanics
    - preserve DA-08 ownership of Window kind, Window ordering, and Window
      finalization
    - preserve DA-26 ownership of equality modes, ComparisonResult, Replay,
      Resume, Retry, and audit workflows
    - preserve Minimal Audit Bundle as non-authoritative evidence only
    - preserve optional digests as comparison accelerators only
    - preserve explicit partial-export and missing-material behavior

Use REWRITE-DA-25 only as translated boundary-preservation guidance. Do not copy
process metadata or obsolete wording into the final DA.

Do not include audit/source metadata or version/process framing in the final
DA-25 documentation. The final DA-25 should not say this is V3 design, in V3,
new design, old design, rewritten design, created by Codex, decided by audit, or
part of a rewrite-history process.

DA-25 should remain the Window artifact, WindowManifest, WindowExport, Minimal
Audit Bundle, optional digest, partial export, missing-material, and offline
inspection boundary document.

DA-25 should not become:

    - committed-state authority specification
    - payload identity / ValueRef / Chunk representation specification
    - persistent-I/O authority specification
    - Window finalization specification
    - trace substrate specification
    - Job lifecycle specification
    - OrchestrationUnit lifecycle or mutation-authority specification
    - equality / ComparisonResult specification
    - Replay / Resume / Retry / audit workflow specification
    - concrete packaging / archive / digest / canonical serialization
      implementation specification

The main work is to preserve DA-25's strong artifact/export boundary model while
normalizing current terminology and preventing export, Minimal Audit Bundle,
digest, missing-material, and offline-inspection semantics from becoming hidden
authority paths.
