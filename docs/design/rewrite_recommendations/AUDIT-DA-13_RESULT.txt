==============================================================================
01. VERDICT
==============================================================================

Recommendation verdict:
    Superseded by Proposal P02 in its SavePack/AppInstance vocabulary; useful
    only as translated boundary-preservation guidance.

    The recommendation correctly preserves DA-13's main semantic model:
    dependencies are hard functional requirements, shared pack-specifier syntax
    does not imply shared semantics, the `packs` field means hard dependencies
    only, dependency context adds policy above DA-11 generic resolution, dependency
    sources are mutually exclusive, GlobalNormal ordering is scoped, provider
    roles are not capability calls, advisory relations are hints, ambiguity
    requires external involvement, dependency failures are explicit, and
    last-known-good is not dependency-resolution fallback.

    However, the recommendation still frames SaveOnly, GlobalPinned, copied
    material, selected graph, and LKG storage around SavePack/AppInstance. Use it
    only after translating those ideas into SaveBundle/Application/ApplicationRun
    terminology.

Document verdict:
    Keep with targeted terminology and source-boundary fixes.

DA-13 is architecturally strong as the dependency declaration and dependency-
specific resolution policy document.

No heavy conceptual rewrite is recommended.

The main required fixes are:

    - replace SavePack vocabulary with SaveBundle-aware dependency-source wording
    - replace AppInstance vocabulary with Application/ApplicationRun where needed
    - clarify SaveOnly as SaveBundle-local copied/retained Pack material, not a
      SavePack Pack-kind model
    - clarify GlobalPinned as SaveBundle graph/pin evidence, not SavePack metadata
    - clarify last-known-good storage as SaveBundle/Application graph evidence or
      activation/recovery evidence, not SavePack-only state
    - keep GlobalNormal root precedence scoped to ordinary global dependency
      resolution only
    - keep provider roles separate from runtime capability invocation and
      capability permission
    - keep advisory relations as hints used by PackManager/UI, not dependency or
      activation authority
    - add missing owner stop-lines for DA-20 / DA-29 and SaveBundle documents
    - avoid final-document version/process metadata leakage

Primary conclusion:
    Keep DA-13, but rewrite it out of the SavePack/AppInstance layer. DA-13
    should remain the dependency contract, dependency-context PackRequest,
    dependency-source policy, version/fingerprint enforcement, provider-role,
    advisory relation, ambiguity, failure, and LKG-boundary document.

==============================================================================
01A. OBSOLETE-PRESERVATION CHECK
==============================================================================

DA-13 should not keep older terminology as a historical artifact.

Specifically, the rewrite should not preserve:

    - SavePack as the durable persistence object
    - SavePack copied material as if SavePack were a Pack kind
    - SavePack metadata as the canonical source of copied/pinned dependency state
    - copied SavePack material as ordinary GlobalNormal material
    - AppInstance as runtime identity vocabulary
    - durable AppInstance state as graph authority vocabulary
    - first-registered-provider behavior without deterministic/scoped/traceable
      ownership rules
    - last-known-good as a dependency-resolution fallback
    - advisory relations as hard dependencies, activation blockers, loader rules,
      or PackManager repair authority

If a legacy alias is intentionally retained, DA-13 should say so explicitly and
should still state the canonical architecture term as primary.

Otherwise, the old names should be removed or translated.

The useful part of the old recommendation is not the old terminology. The useful
part is the dependency boundary:

    Dependencies are hard contracts. Dependency-resolution sources are mutually
    exclusive. Save-local, pinned, and ordinary global dependency sources remain
    source-specific. Advisory relations remain hints. Provider roles remain
    dependency/resolution-layer declarations, not runtime capability calls.

==============================================================================
01B. DOCUMENT-METADATA LEAKAGE CHECK
==============================================================================

The final DA-13 document should read as architecture documentation, not as audit,
version, or rewrite-process metadata.

Do not include statements such as:

    - This is V3 design.
    - In V3, SaveBundle replaces SavePack.
    - The new design uses Proposal P02.
    - This rewrite changed dependency-source terminology.
    - Unlike V2, DA-13 now uses SaveBundle.
    - Codex kept SavePack wording.
    - This audit decided to use ApplicationRun.
    - DA-13 was rewritten because of the audit.

Those facts may be useful in audit files, branch notes, migration notes,
compatibility notes, changelogs, or editor instructions. They do not belong in
the architecture document itself.

The final DA-13 should simply define dependency contracts, PackRequest meaning in
dependency context, accepted-entry normalization, dependency-source policy,
version/fingerprint enforcement, GlobalNormal ordering, provider roles, advisory
relations, ambiguity handling, failure classification, and last-known-good
activation/recovery boundary.

==============================================================================
02. WHAT DA-13 GETS RIGHT
==============================================================================

02.1. Dependencies as hard contracts
------------------------------------

DA-13 correctly says a dependency expresses a hard functional requirement.

It correctly says dependencies are contracts, not preferences.

It correctly says failure to satisfy a hard dependency is a hard failure unless an
explicit accepted policy or user decision from the owning decision layer resolves
it.

Preserve this.

02.2. Shared pack-specifier syntax does not imply shared semantics
------------------------------------------------------------------

DA-13 correctly says hard dependency fields, advisory fields, and role-related
fields may reuse the same pack-specifier structure while producing different
higher-level meaning.

Preserve this.

02.3. `packs` field means hard dependencies only
------------------------------------------------

DA-13 correctly says absence of `packs` means no hard dependencies, an empty list
means explicitly no hard dependencies, every entry under `packs` is a hard
dependency, and list order carries no semantic meaning by itself.

Preserve this.

02.4. DA-11 / DA-13 split is strong
-----------------------------------

DA-13 correctly says DA-11 owns PackRequest grammar and generic resolution
mechanics, while DA-13 owns how PackRequest is interpreted when the requesting
relationship is a dependency.

Preserve this.

02.5. Accepted-entry normalization and fingerprint rules are strong
------------------------------------------------------------------

DA-13 correctly preserves name-only, versioned, and exact-version-plus-fingerprint
forms where allowed by field semantics.

It correctly says fingerprint requires exact concrete version and is not a vague
compatibility hint.

Preserve this.

02.6. Dependency-resolution source exclusivity is strong
--------------------------------------------------------

DA-13 correctly defines three mutually exclusive dependency-resolution sources:

    - SaveOnly
    - GlobalPinned
    - GlobalNormal

It correctly says the resolver does not mix or silently fall back between those
sources.

Preserve this source exclusivity, but rewrite the source meanings around
SaveBundle rather than SavePack.

02.7. GlobalNormal ordering is deterministic and scoped
-------------------------------------------------------

DA-13 correctly defines deterministic GlobalNormal selection:

    1. version handling
    2. author relationship ordering
    3. root precedence
    4. final lexicographic tie-break

It correctly says no scoring model exists and silent substitution is forbidden.

Preserve this.

02.8. Provider roles are not runtime capability calls
-----------------------------------------------------

DA-13 correctly says requiredRoles and providedRoles are dependency/resolution-
layer declarations, not runtime capability invocation semantics.

It correctly says providedRoles does not itself grant capability permission.

Preserve this.

02.9. Advisory relations are hints
----------------------------------

DA-13 correctly says supportedPacks, conflictingPacks, and recommendedPacks are
advisory pack-relation metadata.

It correctly says advisory relations are not hard dependencies, hard activation
blockers, generic resolution constraints, or loader/runtime warning rules by
themselves.

Preserve this.

02.10. Ambiguity and failure handling are strong
------------------------------------------------

DA-13 correctly says ambiguity is surfaced explicitly, requires user decision or
accepted policy input, and does not permit resolver guessing.

It correctly says dependency-resolution failure is explicit, classified,
observable, and never silently resolved by fallback.

Preserve this.

02.11. Last-known-good boundary is good but needs SaveBundle wording
--------------------------------------------------------------------

DA-13 correctly says last-known-good is not consulted during dependency
resolution and is used only after activation failure.

Preserve this boundary.

Rewrite the storage/source wording so it does not say LKG is stored per SavePack
as the architecture object unless a compatibility alias is explicitly retained.

==============================================================================
03. MAJOR REQUIRED FIX: SAVEBUNDLE-BASED DEPENDENCY SOURCE MODEL
==============================================================================

The current DA-13 still says:

    SaveOnly applies when the dependency's packTreeId is listed in SavePack
    metadata as copied.

    only copied packs inside that SavePack are eligible

    saved packs are owned by the SavePack

    GlobalPinned applies when the dependency is bound to a pin in SavePack
    metadata

    GlobalNormal does not consult SavePack content

Proposal P02 changes the durable persistence object to SaveBundle. SaveBundle is
not a Pack.

DA-13 should preserve the source-policy model but translate the source objects.

03.1. SaveOnly -> SaveBundle-local copied or retained Pack material
-------------------------------------------------------------------

Recommended model:

    SaveOnly applies when the dependency's packTreeId is listed in the relevant
    SaveBundle graph evidence, retained Pack material, copied Pack material, or
    accepted graph metadata as SaveBundle-local copied/retained material.

    Under SaveOnly:

        - only copied/retained Pack material local to that SaveBundle/Application
          context is eligible
        - the ordinary global registry is not consulted
        - absence of the copied/retained local Pack material is a hard error

    SaveBundle-local Pack material:

        - is identified by full Pack identity when available
        - is associated with the SaveBundle/Application context
        - is immutable unless explicitly replaced by SaveBundle/persistence rules
        - is visible only within that SaveBundle/Application context unless another
          owning document explicitly says otherwise

Do not say SaveBundle itself is a Pack.

03.2. GlobalPinned -> SaveBundle graph pin / accepted graph pin
---------------------------------------------------------------

Recommended model:

    GlobalPinned applies when the dependency is bound to a pin in SaveBundle graph
    evidence, accepted dependency graph metadata, or another owning persistence /
    graph document.

    Under GlobalPinned:

        - only the pinned concrete Pack identity is eligible
        - resolution occurs in the global registry only
        - missing pinned identity is a hard error
        - the pin does not imply copying or saving

Pins express explicit historical or accepted-graph intent and bypass selector-
based candidate choice.

Do not let GlobalPinned fall back to GlobalNormal.

03.3. GlobalNormal remains ordinary global registry only
-------------------------------------------------------

Keep GlobalNormal as ordinary global registry dependency resolution.

Rewrite:

    SavePack content is not consulted

as:

    SaveBundle-local retained/copied Pack material is not consulted

unless the dependency source is SaveOnly.

GlobalNormal does not apply to:

    - SaveBundle-local copied/retained Pack material
    - GlobalPinned pinned identity
    - pinned graph identity
    - explicit selected graph semantics
    - accepted SaveBundle-local graph semantics

03.4. Root precedence is scoped to GlobalNormal
-----------------------------------------------

Keep custom > first-party > third-party only inside GlobalNormal.

Do not apply ordinary content-root precedence to SaveOnly or GlobalPinned.

Do not let ordinary content-root precedence override SaveBundle-local retained
Pack material or pinned dependency evidence.

==============================================================================
04. REQUIRED OWNER STOP-LINES
==============================================================================

DA-13 should stay the dependency semantics and dependency-source policy document.
It may name other domains to preserve stop-lines, but it should not define their
detailed behavior.

Recommended owner mapping:

    DA-03 owns trace substrate, trace DAG semantics, trace storage, trace
    retention, trace pruning, and trace loss.

    DA-09 owns root discovery boundaries and discovered candidate production.

    DA-10 owns Pack identity, hierarchy, indexing, visibility, and visibility
    semantics for retained Pack material.

    DA-11 owns PackRequest parsing grammar and generic resolution mechanics.

    DA-12 owns importing, module loading, and code-boundary rules.

    DA-14 owns activation lifecycle, activation failure behavior, and
    last-known-good activation/recovery semantics.

    DA-16 owns service, capability, permission, capability invocation, and
    Job-backed capability semantics.

    DA-17 owns user decision, ambiguity decision scope, remembered policy, and
    no-silent-broadening semantics.

    DA-20 owns Application/ApplicationRun lifecycle and runtime identity.

    DA-21 owns RPC, channel, and transport semantics.

    DA-23 owns ExecutionAdapter and runtime code execution boundaries.

    DA-24 owns OrchestrationUnit lifecycle and mutation-authority semantics.

    DA-28 owns RuntimeHost workspace ownership and command-surface semantics.

    DA-29 owns PackManager catalog presentation, advisory relation presentation,
    graph preparation, repair, load-list assistance, and PackManager-domain trace
    semantics.

    SaveBundle and persistence documents own SaveBundle storage format,
    compatibility, generation, retained material, ownership, copied Pack material,
    graph evidence, and loading details.

DA-13 may name these concepts when needed to protect dependency boundaries, but
it should not define their detailed behavior.

==============================================================================
05. PROVIDER-ROLE WATCH ITEM
==============================================================================

DA-13 says first registered provider wins by default and specific-provider
request may be used programmatically.

This remains a live watch item.

The final DA-13 should either:

    - explicitly leave provider registration/selection behavior to another owning
      provider/runtime document, or
    - constrain `first registered provider wins` strongly enough that it is
      deterministic, scoped, trace-visible, authority-safe, and not a capability
      permission bypass.

Provider/runtime documents must define:

    - what registered means
    - who may register providers
    - where provider registration lives
    - whether registration order is deterministic
    - whether activation order controls registration order
    - whether PackManager load-list order controls registration order
    - whether provider selection is trace-visible
    - whether provider selection grants capability-like power
    - whether specific-provider request bypasses policy or permission

Do not let provider-role metadata become runtime capability invocation or
permission authority.

==============================================================================
06. LAST-KNOWN-GOOD BOUNDARY
==============================================================================

DA-13 should preserve the LKG boundary:

    Dependency resolution always attempts fresh dependency resolution first.

    Last-known-good is not consulted during dependency resolution.

    Last-known-good fallback is used only after activation failure.

    LKG fallback is activation/recovery behavior, not dependency success.

Rewrite stale storage wording:

    Turnix stores the last successfully activated graph per SavePack.

into a SaveBundle/Application-aware form such as:

    Turnix may store last-known-good activation graph evidence for an Application
    or SaveBundle according to activation/recovery and persistence documents.

    DA-13 only states that this evidence is not a dependency-resolution fallback.

DA-14 owns the activation/recovery behavior and LKG fallback procedure.
SaveBundle/persistence documents own the durable storage of any retained graph
evidence.

==============================================================================
07. TRACE WORDING FIX
==============================================================================

DA-13 should preserve dependency-domain trace obligations but follow DA-03 trace
wording.

Correct reading:

    Dependency trace evidence is required as a domain emission obligation when
    dependency resolution occurs.

Not:

    Trace persistence is guaranteed forever.

Not:

    Dependency correctness depends on retained trace evidence.

Suggested wording:

    Dependency-resolution trace evidence is required as an emission obligation
    where dependency resolution occurs. Trace representation, retention, pruning,
    and loss remain governed by DA-03.

Trace evidence does not become committed state, SaveBundle truth, activation
success, dependency success, or PackManager decision truth by itself.

==============================================================================
08. WHAT TO PRESERVE FROM CURRENT DA-13
==============================================================================

Preserve these boundaries, but rewrite SavePack/AppInstance-era terms where
present:

    - Dependencies are hard functional requirements.
    - Dependencies are contracts, not preferences.
    - Failure to satisfy a hard dependency is a hard failure unless explicitly
      resolved by an owning policy/user decision layer.
    - Shared pack-specifier syntax does not imply shared semantics.
    - `packs` means hard dependencies only.
    - List order in `packs` carries no semantic meaning by itself.
    - DA-11 owns PackRequest grammar and generic resolution mechanics.
    - DA-13 owns dependency-context policy around PackRequest.
    - Accepted-entry normalization preserves exact-artifact fingerprint locks.
    - Fingerprint requires exact concrete version.
    - Dependency-resolution sources are mutually exclusive.
    - The resolver does not mix dependency-resolution sources silently.
    - The resolver does not silently fall back between dependency-resolution
      sources.
    - SaveOnly remains local copied/retained material only.
    - GlobalPinned remains pinned global identity only.
    - GlobalNormal remains ordinary global registry only.
    - GlobalNormal root precedence applies only to GlobalNormal.
    - Version and fingerprint enforcement remain hard.
    - GlobalNormal selection remains deterministic and scoped.
    - Provider roles are dependency/resolution-layer declarations.
    - requiredRoles is not runtime capability invocation.
    - providedRoles does not grant capability permission.
    - Advisory pack relations are hints.
    - Advisory relations are not hard dependencies or activation blockers.
    - PackManager may present advisory relation evidence but must not upgrade it
      into dependency authority.
    - Ambiguity requires external involvement.
    - The resolver does not guess.
    - Dependency failure is explicit, classified, observable, and not silent
      fallback.
    - Last-known-good is not dependency-resolution fallback.
    - Dependency is not activation.
    - Dependency resolution does not load code.
    - Dependency resolution does not grant runtime access.
    - Dependency resolution does not grant capability permission.

==============================================================================
09. WHAT TO ADD OR CHANGE IN THE REVISED DA-13
==============================================================================

09.1. Add canonical terminology note
------------------------------------

Add a compact note near the interpretation or concept section:

    DA-13 uses canonical architecture names:

        SaveBundle:
            durable persistence closure of an Application

        Application:
            durable application individual

        ApplicationRun:
            one live execution period of an Application

    Older notes may use SavePack or AppInstance. DA-13 does not use those names
    as primary architecture terms unless a compatibility note explicitly says so.

Do not write this as "V3 names", "new names", or "after the rewrite".

09.2. Rewrite dependency-source section
---------------------------------------

Rewrite SaveOnly / GlobalPinned / GlobalNormal source meanings around
SaveBundle-local retained/copied Pack material and SaveBundle/accepted-graph pin
evidence.

Do not classify SaveBundle as a Pack.

Do not make SaveBundle-local Pack material visible globally by default.

09.3. Rewrite LKG section
-------------------------

Replace per-SavePack LKG wording with SaveBundle/Application graph evidence
wording and defer activation/recovery behavior to DA-14.

09.4. Add owner stop-lines
--------------------------

Add DA-20, DA-29, and SaveBundle/persistence stop-lines if not already present.

DA-13 should not define Application/ApplicationRun lifecycle, PackManager repair,
or SaveBundle storage format.

09.5. Keep provider registration open or tightly scoped
-------------------------------------------------------

Do not let first-registered-provider semantics depend on unspecified activation
order or PackManager load-list order.

Leave it to an owning provider/runtime document unless the deterministic and
trace-visible registration rules are defined.

09.6. Keep exact implementation details open
--------------------------------------------

Do not define final manifest parser schema, PackRequest grammar, trace field
schema, provider registry implementation, user decision persistence schema,
PackManager UI behavior, SaveBundle storage format, or activation recovery
procedure in DA-13.

10. SPECIFIC PHRASE REPLACEMENTS
==============================================================================

Use these as a starting pass. Context still matters.

    SavePack
        -> SaveBundle where durable persistence closure is meant
        -> SaveBundle-local retained/copied Pack material where copied material
           is meant
        -> SaveBundle graph evidence / accepted graph evidence where pins or LKG
           graph state are meant

    SavePack copied material
        -> SaveBundle-local copied or retained Pack material

    copied packs inside that SavePack
        -> copied or retained Pack material local to that SaveBundle/Application
           context

    SavePack metadata
        -> SaveBundle graph evidence / SaveBundle metadata / accepted graph
           evidence, depending on exact meaning

    saved packs under this model are owned by the SavePack
        -> SaveBundle-local Pack material is associated with the
           SaveBundle/Application context and remains local unless another owning
           document explicitly says otherwise

    visible only within that save context
        -> visible only within that SaveBundle/Application context unless another
           owning document explicitly says otherwise

    SavePack content is not consulted
        -> SaveBundle-local retained/copied Pack material is not consulted

    copied SavePack material
        -> SaveBundle-local copied/retained Pack material

    Turnix stores the last successfully activated graph per SavePack
        -> Turnix may store last-known-good activation graph evidence for an
           Application or SaveBundle according to activation/recovery and
           persistence documents

    durable AppInstance state
        -> durable Application/SaveBundle state or ApplicationRun state,

    AppInstance lifecycle
        -> ApplicationRun lifecycle

    current Dv3 terminology / current Dv3 type names / current Dv3 names

    Any final-document wording like "In V3, SaveBundle..."
        -> replace with direct architecture language such as "SaveBundle..."

11. ACCEPTANCE CONDITIONS FOR THE REVISED DA-13
==============================================================================

A revised DA-13 is acceptable when all of the following are true:

    - It preserves dependencies as hard contracts.

    - It preserves advisory relations as hints only.

    - It preserves shared pack-specifier syntax as not shared semantics.

    - It preserves `packs` as hard dependencies only.

    - It preserves DA-11 / DA-13 split.

    - It preserves accepted-entry normalization and exact fingerprint locks.

    - It preserves hard dependency failure and no silent downgrade/substitution.

    - It preserves mutually exclusive dependency-resolution sources.

    - It preserves SaveOnly / GlobalPinned / GlobalNormal source boundaries.

    - It rewrites SaveOnly / GlobalPinned / GlobalNormal to use SaveBundle-aware
      terminology rather than SavePack as the durable object.

    - It states or implies that SaveBundle is not a Pack.

    - It keeps GlobalNormal precedence scoped to GlobalNormal only.

    - It prevents GlobalNormal precedence from overriding SaveBundle-local copied
      material, pinned dependency evidence, pinned graph identity, or explicit
      selected graph semantics.

    - It preserves version and fingerprint enforcement.

    - It preserves deterministic and scoped GlobalNormal selection.

    - It keeps provider roles separate from runtime capability invocation and
      capability permission.

    - It leaves provider registration/selection to the owning provider/runtime
      document unless deterministic, scoped, trace-visible rules are defined.

    - It preserves ambiguity as requiring external involvement and DA-17-scoped
      decisions.

    - It preserves dependency failure as explicit and classified.

    - It preserves last-known-good as activation/recovery fallback only, not
      dependency-resolution fallback.

    - It rewrites LKG storage wording out of the SavePack layer.

    - It keeps activation lifecycle and LKG fallback procedure DA-14-owned.

    - It keeps PackManager advisory presentation and graph preparation DA-29-owned.

    - It keeps Application/ApplicationRun lifecycle DA-20-owned.

    - It keeps SaveBundle storage, ownership, retained material, and graph
      evidence details owned by SaveBundle/persistence documents.

    - It keeps dependency-domain trace obligations as emission obligations and
      does not replace DA-03 trace substrate/retention/loss semantics.

    - It does not define concrete PackRequest grammar, generic resolution
      mechanics, trace field schema, provider registry implementation,
      PackManager UI behavior, SaveBundle storage format, or activation recovery
      procedure.

    - It does not mention audit provenance, rewrite process, old/new design, V3,
      Codex, candidate status, or branch history as ordinary architecture text.

==============================================================================
12. FINAL EDITOR INSTRUCTION
==============================================================================

Keep DA-13.

Do not perform a heavy conceptual rewrite.

Do perform a targeted rewrite of the dependency-source and LKG sections so the
text uses SaveBundle/Application/ApplicationRun terminology instead of
SavePack/AppInstance terminology.

Use REWRITE-DA-13 only as translated boundary-preservation guidance. Do not keep
it as an obsolete historical artifact and do not copy its stale SavePack or
AppInstance vocabulary into the rewritten DA.

Do not include audit/source metadata or version/process framing in the final
DA-13 documentation. The final DA-13 should not say this is V3 design, in V3,
new design, old design, rewritten design, created by Codex, decided by audit, or
part of a rewrite-history process.

DA-13 should remain the dependency declaration, dependency-context PackRequest,
accepted-entry normalization, dependency-source policy, version/fingerprint
enforcement, provider-role requirement, advisory relation, ambiguity handling,
failure-condition, and last-known-good boundary document.

DA-13 should not become:

    - Pack identity and visibility specification
    - generic resolution specification
    - importing/module-loading specification
    - activation lifecycle or recovery procedure specification
    - SaveBundle storage-format specification
    - Application/ApplicationRun lifecycle specification
    - PackManager operation or UI specification
    - capability invocation or permission specification
    - provider runtime registry implementation specification
    - Job lifecycle specification
    - RuntimeHost behavior specification
    - concrete trace schema/storage specification

The main work is to preserve DA-13's strong dependency semantics while migrating
fully out of the SavePack/AppInstance layer into the
SaveBundle/Application/ApplicationRun terminology where those concepts must be
named.
