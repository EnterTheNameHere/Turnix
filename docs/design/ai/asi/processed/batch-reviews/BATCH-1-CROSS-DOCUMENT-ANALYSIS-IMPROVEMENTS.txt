SUMMARY
-------
Batch 1 has a coherent foundation for index generation, provided the final ASI
indexes keep authority boundaries explicit.

The central Batch 1 pattern is that Turnix repeatedly separates:
- authority from evidence,
- committed state from delivery or presentation,
- concrete schema validity from semantic success,
- diagnostic tooling from runtime truth,
- implementation proximity from platform authority.

The highest-risk retrieval mistakes are concentrated around trace evidence,
committed state, RPC delivery, RPC schema completion, acknowledgements,
stateUpdate, and ODA-B diagnostic presentation terms.

CROSS_DOCUMENT_THEMES
---------------------
- THEME: Authority does not come from visibility, delivery, or presentation.
  DOCUMENTS: DA-01; DA-02; DA-03; DA-04; DA-21; IS-01; ODA-B
  INDEX_IMPROVEMENT: Preserve this as a relation-index theme. Many Batch 1
    traps are variations of this boundary.

- THEME: Trace evidence explains retained causality but does not define
    committed state.
  DOCUMENTS: DA-03; DA-04; ODA-B
  INDEX_IMPROVEMENT: Route trace-proof, causal-evidence, and diagnostic-evidence
    questions to DA-03 first; route state truth, committed mutation, restoration,
    transactions, and authoritative equality questions to DA-04.

- THEME: RPC delivery and schema validity are not successful work.
  DOCUMENTS: DA-21; IS-01; DA-04; DA-19 when Job details are needed
  INDEX_IMPROVEMENT: Keep acknowledgement, request acceptance, reply envelope,
    isComplete, final, stateUpdate, and job metadata distinct from Job success,
    operation success, work completion, and committed-state mutation.

- THEME: Diagnostic tooling consumes evidence without becoming authority.
  DOCUMENTS: ODA-B; DA-03; DA-04; DA-21; IS-01
  INDEX_IMPROVEMENT: Route tooling-presentation questions to ODA-B, but route
    underlying trace, state, RPC, schema, lifecycle, permission, adapter, or
    replay semantics to the owning DA or IS document.

- THEME: Platform truth is independent of current implementation surfaces.
  DOCUMENTS: DA-01; DA-02; DA-21; IS-01
  INDEX_IMPROVEMENT: Do not let current files, transports, frameworks, same
    language, same process, or message schema names define platform authority.

HIGH_RISK_CONFUSION_SETS
------------------------
- CONFUSION_SET: trace evidence / committed state / persisted state
  PRIMARY_OWNER: DA-04 for committed state
  SUPPORTING_OWNER: DA-03 for trace evidence
  PRESENTATION_OWNER: ODA-B for diagnostic surfaces
  RISK: Assistants may treat retained evidence, trace completeness, diagnostic
    presentation, or persisted bytes as state truth.
  RECOMMENDATION: Add explicit relation-index entries:
    DA-03 trace evidence not-authority-for DA-04 committed state.
    ODA-B diagnostic tooling not-authority-for DA-04 committed state.
    DA-04 persistence as protection separate-from concrete persistence and not
    the source of truth.

- CONFUSION_SET: stateUpdate / committed authoritative state mutation
  PRIMARY_OWNER: DA-04 for committed authoritative mutation
  SUPPORTING_OWNER: DA-21 for abstract update delivery
  CONCRETE_SCHEMA_OWNER: IS-01 for stateUpdate envelope type
  RISK: Assistants may infer state mutation from an update message or delivered
    payload.
  RECOMMENDATION: Preserve this as a top-level ASI trap. A query about the
    concrete stateUpdate message should load IS-01. A query about update flow
    should load DA-21. A query about whether committed state changed must load
    DA-04.

- CONFUSION_SET: isComplete / final / request success / work completion / Job
    success
  PRIMARY_OWNER: IS-01 for isComplete and final field meaning
  SUPPORTING_OWNER: DA-21 for request acceptance and message flow
  LIFECYCLE_OWNER: DA-19 when Job outcome is involved
  RISK: Assistants may interpret an envelope completion marker as semantic
    success.
  RECOMMENDATION: Index isComplete as an IS-01 schema term with strong negative
    relations to operation completion, request success, work completion, Job
    success, adapter readiness, AppInstance readiness, semantic correctness, and
    committed-state mutation.

- CONFUSION_SET: acknowledgement / request success / Job success
  PRIMARY_OWNER: DA-21 for abstract acknowledgement meaning
  CONCRETE_SCHEMA_OWNER: IS-01 for ack and ackOf fields
  LIFECYCLE_OWNER: DA-19 when Job outcome is involved
  RISK: Assistants may treat ack, ackOf, or reply delivery as successful work.
  RECOMMENDATION: Route "Does ack mean success?" to DA-21 first, then IS-01 for
    concrete schema, and DA-19 only when Job outcome is actually asked.

- CONFUSION_SET: ODA-B ERROR/WARNING/INFO / DA-03 trace event level
  PRIMARY_OWNER: ODA-B for tooling severity vocabulary
  SUPPORTING_OWNER: DA-03 for trace event level mechanics
  RISK: Assistants may merge presentation severity with trace event level
    taxonomy.
  RECOMMENDATION: Keep ODA-B severity values indexed only under diagnostic
    tooling presentation unless a future source explicitly maps them to DA-03
    trace levels.

- CONFUSION_SET: ODA-B trace-domain filters / canonical trace-domain authority
  PRIMARY_OWNER: DA-03 for trace field mechanics and subject-owning documents
    for domain-specific meaning
  PRESENTATION_OWNER: ODA-B for filter UI examples
  RISK: Assistants may treat a UI filter list as canonical taxonomy.
  RECOMMENDATION: Add relation-index entry: ODA-B trace-domain filters are
    presentation-only-for DA-03 and subject-owning documents.

- CONFUSION_SET: RuntimeHost / Kernel authority / platform truth
  PRIMARY_OWNER: DA-01 for highest-level authority ordering
  SUPPORTING_OWNER: DA-02 for RuntimeHost boundary position and implementation
    independence
  RISK: Assistants may treat RuntimeHost, current backend code, transport, or
    same-process implementation as platform authority.
  RECOMMENDATION: Route top-level authority questions to DA-01 and architecture
    boundary questions to DA-02; later concrete RuntimeHost mechanics should load
    DA-28 when available.

INDEX_GENERATION_RECOMMENDATIONS

  TARGET_INDEXES: ASI-04_BOUNDARY_AND_NON_OWNERSHIP_INDEX; ASI-05_RELATION_INDEX
  DETAILS: Batch 1 repeatedly defines non-ownership through negative relations:
    trace evidence not committed state, stateUpdate not committed mutation,
    isComplete not work completion, ack not Job success, diagnostics not runtime
    truth, same-language not same authority.

- RECOMMENDATION: Keep DA-03 and ODA-B diagnostic meanings separate.
  TARGET_INDEXES: ASI-01_DOCUMENT_DOMAIN_INDEX; ASI-02_TERM_INDEX;
    ASI-04_BOUNDARY_AND_NON_OWNERSHIP_INDEX
  DETAILS: DA-03 should own trace/evidence substrate semantics. ODA-B should own
    optional developer-facing presentation, reporting, and tooling behavior.

- RECOMMENDATION: Index IS-01 as concrete schema owner only.
  TARGET_INDEXES: ASI-01_DOCUMENT_DOMAIN_INDEX; ASI-02_TERM_INDEX;
    ASI-04_BOUNDARY_AND_NON_OWNERSHIP_INDEX
  DETAILS: IS-01 should be loaded for RPCMessage, isComplete, final, ackOf,
    stateUpdate, origin, lane, seq, and envelope fields, but not used to answer
    authority, lifecycle, Job success, permission, or committed-state questions
    without the owning DA document.

- RECOMMENDATION: Use paired load hints for compound traps.
  TARGET_INDEXES: ASI-03_RETRIEVAL_HINT_INDEX; ASI-05_RELATION_INDEX
  DETAILS:
  - "Are traces authoritative state?" -> DA-03 plus DA-04.
  - "Does stateUpdate mean state changed?" -> IS-01 plus DA-21 plus DA-04.
  - "Does ack mean success?" -> DA-21 plus IS-01; add DA-19 only for Job
    outcome.
  - "Does isComplete mean completion?" -> IS-01; add DA-21 or DA-19 only when
    request flow or Job outcome is involved.
  - "Are diagnostic ERROR/WARNING/INFO trace levels?" -> ODA-B plus DA-03.

- RECOMMENDATION: Keep DA-01 and DA-02 in foundation routing but avoid
    over-loading them.
  TARGET_INDEXES: ASI-01_DOCUMENT_DOMAIN_INDEX; ASI-03_RETRIEVAL_HINT_INDEX
  DETAILS: DA-01 is the project-level invariant and authority-order anchor.
    DA-02 is the platform truth, contract-boundary, and implementation
    independence anchor. Neither should replace concrete DA/IS documents for RPC,

  TARGET_INDEXES: ASI-00_ASSISTANT_SEMANTIC_INDEX_README; ASI-05_RELATION_INDEX
