SEMANTIC_ANCHORS
----------------
- Importing is explicitly not dependency declaration, resolution, adapter selection, execution authorization, activation, execution authority, or capability permission.
- Resolution answers which pack identity satisfies a request; importing answers how a code artifact is obtained once Turnix rules permit that step.
- Native imports remain allowed only for language internals, same-file/same-directory local code, and explicitly allowed Turnix platform surfaces.
- Cross-pack native Python imports are forbidden.
- Python pack code does not become backend authority through Python import behavior.
- Python cross-pack interaction happens through mediated APIs such as services, capabilities, pack metadata, resolvePack, and ensureActivated.
- JavaScript pack code runs in a browser environment with no Node.js assumptions, no filesystem access, no per-pack import maps, and no native cross-pack imports.
- turnixImport is a Turnix-aware resolver, controlled loader, and mediated ESM importer; it is not native import() and not a second independent resolution system.
- turnixImport selectors are identity-based, not filesystem paths, URIs, or semver-qualified references.
- Import selectors must remain consistent with the concrete identity already chosen during dependency resolution.
- Semver belongs to manifests, dependency resolution, and policy decisions, not to turnixImport selectors.
- Sub-entry import matching uses declared JavaScript entry mappings; ambiguous or missing matches are errors; no fallback to default entry exists.
- Default-entry import loads the declared default JavaScript entry; there is no implicit index.js, filename guessing, or directory guessing.
- ESM module evaluation caused by importing is not Turnix-recognized activation.
- resolvePack returns metadata/visibility resolution only; it does not load code, select an execution adapter, authorize execution, or activate.
- ensureActivated may trigger activation but does not return exports or symbols.
- Immediate execution and import-time side effects are discouraged and unsupported by Turnix guarantees.
- onLoad(ctx) is the only supported activation entrypoint and the first moment Turnix intentionally executes pack code.
- Background work started outside supported activation entrypoints, capability calls, or Turnix-defined orchestrated execution pathways remains unsupported, untracked, and outside Turnix cleanup/abort guarantees.
- Import errors are hard, visible, explainable errors and use the standard error envelope.
