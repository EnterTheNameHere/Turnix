PRIMARY_DOMAINS
---------------

- Logical message categories: control, request, emit, reply, error, subscription, cancellation, state/update, and acknowledgement.

- Request acceptance, accepted-work responses, and correlation across Job-backed, adapter-mediated, and RuntimeHost-owned work.

- Relationship between DA-level RPC semantics and concrete implementation specifications.

OWNERSHIP_HINTS
---------------
- Owns RPC as a logical communication boundary.
- Owns the distinction that RPC is not WebSocket, JSON, transport, capability authority, adapter authority, RuntimeHost authority, or Job lifecycle.
- Owns RPCChannel as the transport-neutral interface consumed by the RPC host or equivalent runtime owner.
- Owns the abstract separation between transport, channel, transport adapter, execution adapter, and RuntimeHost entry surface.
- Owns abstract RPC message categories and their high-level message-flow meaning.
- Owns abstract routing, acknowledgement, request acceptance, emit, subscribe, unsubscribe, cancellation, timeout, and disconnect distinctions.
- Owns RPC acceptance and correlation relations for Job-backed, adapter-mediated, and RuntimeHost-operation work.
- Owns the boundary that state/update message delivery does not by itself define committed authoritative state mutation.
- Owns RPC trace-observable message-flow categories and the correlation context expected from RPC evidence.

SEMANTIC_ANCHORS
----------------
- RPC is a logical communication boundary, not WebSocket, JSON, a transport, capability authority, adapter authority, RuntimeHost authority, or Job lifecycle.
- A transport carries RPC messages but does not define RPC semantics.
- RPCChannel is the transport-neutral surface used by the RPC host or equivalent runtime owner.
- A transport adapter translates concrete transport events into RPCChannel events but does not gain authority merely by carrying RPC messages.
- Message delivery, acknowledgement, request acceptance, handler execution, Job creation, and Job terminal outcome are distinct events.
- Successful message delivery is not successful work completion.
- Transport failure is not Job failure.
- Acknowledgement confirms message receipt or transport-level handling only.
- Acknowledgement does not imply request success, capability execution, adapter execution, Job creation, or Job success.
- Request acceptance means the request crossed the RPC dispatch boundary and was accepted by the target operation.
- Request acceptance is not final operation success unless the operation contract explicitly defines successful acceptance as the result.
- Routing identifies a logical target but does not grant permission, activate packs, select or authorize execution adapters, or bypass capability mediation.
- State/update message delivery does not by itself define committed authoritative state mutation; DA-04 owns committed-state authority.
- DA-21 owns RPC acceptance/correlation relations for Job-backed work; DA-19 owns Job lifecycle and terminal outcome semantics.
- DA-21 owns RPC acceptance/correlation relations for adapter-mediated work; DA-23 owns adapter lifecycle and execution-boundary outcome semantics.
- DA-21 owns RPC acceptance/correlation relations for RuntimeHost operations; DA-28 owns RuntimeHost command, operation, entry-surface, workspace, LAN, and lifecycle semantics.
- Transport timeout and disconnect are RPC/channel/transport concerns, not Job, adapter, or RuntimeHost terminal outcomes by themselves.
- RPC cancellation is a request, not a direct execution kill.
- Unsubscribe withdraws delivery interest and does not by itself cancel underlying work.
- Subscription delivery may carry Job, adapter, RuntimeHost, or state evidence, but the reported domain meaning remains owned by the relevant domain document.
- RPC trace evidence preserves correlation between messages and higher-domain events when those events exist.

CONFUSABLE_TERMS
----------------
- TERM_A: RPC
  TERM_B: WebSocket
  DISTINCTION: RPC is the logical communication boundary; WebSocket is one concrete transport whose concrete flow belongs to IS-02.

- TERM_A: RPC
  TERM_B: JSON envelope
  DISTINCTION: DA-21 owns abstract RPC semantics; concrete JSON envelope fields belong to IS-01.

- TERM_A: RPCChannel
  TERM_B: transport
  DISTINCTION: RPCChannel is the transport-neutral interface; transport is the concrete carrier adapted into that interface.

- TERM_A: transport adapter
  TERM_B: execution adapter
  DISTINCTION: Transport adapters translate concrete transport events into RPCChannel events; execution adapter boundary semantics belong to DA-23.

- TERM_A: transport adapter
  TERM_B: RuntimeHost entry surface
  DISTINCTION: A transport adapter adapts carriers into RPCChannel events; RuntimeHost entry-surface semantics belong to DA-28 even if one implementation participates in both roles.

- TERM_A: acknowledgement
  TERM_B: request success
  DISTINCTION: Acknowledgement confirms receipt or transport/RPC handling only; request success depends on the operation contract.

- TERM_A: acknowledgement
  TERM_B: Job success
  DISTINCTION: Acknowledgement does not imply Job creation or Job terminal success.

- TERM_A: request acceptance
  TERM_B: final operation success
  DISTINCTION: Acceptance means crossing the RPC dispatch boundary and target acceptance, not final success unless the operation contract defines that result.

- TERM_A: state or update messages
  TERM_B: committed state mutation
  DISTINCTION: State/update delivery through RPC does not by itself define authoritative committed-state mutation; load DA-21 for delivery flow and DA-04 for committed-state authority.

- TERM_A: subscription delivery
  TERM_B: reported domain meaning
  DISTINCTION: Subscription delivery may carry domain evidence, but Job, adapter, RuntimeHost, and committed-state meanings remain owned by their domain documents.

- TERM_A: transport timeout
  TERM_B: Job timeout
  DISTINCTION: Transport timeout is an RPC/channel/transport concern; Job timeout is a Job lifecycle concern owned by DA-19.

- TERM_A: transport disconnect
  TERM_B: Job cancellation
  DISTINCTION: Disconnect does not automatically cancel, supersede, discard, or fail Job-backed work.

- TERM_A: transport disconnect
  TERM_B: adapter failure / RuntimeHost failure
  DISTINCTION: Disconnect does not automatically fail an adapter or stop/fail a RuntimeHost; DA-23 or DA-28 owns those lifecycle outcomes.

- TERM_A: RPC cancellation
  TERM_B: direct execution kill
  DISTINCTION: RPC cancellation is a request translated into the owning lifecycle domain when applicable; it does not directly kill arbitrary execution.

- TERM_A: unsubscribe
  TERM_B: cancellation of underlying work
  DISTINCTION: Unsubscribe withdraws delivery interest; it cancels underlying work only if operation contract or policy explicitly connects them.
