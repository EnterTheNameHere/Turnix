----------------

- RuntimeHost trace schema answers which concrete fields identify RuntimeHost-domain trace evidence across host lifecycle, workspace ownership, commands, startup modes, clients, LAN exposure, and host-level operations.
- RuntimeHost trace schema provides field vocabulary, not trace event storage, trace DAG semantics, span mechanics, or trace reason meanings.
- DA-03-owned substrate fields retain DA-03 meaning when used by RuntimeHost-domain trace records.
- RuntimeHost-domain fields are represented as trace attributes unless a later trace serialization implementation specification defines a direct serialized mapping.
- Field grouping organizes schema and implementation clarity; it does not create separate trace event classes by itself.
- One RuntimeHost-domain trace record may contain fields from multiple groups when an event crosses domains.
- Fields from another domain may appear only as correlation fields unless the owning domain document permits more detailed inclusion.
- sourceDomain is RuntimeHost for RuntimeHost-domain trace records.
- runtimeHostId remains distinct from workspaceId, commandId, startupRequestId, runtimeOperationId, clientConnectionId, appInstanceId, jobId, orchestrationUnitId, viewId, adapter identity, RPC message identity, transactionId, and decisionId.
- read-only inspection uses accessMode rather than ownershipMode.
- commandStatus, startupStatus, and runtimeOperationStatus remain distinct.
- cross-domain correlation fields do not transfer authority or semantic ownership into RuntimeHost trace evidence.
- transport and channel fields are correlation fields and do not redefine DA-21 semantics.
- extension fields do not redefine IS-07 base fields, DA-28 trace reason meanings, or DA-03 trace substrate semantics.
