SEMANTIC_ANCHORS
----------------
- Kernel owns authority; adapters execute declared pack code; transports carry messages; RPC defines the logical boundary.
- Pack code participates in an AppInstance only through Turnix-managed context, capability, RPC-shaped, lifecycle,
  policy, trace, and state boundaries.
- Kernel authority is not delegated merely by same process, same language, in-process transport, frontend messaging,
  RuntimeHost entry-surface command ability, or pack code declaration.
- Execution adapters are Turnix-managed boundary participants, not authority by themselves.
- Adapter mediation does not imply sandboxing.
- Recognition, declaration, binding, permission, activation, and execution are separate phases; no phase silently implies a later phase.
- Execution success does not imply committed-state mutation, RuntimeHost command acceptance, RuntimeHost operation success,
  or workspace ownership change.
- Executable artifacts are declared explicitly; recognized code files are not executed merely because they exist.
- A declaration does not grant capability permission, persistent I/O authority, committed-state mutation authority,
  or RuntimeHost command-surface authority.
- Pack-provided Python is not backend implementation code merely because Turnix backend implementation is Python.
- Pack-provided JavaScript is not frontend authority merely because it runs in a browser.
- Pack-provided code does not import backend internals as an authority path.
- PackContext exposes scoped participation, not general backend internals, unrestricted filesystem authority,
  unrestricted committed-state mutation, unrestricted capability invocation, or unrestricted RuntimeHost control authority.
- RPC-shaped boundary is not equivalent to WebSocket and is not necessarily networked.
- Direct in-process calls may implement an RPC-shaped boundary only when route identity, permission checks,
  lifecycle ownership, trace correlation, structured errors, Orchestration Unit boundaries, transaction boundaries,
  AppInstance/SavePack state authority, and RuntimeHost authority boundaries are preserved.
- Transport choice does not define authority, capability permission, adapter execution authorization, AppInstance lifecycle,
  RuntimeHost lifecycle, or Job lifecycle.
- Browser state is not authoritative AppInstance state.
- Remembered policy decisions do not silently broaden to new adapter kinds, packs, capabilities, SavePacks,
  RuntimeHost entry surfaces, or trust classes.
- If DA-23 appears to conflict with DA-27 or DA-28, preserve Kernel authority, capability mediation, and the RPC-shaped boundary until documents are corrected.
