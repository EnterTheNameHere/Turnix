SEMANTIC_ANCHORS
----------------
- Committed state is not live runtime object identity.
- Committed values are represented through immutable payload references.
- Runtime objects are decoded views of committed payload material.
- Storage-neutral representation does not depend on filesystem path, database row identity, runtime pointer identity, or machine-local layout accident.
- A committed key is representable as key -> ValueRef at the commit boundary.
- ValueRef is immutable once created.
- Decode failure is explicit and does not validate authoritative content.
- Chunk is an immutable byte sequence.
- ChunkId is canonical Chunk identity and is content-derived.
- ChunkId is independent of path, row identifier, timestamp, machine identity, and wall-clock time.
- Chunk identity is format-aware; different encodings produce different ChunkIds unless a later authoritative rule defines equivalence.
- ValueRef is a deterministic decoding contract, not a live memory pointer.
- ValueRef forms are exactly InlineValueRef and ChunkValueRef.
- Arbitrary network references and arbitrary file-path references are not ValueRef forms under DA-05.
- Committed values are schemaless by default.
- Schema linkage is optional representation metadata and does not become required for ordinary committed value storage.
- Static data origin does not bypass the committed representation contract.
- Payload sharing does not change authority boundaries.
- Reachability determines retention safety; it does not redefine artifact authority.
- Persistent I/O authority controls access, but does not redefine representation meaning.
- Optional storage capabilities do not change Chunk or ValueRef identity semantics.
