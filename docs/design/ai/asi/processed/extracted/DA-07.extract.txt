Semantic anchors
----------------
- Persistent I/O is centralized and mediated.
- Same-language or same-process execution does not create persistence authority.
- IoManager is the sole authority responsible for persistent I/O.
- Readers load data and Writers persist data under IoManager control.
- Reader / Writer providers refine mechanics, not platform authority.
- Raw handles and raw paths do not escape the Reader / Writer boundary.
- Built-in providers are available before discovery and indexing.
- Additional providers are unavailable until the providing pack is activated.
- Discovery and indexing use built-in Readers only.
- Runtime writable roots are userdata/ and saves/.
- Runtime read-only roots are custom/, first-party/, and third-party/.
- Root writability does not by itself authorize state mutation.
- Persistent I/O errors classify into exactly one of unrecoverable,
  user-decidable, or optional / best-effort.
- Identity-bearing data never uses silent fallback.
- User-decidable recovery requires a minimal recovery surface.
- Refused, skipped, failed, retried, recovered, or completed I/O outcomes are
  trace-visible.
- Save-local copied packs and save-internal artifacts do not become part of
  initial global indexing merely because they exist in save data.
- Migrators are deterministic and side-effect controlled but do not provide
  inverse operations by themselves.
- IoManager creates rollback points before identity-bearing mutations according
  to policy.
- Automatic rollback does not occur without explicit policy or user-visible
  consent where required.
- Streaming is explicit, never implicit.
- Streaming write staging is mandatory and final destination update occurs only
  on commit.
- Streaming is forbidden for discovery, indexing, manifests, configuration
  loading, dependency resolution, and activation-critical reads.
- Native filesystem APIs are not a Turnix persistence authority path for
  pack-provided code or adapter-executed code.

Confusable terms
----------------
- IoManager vs Reader / Writer:
  IoManager owns persistence authority; Readers and Writers implement concrete
  format handling under IoManager control.
- Writable root vs mutation authority:
  A writable root permits persistence targets under root policy, but does not
  grant state-mutation authority by itself.
- Adapter-executed code vs persistence authority:
  Adapter-executed code may request persistence through mediated paths, but does
  not gain raw filesystem authority.
- Built-in provider vs extended provider:
  Built-in providers exist before discovery; extended providers require provider
  registration and activation of the providing pack.
- User-decidable vs optional / best-effort:
  User-decidable failures pause continuation for explicit recovery; optional
  failures affect non-authoritative artifacts such as logs, traces, or caches.
- Backup vs snapshot:
  Backups fit small critical files or prior versions; snapshots fit related
  multi-file or multi-artifact units.
- Migrator vs rollback:
  Migrators move persisted data forward; rollback safety comes from IoManager
  and the DA-04 commit model, not inverse migrator logic.
- Streaming write vs partial final output:
  Streaming write may stage incrementally, but cancellation must not create a
  partial valid final output.
