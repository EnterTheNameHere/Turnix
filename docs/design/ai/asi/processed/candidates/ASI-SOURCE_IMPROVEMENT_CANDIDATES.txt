Turnix Assistant Semantic Index source improvement candidates
=============================================================

Purpose
-------
This file records candidate improvements for canonical source documents found
during ASI extraction, audit, review, or supervisor work.

This file is non-authoritative workflow state. It does not define Turnix
semantics.

Maintenance
-----------
This file is workflow-maintained.

Manual edits are not expected unless a supervisor or user explicitly assigns
candidate maintenance.

Required existence
------------------
This file is persistent ASI workflow infrastructure.

It must exist before workflows that record or review source-document improvement
candidates can run.

It may be empty of entries, but it must still contain the format and status
rules needed by workers.

Mutation policy
---------------
This file is updated in place.

Existing entries are preserved unless they are explicitly updated, superseded,
or corrected by an assigned workflow or supervisor/user maintenance task.

Workers may add new candidates or update matching candidates by CANDIDATE_ID.
Workers must not rewrite unrelated entries.

Candidate outcomes
------------------
Expected candidate outcomes include:
- ASI_ONLY
- SOURCE_DOCUMENT
- BOTH_ASI_AND_SOURCE_DOCUMENT
- DEFERRED
- REJECTED
- APPROVED_FOR_SOURCE_PATCH
- APPLIED

Entry status values
-------------------
Expected status values include:
- NEEDS_SUPERVISOR_DECISION
- ACCEPTED
- DEFERRED
- REJECTED
- APPROVED_FOR_SOURCE_PATCH
- APPLIED
- SUPERSEDED

Problem type values
-------------------
Expected problem type values include:
- AMBIGUITY
- MISSING_BOUNDARY
- TERM_CONFUSION
- CROSS_DOCUMENT_MISMATCH
- WEAK_RETRIEVAL_WORDING
- POSSIBLE_SEMANTIC_GAP
- OTHER

Entry format
------------
Use this format for source-improvement candidates:

BEGIN_ENTRY
CANDIDATE_ID:
STATUS:
OUTCOME:
SOURCE_DOCS:
FOUND_IN:
PROBLEM_TYPE:
ISSUE:
RISK:
RECOMMENDED_ACTION:
SUGGESTED_SOURCE_FIX:
SUGGESTED_ASI_FIX:
APPROVAL_REF:
LAST_REVIEW_REF:
NOTES:
END_ENTRY

Field rules
-----------
CANDIDATE_ID:
Stable source-improvement candidate ID.

STATUS:
One of the expected status values.

OUTCOME:
One of the expected candidate outcomes.

SOURCE_DOCS:
Canonical DOC_ID values affected by the candidate. Use ";" to separate multiple
DOC_ID values.

FOUND_IN:
Extraction record, audit report, ASI index, test report, or supervisor review
where the candidate was found.

PROBLEM_TYPE:
One of the expected problem type values.

ISSUE:
Concise description of the source clarity problem.

RISK:
What can go wrong if the issue remains unresolved.

RECOMMENDED_ACTION:
Suggested disposition for supervisor/user review.

SUGGESTED_SOURCE_FIX:
Suggested source-document clarification. Use "-" when not applicable.

SUGGESTED_ASI_FIX:
Suggested ASI/index clarification. Use "-" when not applicable.

APPROVAL_REF:
User/supervisor approval reference when approved. Use "-" when not approved.

LAST_REVIEW_REF:
Commit, branch, run note, or placeholder identifying the last review when
available.

NOTES:
Compact notes. Use "-" when empty.
