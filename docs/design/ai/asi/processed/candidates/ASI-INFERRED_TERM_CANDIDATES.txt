Turnix Assistant Semantic Index inferred term candidates
=======================================================

Purpose
-------
This file records inferred terminology candidates found by ASI inferred-term
review workflows.

This file is non-authoritative workflow state. It does not define Turnix
semantics.

Maintenance
-----------
This file is workflow-maintained by inferred-term review and supervisor
workflows.

Manual edits are not expected unless a supervisor or user explicitly assigns
candidate maintenance.

Required existence
------------------
This file is persistent ASI workflow infrastructure.

It must exist before workflows that record or review inferred terminology
candidates can run.

It may be empty of entries, but it must still contain the format and status
rules needed by workers.

Mutation policy
---------------
This file is updated in place.

Existing entries are preserved unless they are explicitly updated, superseded,
or corrected by an assigned workflow or supervisor/user maintenance task.

Inferred-term review workers may add new candidates or update matching
candidates by CANDIDATE_ID.
Workers must not rewrite unrelated entries.

Classification values
---------------------
Expected classification values include:
- EXPLICIT_SOURCE_TERM
- SUPPORTED_INFERRED_TERM
- CANONICAL_TERM_CANDIDATE
- INDEX_ALIAS_ONLY
- REJECT_OR_REPLACE

Entry status values
-------------------
Expected status values include:
- NEEDS_SUPERVISOR_DECISION
- ACCEPTED
- DEFERRED
- REJECTED
- APPLIED
- SUPERSEDED

Entry format
------------
Use this format for inferred-term candidates:

BEGIN_ENTRY
CANDIDATE_ID:
STATUS:
TERM:
SOURCE_DOC:
FOUND_IN:
PRESENT_IN_SOURCE:
SOURCE_LOCATION_HINT:
GENERATED_MATERIAL_FILES:
CLASSIFICATION:
WHY_TERM_MATTERS:
RISK_IF_ACCEPTED_INCORRECTLY:
RISK_IF_REJECTED_INCORRECTLY:
RECOMMENDATION:
APPROVAL_REF:
LAST_REVIEW_REF:
NOTES:
END_ENTRY

Field rules
-----------
CANDIDATE_ID:
Stable inferred-term candidate ID.

STATUS:
One of the expected status values.

TERM:
The inferred, generated, or normalized term being reviewed.

SOURCE_DOC:
Canonical DOC_ID of the source document being compared.

FOUND_IN:
Workflow, extraction record, ASI index, or report where the term was found.

PRESENT_IN_SOURCE:
yes, no, partial, or spelling-variant.

SOURCE_LOCATION_HINT:
Section, heading, or source area that supports or rejects the term. Use "-"
when unknown.

GENERATED_MATERIAL_FILES:
Generated files that used the term. Use ";" to separate multiple files.

CLASSIFICATION:
One of the expected classification values.

WHY_TERM_MATTERS:
Why the term affects retrieval, design, implementation naming, or assistant
routing.

RISK_IF_ACCEPTED_INCORRECTLY:
What can go wrong if the term is promoted incorrectly.

RISK_IF_REJECTED_INCORRECTLY:
What can go wrong if the term is rejected incorrectly.

RECOMMENDATION:
Suggested disposition for supervisor/user review.

APPROVAL_REF:
User/supervisor approval reference when approved. Use "-" when not approved.

LAST_REVIEW_REF:
Commit, branch, run note, or placeholder identifying the last review when
available.

NOTES:
Compact notes. Use "-" when empty.

Entries
-------
No inferred-term candidates have been recorded in this new ASI structure yet.

END
---
