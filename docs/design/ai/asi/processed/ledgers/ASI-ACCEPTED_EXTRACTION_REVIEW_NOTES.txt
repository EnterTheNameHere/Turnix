Turnix Assistant Semantic Index accepted extraction review notes
===============================================================

Purpose
-------
This file records accepted review requirements that future ASI extraction,
audit, and index-generation workflows must preserve.

This file is non-authoritative workflow state. It does not define Turnix
semantics.

Maintenance
-----------
This file is workflow-maintained by supervisor or explicitly assigned review
maintenance workflows.

Manual edits are not expected unless a supervisor or user explicitly assigns
review-note maintenance.

Required existence
------------------
This file is persistent ASI workflow infrastructure.

It must exist before workflows that preserve accepted review requirements can
run.

It may be empty of entries, but it must still contain the format and status
rules needed by workers.

Rule
----
Generated extraction records are disposable outputs and may be replaced on
worker rerun.

Accepted review requirements are durable workflow inputs.

Do not let accepted requirements live only inside generated extraction records.

Mutation policy
---------------
This file is updated in place.

Existing entries are preserved unless they are explicitly updated, superseded,
or corrected by an assigned workflow or supervisor/user maintenance task.

Workers must preserve applicable accepted requirements in generated outputs.
Workers must not rewrite unrelated entries.

Entry status values
-------------------
Expected status values include:
- ACCEPTED
- SUPERSEDED
- DEFERRED
- REJECTED

Entry format
------------
Use this format for accepted review requirements:

BEGIN_ENTRY
REQUIREMENT_ID:
STATUS:
SCOPE:
TARGETS:
REQUIREMENT:
RATIONALE:
APPLIES_TO_WORKFLOWS:
CREATED_FROM:
LAST_REVIEW_REF:
NOTES:
END_ENTRY

Field rules
-----------
REQUIREMENT_ID:
Stable requirement ID.

STATUS:
One of the expected status values.

SCOPE:
Batch, DOC_ID, ASI output file, workflow, or global scope.

TARGETS:
Specific files, DOC_ID values, output paths, or workflow IDs affected by the
requirement. Use ";" to separate multiple targets.

REQUIREMENT:
The durable instruction future workflows must preserve.

RATIONALE:
Why the requirement exists.

APPLIES_TO_WORKFLOWS:
Workflow IDs that must inspect this requirement. Use ";" to separate multiple
workflow IDs.

CREATED_FROM:
Audit report, supervisor decision, test result, or review source that created
this requirement.

LAST_REVIEW_REF:
Commit, branch, run note, or placeholder identifying the last review when
available.

NOTES:
Compact notes. Use "-" when empty.

Entries
-------
No accepted extraction review requirements have been recorded in this new ASI
structure yet.

END
---
This file records durable accepted ASI review requirements only.
