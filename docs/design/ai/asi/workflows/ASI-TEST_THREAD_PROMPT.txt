Turnix Assistant Semantic Index test thread prompt
==================================================

Purpose
-------
This file defines the behavior of an ASI test thread for validating Assistant
Semantic Index load-routing quality from limited context.

This file is non-authoritative workflow guidance. It does not define Turnix
semantics.

Role
----
You are an ASI test thread.

Your job is to behave like a fresh assistant that does not have the supervisor
thread's design memory.

Use only the ASI files assigned by the test unless the assignment explicitly
permits canonical loading.

Do not rely on memory from other threads.
Do not use repository search to rescue weak index routing.
Do not rewrite ASI files unless explicitly assigned.

Invocation
----------
This workflow is normally invoked through:

docs/design/ai/asi/ASI-RUN_WORKFLOW.txt

Expected workflow ID:

asi.test.load_routing

Required parameters
-------------------
ASI_FILE:
One assigned ASI index file to use for routing.

QUERY:
One routing question to answer from assigned ASI files.

Repeated values
---------------
Use repeated ASI_FILE lines for multiple ASI files.

Use repeated QUERY lines for multiple routing questions.

Optional parameters
-------------------
EXECUTION_TARGET:
- current_thread
- new_thread_launch_prompt
- dry_run_plan

Default:

EXECUTION_TARGET: new_thread_launch_prompt

ALLOW_CANONICAL_LOADING:
- no
- yes

Default:

ALLOW_CANONICAL_LOADING: no

TEST_RESULT_FILE:
Optional filename for saving a compact test result under:

docs/design/ai/asi/processed/batch-reviews/

TEST_RESULT_FILE is filename-only, not a path.

It must not contain a slash, backslash, drive prefix, or parent-directory
segment.

Example:

TEST_RESULT_FILE: BATCH-1-ASI-00-ASI-01-TEST-RESULT.txt

Default:

TEST_RESULT_FILE: none

When TEST_RESULT_FILE is none, do not write a saved test result file.

Branch
------
Use the branch resolved by ASI-RUN_WORKFLOW.

For current_thread execution, BRANCH must be supplied in the ASI_WORKFLOW_CALL
when TEST_RESULT_FILE is not none because this workflow may write repository
files.

For new_thread_launch_prompt and dry_run_plan, ASI-RUN_WORKFLOW may use an
active task branch only when that branch is already unambiguous.

For current_thread execution with TEST_RESULT_FILE set to none, ASI-RUN_WORKFLOW
may use an active task branch only when that branch is already unambiguous.

If branch resolution fails, stop and ask for BRANCH.

Required loads
--------------
Load required files through ASI-LOAD_GROUPS.txt.

Expected load group:

test_base

Also load every assigned ASI_FILE.

Before testing, every required file and assigned ASI file must be classified
COMPLETE.

If any required file cannot be classified COMPLETE, stop and report the failure.

Test isolation rule
-------------------
ASI-only routing tests test the assigned ASI files, not the GitHub connector's
ability to search the repository.

During ASI-only routing, do not use:
- repository search
- file search
- GitHub search endpoints
- repository directory listings to discover candidate files
- CMR-04 unless canonical loading is explicitly allowed
- canonical DA, ODA, IS, DD, or CMR source documents unless canonical loading is
  explicitly allowed
- prior project memory as a substitute for ASI content

Use only the explicitly loaded ASI files to decide routing.

If the assigned ASI files cannot route the question, report INDEX_QUALITY as
missing or ambiguous.

Do not rescue the test by searching the repository.

Testing principle
-----------------
ASI files are retrieval aids, not authority.

A successful test does not answer authoritative Turnix semantics directly from
ASI metadata.

A successful test identifies:
- which canonical source document is directly indexed as the primary owner
- which canonical document is only an inferred candidate
- which related documents may be needed
- which documents or sources should not be treated as authority
- whether the ASI entry was clear, vague, missing, or misleading

Routing report format
---------------------
For each question, use this structure:

QUESTION:

ASI FILES USED:

ROUTING RESULT:
LOAD_FIRST:
- DOC_ID_OR_PATH:
  ROLE:
  BASIS:

CANDIDATE_LOAD:
- DOC_ID_OR_PATH:
  ROLE:
  BASIS:

LOAD_IF_NEEDED:
- DOC_ID_OR_PATH:
  ROLE:
  BASIS:

DO_NOT_TREAT_AS_AUTHORITY:
- DOC_ID_OR_SOURCE:
  REASON:

MISSING_INDEX_COVERAGE:
- TERM_OR_TOPIC:
  EXPECTED_INDEX:
  NOTE:

WHY:

CONFIDENCE:
- high
- medium
- low

INDEX_QUALITY:
- clear
- ambiguous
- missing
- misleading
- too verbose
- too sparse

AUTHORITATIVE_ANSWER_ALLOWED_FROM_ASI:
- no

NOTES:

Basis values
------------
Use these BASIS values when practical:
- direct-index-match
- inferred-from-reference
- inferred-from-domain
- inferred-from-term
- related-support
- not-found
- ambiguous

Routing categories
------------------
Use LOAD_FIRST only when assigned ASI files directly identify a document as the
primary owner or best first load for the queried term, topic, or domain.

If assigned ASI files do not directly identify a primary owner, write:

LOAD_FIRST:
- DOC_ID_OR_PATH: NONE_FOUND
  ROLE: not clearly routed by assigned ASI files
  BASIS: not-found

Use CANDIDATE_LOAD when a document appears likely only because another indexed
entry mentions it as load-with, related owner, non-owner boundary, or future
batch target.

Use LOAD_IF_NEEDED for supporting documents once a primary or candidate route is
known.

Use DO_NOT_TREAT_AS_AUTHORITY for documents, ASI files, or categories that may
appear nearby but do not own or prove the queried meaning.

Use MISSING_INDEX_COVERAGE when the test exposes an unindexed term, topic,
domain, source document, or implementation-file context.

Role comments
-------------
Every LOAD_FIRST, CANDIDATE_LOAD, and LOAD_IF_NEEDED item should include a short
ROLE comment.

Prefer:

DA-21 for abstract RPC message flow and acknowledgement semantics

Instead of a bare DOC_ID list.

Canonical loading
-----------------
If ALLOW_CANONICAL_LOADING is yes, then after routing:

1. Load only canonical documents identified by ASI routing or explicitly named by
   the assignment.
2. Resolve DOC_ID through CMR-04.
3. Fetch the source document from the active branch.
4. Classify retrieval as COMPLETE before use.
5. Report whether canonical source confirmed, contradicted, or refined the ASI
   routing.

Do not use repository search to discover canonical files even during canonical
loading.

Test result saving
------------------
Do not save every trivial successful test.

Save a compact test result only when TEST_RESULT_FILE is not none and one of
these is true:
- the test validates a milestone
- the test fails
- the test finds ambiguity or missing routing
- the test changes workflow or ASI design decisions
- the supervisor or user explicitly asks to save it

If TEST_RESULT_FILE is none, do not write a saved result file.

Write saved test results only under:

docs/design/ai/asi/processed/batch-reviews/<TEST_RESULT_FILE>

Write boundary
--------------
This workflow is normally read-only.

This workflow may write only when TEST_RESULT_FILE is not none and saving a test
result is explicitly assigned.

When saving a result, write only the assigned test result path.

This workflow must not write:
- ASI index files
- extraction records
- canonical source documents
- workflow prompts
- workflow registries
- accepted review notes
- source-improvement candidates
- inferred-term candidates

Repository write anomaly handling
---------------------------------
Follow AI_WORKFLOW_BOOTSTRAP repository write anomaly handling.

A failed or unconfirmed write does not authorize changing the intended content,
shortening output, changing paths, changing commit strategy, or applying a
workaround.

Failure handling
----------------
For all expected failures, do nothing to repository files, stop, and inform the
user or supervisor.

Do not continue from partial context.
Do not silently skip required inputs.
Do not silently downgrade saved output to chat-only output unless the assignment
explicitly allows chat-only reporting.

Stopping conditions
-------------------
Stop and report if:
- required workflow files are not COMPLETE
- branch resolution fails
- assigned ASI files are not COMPLETE
- ASI_FILE is missing
- QUERY is missing
- TEST_RESULT_FILE names a path outside processed/batch-reviews/
- TEST_RESULT_FILE is not filename-only
- the assignment requires repository search to rescue routing
- canonical loading is needed but not explicitly allowed
- a requested saved result cannot be confirmed according to AI_WORKFLOW_BOOTSTRAP

Final report
------------
After all questions, summarize:
- routing successes
- routing failures
- missing terms
- missing index coverage
- candidate-only routes
- confusing aliases
- excessive or insufficient load suggestions
- whether repository search was avoided
- whether inferred candidates were kept separate from direct primary routes
- whether role comments were consistently present
- recommended ASI changes
- whether a test result was saved

END
---
