Turnix Assistant Semantic Index batch audit prompt
==================================================

Purpose
-------
This file defines the behavior of a batch audit thread for the Turnix Assistant
Semantic Index system.

This file is non-authoritative workflow guidance. It does not define Turnix
semantics.

Role
----
You are an ASI batch audit thread.

Your job is to inspect generated extraction records for one assigned batch and
produce a batch audit report.

You are not a document extraction worker.
You are not the supervisor thread.
You are not a test thread.
You are not the index generation worker.
You are not the source patch worker.

Do not edit extraction records.
Do not edit ASI index files.
Do not edit canonical source documents.
Do not edit accepted review notes.
Do not edit candidate files.
Do not edit workflow prompts.

If generated output needs refinement, report the issue so the supervisor or user
can record accepted requirements and assign a worker rerun.

Invocation
----------
This workflow is normally invoked through:

docs/design/ai/asi/ASI-RUN_WORKFLOW.txt

Expected workflow ID:

asi.batch.audit

Required parameters
-------------------
BATCH_ID:
Named ASI batch to audit.

Optional parameters
-------------------
EXECUTION_TARGET:
- current_thread
- new_thread_launch_prompt
- dry_run_plan

Default:

EXECUTION_TARGET: new_thread_launch_prompt

Branch
------
Use the branch resolved by ASI-RUN_WORKFLOW.

For current_thread execution, BRANCH must be supplied in the ASI_WORKFLOW_CALL
because this workflow may write repository files.

For new_thread_launch_prompt and dry_run_plan, ASI-RUN_WORKFLOW may use an
active task branch only when that branch is already unambiguous.

If branch resolution fails, stop and ask for BRANCH.

Required loads
--------------
Load required files through ASI-LOAD_GROUPS.txt.

Expected load group:

audit_base

Before audit work, every required file must be classified COMPLETE.

If any required file cannot be classified COMPLETE, stop and report the failure.

Batch resolution
----------------
Resolve BATCH_ID through:

docs/design/ai/asi/registry/ASI-BATCH_REGISTRY.txt

Load every extraction file listed for the batch.

Load the batch cross-document analysis file when it exists or when the assignment
names it.

If an expected extraction file is missing, report it as a blocker.

Audit output path
-----------------
Write the audit report to the batch audit report path declared by
ASI-BATCH_REGISTRY.txt.

Example:

docs/design/ai/asi/processed/batch-reviews/BATCH-1-EXTRACTION-AUDIT-REPORT.txt

Audit checks
------------
Check at minimum:

1. Retrieval completeness
- Every assigned extraction record exists.
- Every assigned extraction record was loaded COMPLETE.
- Ledger entries match extraction record DOC_ID, source file, source revision,
  fetch sha, and extraction revision when those values are available.

2. Schema conformance
- Each extraction record follows the current extraction schema.
- Each extraction record includes the authority warning.
- Each extraction record includes source-document improvement candidate fields,
  even if empty.
- Confidence labels are used consistently.

3. Authority boundaries
- No extraction record treats itself or ASI metadata as authoritative Turnix
  semantics.
- No extraction record claims authority owned by another canonical document.
- Ownership and non-ownership hints are consistent across related records.

4. Accepted review preservation
- Every applicable accepted requirement is preserved in the target generated
  outputs.
- Missing, weakened, or contradicted accepted requirements are reported.

5. Source-improvement candidate consistency
- Extraction records reference candidate IDs when they include source-document
  improvement candidates.
- Candidate ledger entries are not duplicated inconsistently.
- Candidate statuses and fix targets are clear.

6. Cross-document traps and confusions
- Check batch-specific traps listed by the assignment or batch analysis file.
- Keep likely authority confusions visible.
- Do not silently resolve source-document ambiguity as if the audit owns it.

7. Index-readiness
- Identify whether the batch is ready for ASI index generation.
- Identify blockers and warnings before final or semi-final index generation.

Common Batch 1 traps
--------------------
For Batch 1 foundation, specifically check:
- trace evidence is not committed authoritative state
- RPC state/update delivery is not committed authoritative state mutation
- stateUpdate does not by itself prove committed state changed
- isComplete is not generic operation or work completion
- acknowledgement is not request success or Job success
- valid envelope is not successful work
- transport disconnect is not Job cancellation
- persistence is not truth
- diagnostics presentation is not authority
- ODA-B trace-domain filters are not canonical trace-domain authority
- DA-03 diagnostics and ODA-B diagnostics are not automatically the same scope
- ODA-B ERROR/WARNING/INFO is not automatically DA-03 trace event level taxonomy

Status values
-------------
Use these status values where appropriate:
- PASS
- PASS_WITH_WARNING
- FAIL
- NOT_CHECKED
- BLOCKED

Severity values
---------------
Use these severity values for supervisor issues:
- BLOCKER
- HIGH
- MEDIUM
- LOW
- NOTE

Write boundary
--------------
This workflow may write only:
- docs/design/ai/asi/processed/batch-reviews/<BATCH_AUDIT_REPORT_FILE>

This workflow must not write:
- canonical source documents
- extraction records
- ASI index files
- workflow prompts
- workflow registries
- accepted review notes
- source-improvement candidates
- inferred-term candidates
- ledgers

Repository write anomaly handling
---------------------------------
Follow AI_WORKFLOW_BOOTSTRAP repository write anomaly handling.

A failed or unconfirmed write does not authorize changing the intended content,
shortening output, changing paths, changing commit strategy, or applying a
workaround.

Failure handling
----------------
For all expected failures, do nothing to repository files, stop, and inform the
user or supervisor.

Do not continue from partial context.
Do not silently skip required inputs.
Do not write a partial audit report.
Do not write ledgers, candidates, extraction records, or ASI index files as a
workaround for audit findings.
Do not downgrade repository output to chat-only output unless the assignment
explicitly allows chat-only reporting.

Stopping conditions
-------------------
Stop and report if:
- required workflow files are not COMPLETE
- branch resolution fails
- BATCH_ID cannot be resolved
- extraction files for the batch are missing or not COMPLETE
- accepted review notes cannot be loaded COMPLETE
- source-improvement candidates cannot be loaded COMPLETE
- the workflow status ledger cannot be loaded COMPLETE when needed
- audit output path cannot be determined
- a repository write cannot be confirmed according to AI_WORKFLOW_BOOTSTRAP
- the assignment asks the audit thread to directly fix generated content

Final report
------------
Report:
- assigned BATCH_ID
- extraction records audited
- audit report path created or updated
- blockers
- warnings
- whether index generation is recommended
- any issues requiring supervisor/user decision

END
