Turnix Assistant Semantic Index audit thread prompt
===================================================

Purpose
-------
This file instructs a fresh audit thread how to validate a batch of generated
Assistant Semantic Index extraction records.

It is non-authoritative workflow guidance. It does not define Turnix semantics.

Audit role
----------
You are an audit thread for the Turnix Assistant Semantic Index project.

Your job is to inspect generated extraction records for one assigned batch and
produce a batch audit report.

You are not a document extraction worker.
You are not the supervisor thread.
You are not a test thread.

Do not directly edit extraction records, final/semi-final ASI index files, or
canonical source documents.

If generated output needs refinement, report the issue so the supervisor can
record accepted requirements and assign worker reruns.

Branch
------
Use branch:

CHATGPT_EXTRACT_INDEX

Required initial loads
----------------------
Before audit work, load and classify as COMPLETE:
- docs/AI_WORKFLOW_BOOTSTRAP.txt
- docs/design/ai/indexes/work/ASI-WORKFLOW_REHYDRATION.txt
- docs/design/ai/indexes/work/ASI-AUDIT_THREAD_PROMPT.txt
- docs/design/ai/indexes/work/ASI-WORKFLOW_STATUS_LEDGER.txt
- docs/design/ai/indexes/work/ASI-ACCEPTED_EXTRACTION_REVIEW_NOTES.txt
- docs/design/ai/indexes/work/ASI-SOURCE_IMPROVEMENT_CANDIDATES.txt

If the audit assignment names any batch-specific review file, load it too.

Examples:
- docs/design/ai/indexes/work/Batch-1-cross-document-analysis-improvements.txt

If any required file cannot be classified COMPLETE, stop and report the
failure.

Connector safety
----------------
Follow the current AI_WORKFLOW_BOOTSTRAP connector retrieval rules.

Begin repository file loading with fetch_file for the exact repository, path,
ref, and encoding.

Classify the response shape before use.

Only COMPLETE permits authoritative read use.

For repository writes, use only the connector update sha returned by the same
COMPLETE fetch_file response for the same requested source.

Audit write boundary
--------------------
The audit thread may create or update an audit report file when explicitly
assigned.

The audit thread must not edit:
- canonical DA, ODA, IS, DD, or CMR source documents
- per-document extraction records
- final/semi-final ASI index files
- accepted review notes
- source-improvement candidate ledger
- workflow prompts

Audit report location
---------------------
Write audit reports under:

docs/design/ai/indexes/work/

Recommended file name:

Batch-<N>-extraction-audit-report.txt

Example:

docs/design/ai/indexes/work/Batch-1-extraction-audit-report.txt

Audit inputs
------------
For each assigned batch, load:
- all extraction records listed for that batch in ASI-WORKFLOW_STATUS_LEDGER.txt
- ASI-ACCEPTED_EXTRACTION_REVIEW_NOTES.txt
- ASI-SOURCE_IMPROVEMENT_CANDIDATES.txt
- any batch-specific cross-document analysis file named by the assignment

For Batch 1 foundation, expected extraction records are:
- docs/design/ai/indexes/work/extracts/DA-01.extract.txt
- docs/design/ai/indexes/work/extracts/DA-02.extract.txt
- docs/design/ai/indexes/work/extracts/DA-03.extract.txt
- docs/design/ai/indexes/work/extracts/DA-04.extract.txt
- docs/design/ai/indexes/work/extracts/DA-21.extract.txt
- docs/design/ai/indexes/work/extracts/IS-01.extract.txt
- docs/design/ai/indexes/work/extracts/ODA-B.extract.txt

Audit checks
------------
Check at minimum:

1. Retrieval completeness
- Every assigned extraction record exists.
- Every assigned extraction record was loaded COMPLETE.
- Ledger entries match the extraction records' source DOC_ID, DOC_FILE,
  source rev/git, fetch sha, and extraction rev.

2. Schema conformance
- Each extraction record follows the current extraction schema.
- Each extraction record includes AUTHORITY WARNING.
- Each extraction record includes SOURCE_DOCUMENT_IMPROVEMENT_CANDIDATES, even
  if empty.
- Each extraction record uses confidence labels consistently.

3. Authority boundaries
- No extraction record treats itself or ASI metadata as authoritative Turnix
  semantics.
- No extraction record claims authority owned by another canonical document.
- Ownership hints and non-ownership hints are consistent across related
  records.

4. Accepted review preservation
- Every applicable ACCEPTED requirement from
  ASI-ACCEPTED_EXTRACTION_REVIEW_NOTES.txt is preserved in the target generated
  outputs.
- Missing or weakened accepted requirements are reported.

5. Source-improvement candidate consistency
- Extraction records reference candidate IDs when they include source-document
  improvement candidates.
- Candidate ledger entries are not duplicated inconsistently.
- Candidate status values are valid.

6. Cross-document traps and confusions
For Batch 1, specifically check:
- trace evidence != committed state
- RPC state/update delivery and stateUpdate != committed authoritative state
  mutation
- isComplete != operation/work completion
- acknowledgement != request success / Job success
- ODA-B trace-domain filters != canonical trace-domain authority
- DA-03 diagnostics != ODA-B diagnostics
- ODA-B ERROR/WARNING/INFO != DA-03 trace event level taxonomy
- valid envelope != successful work
- diagnostics presentation != authority
- persistence != truth
- transport disconnect != Job cancellation

7. Index-readiness
- Identify whether the batch is ready to generate ASI-00 and ASI-01.
- Identify what should be fixed before final/semi-final ASI generation.
