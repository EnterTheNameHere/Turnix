Turnix Assistant Semantic Index progress logging
================================================

Purpose
-------
This file defines optional user-visible progress logging for ASI workflows.

This file is non-authoritative workflow guidance. It does not define Turnix
semantics.

Use this file when
------------------
Use this file when an ASI_WORKFLOW_CALL uses:

PROGRESS_LOG: compact

or:

PROGRESS_LOG: structured

Progress logging is for user-visible workflow callouts. It is not tracing, does
not replace workflow reports, and does not authorize any read or write.

Modes
-----
PROGRESS_LOG: none
No progress callouts are required.

PROGRESS_LOG: compact
Use short cockpit-style before/after progress callouts around major workflow
phases.

PROGRESS_LOG: structured
Use compact structured action blocks around major workflow phases.

Default mode
------------
PROGRESS_LOG: none

Compact callout style
---------------------
Compact mode uses plain user-visible sentences.

Examples:

I am about to load required workflow files.

Finished loading required workflow files; all were COMPLETE.

I am about to compare existing DA-04 extraction against the candidate ledger.

Finished comparison; found dangling prior candidate B1-SRC-001.

I am about to prepare the replacement DA-04 extraction record.

Finished preparing replacement extraction; dangling prior candidate preserved as
provenance only.

I am about to write DA-04.extract.txt.

Finished write; commit abc123; connector time 938 ms.

Structured callout style
------------------------
Structured mode uses small action blocks.

Example:

ACTION 07 START
TYPE: CHECK
TARGET: existing DA-04 extraction vs candidate ledger
WHY: detect whether prior extraction candidate IDs are ledgered
NEXT: decide candidate handling

ACTION 07 FINISHED
RESULT: found dangling prior candidate B1-SRC-001
NEXT: handle as pending supervisor reconciliation

Structured mode should still be compact. It is not a full trace format.

Logging rule
------------
Progress logging marks workflow phase boundaries, not only tool calls.

When enabled, emit a callout before and after major workflow phases such as:
- loading required files
- comparing source, ledgers, old generated output, or accepted requirements
- deciding candidate or accepted-review handling
- preparing large replacement content
- performing repository writes
- verifying repository writes
- stopping on a blocker

The callout should say what phase is starting or finishing, what target is
involved, and the next expected action when useful.

Do not expose private reasoning. Summarize the workflow phase only.

Timing rule
-----------
Do not add separate time calls, Python calls, Bash calls, or clock formatting
only for progress logging.

If a connector or tool result already includes elapsed time, the assistant may
include that returned timing in the finished callout.

If no timing is returned, omit timing.

Reasoning-delay visibility
--------------------------
The purpose of compact progress logging is to reveal which workflow phase is
currently active.

If the last visible callout says the assistant is about to write a file, delay
probably belongs to the connector/tool call.

If the last visible callout says the assistant is preparing replacement content,
comparing ledgers, or deciding candidate handling, delay probably belongs to
model-side reasoning or output preparation.

This distinction is useful even without timestamps.

Non-goals
---------
Progress logging is not:
- tracing
- audit logging
- a replacement for final reports
- a replacement for write confirmation
- a reason to add timing tool calls
- a reason to expose chain-of-thought
- a reason to change read/write boundaries
- a reason to run dry-run behavior instead of real workflow execution

Stopping behavior
-----------------
If progress logging itself becomes confusing, too verbose, or begins to slow the
workflow, fall back to fewer compact callouts and report that the progress log
was reduced.

Do not change workflow semantics to preserve the log.

End
---
This file defines ASI progress logging behavior only.
