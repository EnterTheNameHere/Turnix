Turnix Assistant Semantic Index prepare prompt entrypoint
=========================================================

Purpose
-------
This file is a human-facing convenience entrypoint for preparing ASI workflow
launch prompts without manually writing full ASI_WORKFLOW_CALL blocks.

This file is non-authoritative workflow guidance. It does not define Turnix
semantics.

Use this file when
------------------
Use this file when the user asks for a prompt for a separate thread, worker
thread, audit thread, test thread, inferred-term review thread, source-patch
thread, index-generation thread, or supervisor thread.

This file is for prompt preparation only.

It does not run the target workflow.
It does not write generated ASI output.
It does not edit canonical source documents.
It does not replace ASI-RUN_WORKFLOW.txt.

Shortcut role
-------------
The shortcut converts a human request into an ASI_WORKFLOW_CALL with:

EXECUTION_TARGET: new_thread_launch_prompt

Then the assistant uses ASI-RUN_WORKFLOW.txt to resolve the workflow and print
the generated launch prompt.

The shortcut may infer obvious workflow parameters from the user's sentence when
unambiguous.

The shortcut must not invent missing required parameters.

Required initial loads
----------------------
Before preparing a launch prompt through this shortcut, load and classify as
COMPLETE:
- docs/AI_WORKFLOW_BOOTSTRAP.txt
- docs/design/ai/asi/ASI-PREPARE_PROMPT.txt

- docs/design/ai/asi/registry/ASI-WORKFLOW_REGISTRY.txt
- docs/design/ai/asi/registry/ASI-LOAD_GROUPS.txt

Load this when BATCH_ID is needed or can be inferred:
- docs/design/ai/asi/registry/ASI-BATCH_REGISTRY.txt

Load this when PROGRESS_LOG is compact or structured:
- docs/design/ai/asi/ASI-PROGRESS_LOGGING.txt

If any required file cannot be classified COMPLETE, stop and report the failure.

Supported shortcut phrases
--------------------------
The assistant may map these request shapes:

"extracts from <DOC_ID>"
"extract <DOC_ID>"
"document worker for <DOC_ID>"
  -> WORKFLOW_ID: asi.document.extract

"audit <BATCH_ID>"
"batch audit for <BATCH_ID>"
  -> WORKFLOW_ID: asi.batch.audit

"test routing"
"load routing test"
  -> WORKFLOW_ID: asi.test.load_routing

"inferred term review for <DOC_ID>"
"review inferred terms for <DOC_ID>"
  -> WORKFLOW_ID: asi.inferred_terms.review

"generate index <ASI_OUTPUT_FILE>"
"index generation for <ASI_OUTPUT_FILE>"
  -> WORKFLOW_ID: asi.index.generate

"source patch <CANDIDATE_ID>"
"apply source patch <CANDIDATE_ID>"
  -> WORKFLOW_ID: asi.source_patch.apply

"supervisor review"
"ASI supervisor"
  -> WORKFLOW_ID: asi.supervisor.review

Required parameter inference
----------------------------
The shortcut may infer BATCH_ID for a DOC_ID by reading ASI-BATCH_REGISTRY.

If a DOC_ID appears in exactly one batch, use that batch.

If a DOC_ID appears in multiple batches or no batch, stop and ask for BATCH_ID.

The shortcut may normalize obvious ASI index nicknames:
- ASI-00 -> docs/design/ai/asi/processed/indexes/ASI-00_ASSISTANT_SEMANTIC_INDEX_README.txt
- ASI-01 -> docs/design/ai/asi/processed/indexes/ASI-01_DOCUMENT_DOMAIN_INDEX.txt
- ASI-02 -> docs/design/ai/asi/processed/indexes/ASI-02_TERM_INDEX.txt
- ASI-03 -> docs/design/ai/asi/processed/indexes/ASI-03_RETRIEVAL_HINT_INDEX.txt
- ASI-04 -> docs/design/ai/asi/processed/indexes/ASI-04_BOUNDARY_AND_NON_OWNERSHIP_INDEX.txt
- ASI-05 -> docs/design/ai/asi/processed/indexes/ASI-05_RELATION_INDEX.txt

The shortcut may infer EXECUTION_TARGET as new_thread_launch_prompt.

Progress log inference
----------------------
The shortcut may infer PROGRESS_LOG when the user explicitly asks for progress
logging, compact progress, structured progress, cockpit-style callouts, or
visible progress.

Default:

PROGRESS_LOG: none

Examples:
- "with compact progress logging" -> PROGRESS_LOG: compact
- "with compact progress" -> PROGRESS_LOG: compact
- "with cockpit-style callouts" -> PROGRESS_LOG: compact
- "with structured progress logging" -> PROGRESS_LOG: structured

The shortcut must not infer PROGRESS_LOG: compact merely because a workflow may
take time.

When PROGRESS_LOG is compact or structured, the resolved ASI_WORKFLOW_CALL must
include the PROGRESS_LOG field.

The shortcut must not infer:
- BRANCH, READ_BRANCH, or WRITE_BRANCH when no active branch is unambiguous
- QUERY for routing tests
- GENERATED_MATERIAL_FILE for inferred-term review
- ASI_OUTPUT_FILE for index generation
- CANDIDATE_ID for source patch
- APPROVAL for source patch

When required parameters are missing, stop and ask for the missing parameters.

Branch rule
-----------
If the user names a branch, use it as BRANCH shorthand.

BRANCH shorthand resolves to:
- READ_BRANCH: <BRANCH>
- WRITE_BRANCH: <BRANCH>

The generated launch prompt must use READ_BRANCH and WRITE_BRANCH explicitly.
It must not rely on a bare BRANCH field for repository file loading.

If the user explicitly names different read and write branches, preserve both
only when the request clearly intends split read/write branch behavior.

If no branch is named, the shortcut may use the active task branch as both
READ_BRANCH and WRITE_BRANCH only when it is already unambiguous.

If no branch is supplied and no active task branch is unambiguous, stop and ask
for BRANCH or explicit READ_BRANCH and WRITE_BRANCH.

Output rule
-----------
The shortcut must print two things:

1. The resolved ASI_WORKFLOW_CALL block.
2. The generated launch prompt produced through ASI-RUN_WORKFLOW.

Do not skip the ASI_WORKFLOW_CALL block. It is useful for debugging and copying.

Stopping conditions
-------------------
Stop and report if:
- required files are not COMPLETE
- the requested workflow cannot be mapped unambiguously
- required parameters are missing
- BATCH_ID cannot be inferred for DOC_ID
- branch resolution fails
- the resolved ASI_WORKFLOW_CALL would violate ASI-WORKFLOW_CALL_FORMAT
- PROGRESS_LOG cannot be resolved to none, compact, or structured
- ASI-RUN_WORKFLOW reports a contract conflict

End
