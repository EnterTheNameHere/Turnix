Turnix Assistant Semantic Index file index
==========================================

Purpose
-------
This file lists known Assistant Semantic Index files and their intended use.

This file is non-authoritative workflow guidance. It does not define Turnix
semantics.

File index role
---------------
The file index helps humans and language models identify:
- ASI entrypoints
- ASI registry files
- ASI workflow prompt files
- ASI processed-output locations
- which files are read-only orientation
- which files are workflow-maintained state
- which files are generated or regenerable output

General rules
-------------
1. The file index does not grant authority by itself.
2. The file index does not grant write permission by itself.
3. Workflow write permission is declared in ASI-WORKFLOW_REGISTRY.txt and the
   selected workflow prompt.
4. If a file index entry conflicts with a workflow registry entry or prompt file,
   stop and report a workflow contract conflict.
5. Do not use this index to infer missing canonical Turnix document paths. Use
   CMR-04 for canonical DOC_ID resolution.
6. Generated-output pattern entries identify allowed output locations. They do
   not imply that a concrete generated file already exists.

FILE_KIND values
----------------
orientation:
Human-facing explanation. Not runnable.

entrypoint:
Top-level ASI action file.

registry:
Structured ASI control file used for resolving workflows or load queries.

workflow_prompt:
Role prompt for one kind of workflow thread.

processed_index:
Generated or semi-final assistant-facing ASI index file.

processed_extraction:
Generated extraction record for one canonical Turnix document.

processed_report:
Workflow-produced review or audit report.

processed_ledger:
Workflow-maintained state or accepted-decision file.

processed_candidate:
Workflow-maintained candidate list.

processed_pattern:
Generated-output path pattern. The pattern documents an allowed location but is
not itself a concrete file.
