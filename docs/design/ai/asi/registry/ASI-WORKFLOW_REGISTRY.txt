Turnix Assistant Semantic Index workflow registry
=================================================

Purpose
-------
This file defines Assistant Semantic Index workflow IDs and their contracts.

This file is non-authoritative workflow guidance. It does not define Turnix
semantics.

Registry role
-------------
The workflow registry maps a workflow ID to:
- purpose
- workflow prompt file
- required parameters
- optional parameters
- repeatable parameters
- required load groups
- deferred write-phase load groups
- execution targets
- execution profile
- read boundary
- write boundary
- forbidden writes
- expected outputs

General rules
-------------
1. A workflow may only run when WORKFLOW_ID resolves to one registry entry.
2. Required parameters must be present before the workflow runs.
3. Registry entries do not override AI_WORKFLOW_BOOTSTRAP retrieval safety.
4. Registry entries do not make ASI metadata authoritative.
5. If registry and workflow prompt conflict, stop and report the conflict.
6. Do not silently choose one rule and continue.
7. Every OPTIONAL_PARAM must have an explicit DEFAULT_PARAM entry.
8. A default value of none means the parameter is absent and no optional action
   is authorized by that parameter.
9. BRANCH is a workflow-call context field, not a workflow-specific optional
   parameter.
10. For current_thread execution of any workflow that may write repository
    files, BRANCH is required in the ASI_WORKFLOW_CALL.
11. For new_thread_launch_prompt and dry_run_plan, an active task branch may be
    used only when it is already unambiguous.
12. For current_thread read-only execution, an active task branch may be used
    only when the workflow has no MAY_WRITE entries and the branch is already
    unambiguous.
13. If no branch is supplied and no active task branch is unambiguous, stop and
    ask for BRANCH.
14. LOAD_GROUP entries are required before the workflow body starts.
15. LOAD_GROUP_BEFORE_WRITE entries are required before the named write class or
    write phase starts. They must not be parsed as ordinary LOAD_GROUP entries.
16. Fields may repeat only when declared with REPEATABLE_PARAM.
17. A repeated non-repeatable field with different values makes the workflow
    call malformed.
18. A repeated non-repeatable field with the same value may be ignored only
    after reporting the duplicate.

Execution profile values
------------------------
local_ok:
The workflow is suitable for local or cloud LLM execution when context fits.

local_with_review:
The workflow can be run locally, but review by a stronger model or human may be
useful for subtle issues.

cloud_recommended:
The workflow benefits significantly from strong cloud-model judgment.

human_required_before_write:
The workflow may draft or plan, but write actions require explicit human or
supervisor approval.
