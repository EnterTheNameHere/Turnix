SEMANTIC_ANCHORS
----------------
- Runtime memory is not authoritative merely because it is resident, visible, active, or in use.
- Committed state is authoritative only because it crossed DA-04's explicit commit boundary.
- Observation may explain what happened, but observation does not define committed truth.
- Authoritative material is sufficient for deterministic restoration inside DA-04 boundaries.
- Non-authoritative material is not required for committed-state correctness or authoritative-state equality.
- Traces, journals, transactional layers, and debugger artifacts are not authoritative state.
- Transactions stage speculative mutation until commit or abort.
- Commit and abort are atomic outcomes; partial propagation does not occur.
- Nested child transactions propagate into parent transactions, not directly into committed layers.
- Only the outermost transaction commit mutates committed layers while an enclosing transaction exists.
- Commit conflict detection rejects stale committed-layer base revisions deterministically.
- Silent merge, last-write-wins, heuristic reconciliation, and hidden fallback do not occur for conflicting authoritative mutation.
- Persistence protects committed state against loss but does not define state truth.
- RPC state/update delivery and concrete stateUpdate messages do not by themselves define committed authoritative state mutation.
- Same-language, same-process, adapter-executed, or tooling-originated mutation does not bypass the committed-state boundary.
- Deterministic restoration applies only within the committed-state boundary and does not reconstruct uncommitted runtime activity.

  DISTINCTION: Memory is runtime representation and mutable; state is the authoritative outcome of committed memory.

- TERM_A: runtime memory
  TERM_B: committed state
  DISTINCTION: Runtime memory is not authoritative merely because it is resident, visible, active, or currently in use.

- TERM_A: authoritative material
  TERM_B: non-authoritative material
  DISTINCTION: Authoritative material defines current system truth; non-authoritative material may explain, audit, debug, or diagnose but does not define state truth.

- TERM_A: committed state
  TERM_B: persisted state
  DISTINCTION: Committed state becomes truth by commit boundary; persistence protects against loss but does not define truth.

- TERM_A: trace evidence
  TERM_B: committed state
  DISTINCTION: Trace evidence can explain committed mutation, but trace completeness is not required for committed-state correctness.

- TERM_A: journal-backed recovery
  TERM_B: committed-state restoration
  DISTINCTION: DA-04 does not require journal-backed determinism or recovery; restoration depends on retained authoritative material.

- TERM_A: staged mutation
  TERM_B: committed mutation
  DISTINCTION: Staged mutation inside a transaction is non-authoritative until commit into the relevant authoritative boundary.

- TERM_A: child transaction commit
  TERM_B: committed-layer mutation
  DISTINCTION: A child transaction commit propagates to a parent transaction while an enclosing transaction exists; only the outermost transaction commit mutates committed layers.
