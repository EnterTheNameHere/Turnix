SEMANTIC_ANCHORS
----------------
- Tracing answers what happened, what caused what, and why.
- Tracing is structured evidence with explicit reasons and causal links, not logging.
- Plain logs are secondary and optional; they do not replace trace evidence.
- Retained trace evidence is authoritative for retained causal proof, represented decisions, audit reconstruction, debugger/tooling correlation, and policy-enforcement provenance.
- Trace evidence is not authoritative committed state and does not define rollback eligibility by itself.
- Trace causality is represented through explicit DAG links, not inferred from timestamps.
- Temporal ordering is observational only.
- If an action is absent from retained trace evidence, the action is not provable from trace.
- Absence of failure evidence is not proof of success.
- Trace loss is acceptable only when known loss or incompleteness is explicitly represented.
- Trace consumers rely on controlled structured access surfaces, not direct file scraping.
- User-facing diagnostic views may simplify presentation but must preserve causality and must not fabricate reasons.
- Development-mode trace enrichment is explicit, non-authoritative, and does not change runtime behavior.
- Domain-specific trace obligations belong to the documents that own those domains.

RETRIEVAL_HINTS
---------------
- For questions like "what happened," "what caused this," "why did Turnix do this," or "what proves this decision," route to DA-03 when the answer concerns retained trace evidence.
- For "is trace evidence authoritative state," route to DA-03 and DA-04; DA-03 gives the negative boundary and DA-04 owns committed state.
- For "TraceSpan," "trace span," "span begin," "span end," "span identity," or "no included span end without begin," route to DA-03; add DA-08 for snapshot/export enforcement.
- For "parentEventIds," "causal parent," "trace DAG," timestamp causality confusion, or event causality, route to DA-03.
- For "reason field" or "trace attributes," route to DA-03 for field mechanics, then subject-owning documents for concrete values and required attributes.
- For "TraceEvidenceDeclaredIncomplete," "TraceContinuityBroken," pruning, dropped traces, or incomplete traces, route to DA-03; add DA-08 for export/offline evidence questions.
- For "KernelRunSpanBegin," "KernelRunSpanEnd," "endReasonCategory," "NormalExit," "Crash," "ForcedExit," or "Restart" in kernel-run trace context, route to DA-03.
- For surfaced errors with trace IDs, error envelopes, or trace correlation identifiers, route to DA-03 plus the relevant protocol/schema document.
- For diagnostic UI that displays traces, route to DA-03 for causality/non-fabrication constraints and ODA-B or DA-22 for optional tooling or UI concerns.
- For development-mode "why not chosen," speculative branches, verbose traces, or diagnostic enrichment, route to DA-03 and usually ODA-B.
- For domain-specific trace obligations, route first to the subject-owning document; use DA-03 for substrate mechanics and interpretation boundaries.
