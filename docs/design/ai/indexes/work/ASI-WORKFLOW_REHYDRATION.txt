Turnix Assistant Semantic Index workflow rehydration
====================================================

Purpose
-------
This file preserves the working rules for the Assistant Semantic Index
extraction project.

It is intended to be loaded by supervisor, worker, and test threads that work
on assistant-facing index material for Turnix documentation.

This file is non-authoritative. It does not define Turnix semantics. It does
not override CMR, DD, DA, ODA, IS, or AI_WORKFLOW_BOOTSTRAP documents.

Active branch
-------------
CHATGPT_EXTRACT_INDEX

Project goal
------------
Create assistant-facing retrieval metadata that helps language model assistants
choose which Turnix documents to load for a topic, term, domain, or boundary
question.

The index layer helps with:
- document routing
- semantic family aliases
- domain discovery
- term discovery
- ownership and non-ownership hints
- relation hints
- load-when guidance
- fresh-context testing

The index layer does not replace authoritative documents.

Authority rule
--------------
Assistant index files may guide loading.
Assistant index files may not define Turnix semantics.
For authoritative meaning, load the referenced canonical source document.

Source clarity first
--------------------
The extraction process is also a source-document health check.

If extraction reveals that a canonical document can easily be misunderstood,
record the finding as a source-document improvement candidate.

The supervisor decides whether the issue is:
- source-document clarity problem
- ASI routing problem
- extraction wording problem
- real semantic gap
- deferred until related documents are extracted

If a source document can be clarified without changing intended semantics,
prefer clarifying the source over compensating only in ASI.

Workers do not edit canonical source documents during extraction unless the
assignment explicitly instructs them to do source-document patch work.

Source-document improvement candidates are recorded in:

docs/design/ai/indexes/work/ASI-SOURCE_IMPROVEMENT_CANDIDATES.txt

Supervisor/worker output boundary
---------------------------------
The supervisor thread designs and governs the workflow.

The supervisor thread may directly edit workflow/control files, such as:
- ASI-WORKFLOW_REHYDRATION.txt
- ASI-WORKFLOW_STATUS_LEDGER.txt
- ASI-WORKER_THREAD_PROMPT.txt
- ASI-TEST_THREAD_PROMPT.txt
- ASI-SUPERVISOR_THREAD_PROMPT.txt
- ASI-SOURCE_IMPROVEMENT_CANDIDATES.txt
- ASI-ACCEPTED_EXTRACTION_REVIEW_NOTES.txt
- Batch-*-cross-document-analysis-improvements.txt

The supervisor thread must not directly refine generated extraction records or
final/semi-final ASI index files. If generated output needs refinement, the
supervisor records the requirement in workflow/control files and assigns a
worker thread to regenerate or update the generated output.

Generated files include:
- docs/design/ai/indexes/work/extracts/*.extract.txt
- docs/design/ai/indexes/ASI-*.txt once created as final or semi-final index
  files

Accepted review notes
---------------------
Extraction records are disposable generated artifacts. They may be replaced on
worker rerun.

Accepted review findings that must survive regeneration are stored in:

docs/design/ai/indexes/work/ASI-ACCEPTED_EXTRACTION_REVIEW_NOTES.txt

Workers must load that file before regenerating extraction records or ASI index
files. When accepted requirements apply to an assigned document, batch, or
output file, the worker must preserve them unless the supervisor explicitly
supersedes, rejects, defers, or source-applies them.

The previous extraction record may be used as reference material, but it is not
the source of truth for accepted review requirements.

Canonical identity rule
-----------------------
Phase 1 keeps canonical DOC_ID values unchanged.

Examples:
- DA-03 remains DA-03
- TRACE may be an assistant semantic family alias for DA-03
- IS-01 remains IS-01
- RPC-SCHEMA may be an assistant semantic family alias for IS-01

Aliases are retrieval aids, not replacement DOC_ID values.

Forbidden in Phase 1
--------------------
Do not:
- rename canonical DOC_ID values
- move canonical documents
- split authoritative documents
- rewrite canonical documents as part of extraction
- treat assistant indexes as authority
- copy large normative sections into index files
- infer definitions without a source pointer
- use incomplete connector output as authoritative source text
- obtain update sha values through workaround routes
- edit source documents while performing extraction unless explicitly assigned
- let accepted review findings live only inside generated extraction records
- have supervisor threads directly patch generated extraction/index output
  content for refinement

Thread roles
------------
Supervisor thread:
- designs the extraction workflow
- reviews extracted records
- changes extraction schema when needed
- reviews source-document improvement candidates
- records accepted review requirements
- assigns worker threads for generated output changes
- decides when temporary work becomes final index material
- preserves design intent

Worker thread:
- performs bounded extraction tasks
- loads required workflow files
- fetches assigned source documents
- verifies retrieval completeness
- loads and applies accepted review requirements
- replaces per-document extraction records on rerun
- updates the status ledger
- records source-document improvement candidates when found
- does not redesign workflow unless explicitly assigned
- does not edit canonical source documents unless explicitly assigned

Test thread:
- validates ASI usability from fresh context
- loads only assigned ASI files first
- answers routing questions by using the index
- reports ambiguity, missing terms, wrong routing, or excessive loading
- does not rely on prior supervisor-thread memory

Connector retrieval rule
------------------------
Follow AI_WORKFLOW_BOOTSTRAP for repository connector safety.

For authoritative repository file work, begin with fetch_file for the exact
repository, path, ref, and encoding.

Classify each retrieval before use. Only COMPLETE permits authoritative read
use.

Repository write work requires complete authoritative file content and the
connector update sha from the same COMPLETE fetch_file response for the same
requested source.

Extraction record location
--------------------------
Temporary per-document extraction records live under:

docs/design/ai/indexes/work/extracts/

Suggested file name:

<DOC_ID>.extract.txt

Example:

docs/design/ai/indexes/work/extracts/DA-03.extract.txt

Extraction rerun policy
-----------------------
When a worker reruns extraction for a document, it loads the existing extraction
record if present, but replaces the entire extraction record with a freshly
assembled record.

The worker does not patch small fragments into old extraction records unless the
assignment explicitly asks for a targeted edit.

This prevents stale extraction wording from accumulating underneath newer
workflow rules while accepted review notes preserve approved refinements.

----------------------------------
Assistant-facing index files live under:

docs/design/ai/indexes/

Extraction rules
----------------
Extract routing and indexing metadata only.

Prefer compact hints over copied prose.

Do not copy full "It defines" or "It does NOT define" blocks. Convert them into
short OWNERSHIP_HINTS and NON_OWNERSHIP_HINTS.

Every high-value term should point to a source document and, when practical, a
source section hint.

Use confidence values:
- explicit
- assistant-assigned
- inferred
- needs-review

Use assistant-assigned for semantic family aliases created by this project.

Source improvement candidate rules
----------------------------------
Record a source-document improvement candidate when extraction reveals any of:
- ambiguity
- missing boundary
- term confusion
- cross-document mismatch
- weak retrieval wording in the source
- possible semantic gap

Classify the proposed fix target as one of:
- ASI only
- source document
- both ASI and source document
- needs supervisor decision
- defer until related documents are extracted

If a candidate is recorded in an extraction record, also add it to:

docs/design/ai/indexes/work/ASI-SOURCE_IMPROVEMENT_CANDIDATES.txt

Workers may record candidates but do not approve or apply source-document
changes.

Status ledger rule
------------------
After creating or replacing an extraction record, update:

docs/design/ai/indexes/work/ASI-WORKFLOW_STATUS_LEDGER.txt

The ledger records:
- DOC_ID
- canonical file
- workflow status
- extraction file
- source revision identity
- extraction revision
- review state
- notes

------------------

test them in a fresh test thread.
