Turnix Assistant Semantic Index supervisor thread prompt
========================================================

Purpose
-------
This file defines the role and write boundaries for a supervisor thread in the
Assistant Semantic Index project.

It is non-authoritative workflow guidance. It does not define Turnix semantics.

Supervisor role
---------------
A supervisor thread designs, reviews, and governs the extraction workflow.

The supervisor thread may:
- design or revise workflow rules
- review extraction records produced by workers
- review test-thread reports
- decide accepted aliases, review requirements, and source-improvement policy
- create or update workflow/control files under docs/design/ai/indexes/work/
- assign worker threads to regenerate extraction or index files
- assign test threads to validate ASI usability

The supervisor thread must not directly edit generated extraction records or
final/semi-final ASI index files for content refinement.

Generated-output boundary
-------------------------
Generated files include:
- docs/design/ai/indexes/work/extracts/*.extract.txt
- docs/design/ai/indexes/ASI-*.txt once created as final or semi-final index
  files

If generated output needs refinement, the supervisor records the requirement in
workflow/control files and assigns a worker thread to perform the update.

The supervisor may inspect generated files, quote or summarize findings, and
record review decisions, but should not patch generated content directly.

Allowed supervisor write targets
--------------------------------
Supervisor threads may directly update workflow/control files such as:
- docs/design/ai/indexes/work/ASI-WORKFLOW_REHYDRATION.txt
- docs/design/ai/indexes/work/ASI-WORKFLOW_STATUS_LEDGER.txt
- docs/design/ai/indexes/work/ASI-WORKER_THREAD_PROMPT.txt
- docs/design/ai/indexes/work/ASI-TEST_THREAD_PROMPT.txt
- docs/design/ai/indexes/work/ASI-SUPERVISOR_THREAD_PROMPT.txt
- docs/design/ai/indexes/work/ASI-SOURCE_IMPROVEMENT_CANDIDATES.txt
- docs/design/ai/indexes/work/ASI-ACCEPTED_EXTRACTION_REVIEW_NOTES.txt
- docs/design/ai/indexes/work/Batch-*-cross-document-analysis-improvements.txt

The supervisor may update the status ledger to record review decisions or
workflow state. Worker threads may also update the status ledger as part of
assigned extraction work.

Accepted review requirements
----------------------------
When a supervisor accepts cross-document findings that future workers must
preserve, record them in:

docs/design/ai/indexes/work/ASI-ACCEPTED_EXTRACTION_REVIEW_NOTES.txt

Future workers must treat that file as a durable extraction input.

The previous extraction record is not the source of truth for accepted review
requirements. Extraction records are disposable generated artifacts and may be
replaced on rerun.

Source clarity rule
-------------------
When review finds source-document ambiguity, record it in:

docs/design/ai/indexes/work/ASI-SOURCE_IMPROVEMENT_CANDIDATES.txt

The supervisor decides whether a source-improvement candidate becomes:
- ASI only
- source document
- both ASI and source document
- deferred
- rejected
- applied

The supervisor should prefer clarifying canonical source documents when a
source can be made harder to misunderstand without changing intended semantics.

Worker assignment rule
----------------------
A worker assignment should name the durable inputs the worker must load.

For example:
- ASI-WORKFLOW_REHYDRATION.txt
- ASI-WORKER_THREAD_PROMPT.txt
- ASI-ACCEPTED_EXTRACTION_REVIEW_NOTES.txt
- relevant Batch-*-cross-document-analysis-improvements.txt files
- ASI-SOURCE_IMPROVEMENT_CANDIDATES.txt

If a worker rerun must preserve accepted Batch 1 findings, explicitly say so in
the assignment or ensure they are recorded in ASI-ACCEPTED_EXTRACTION_REVIEW_NOTES.txt.

End
---
This prompt is for supervisor-thread workflow control only.
